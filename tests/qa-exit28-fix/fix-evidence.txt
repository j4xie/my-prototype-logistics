Approach chosen: Option A (SSH-side curl via loopback)
------------------------------------------------------
The MO offered two options:
  A) SSH to 47 and curl 127.0.0.1:10011 — restores actual defensive value.
  B) `|| true` on the local curl — silences the exit but turns the
     "test 10011 异常" warning into permanent noise on every prod deploy
     (since SG-blocked local curl always returns HTTP 000 != 200).

Option A picked because:
  - Symmetric with the existing test→prod cross-check at line 1136, which
    already SSHes to GATEWAY for the cross-environment health probe.
  - 47:loopback is unfiltered by SG (SG rules apply to ingress from
    external IPs, not loopback), so the check actually exercises test
    10011 instead of producing a permanent false warning.
  - Defense-in-depth `|| echo "000"` inside the command sub also handles
    SSH itself failing (key, network, etc), so a transient SSH issue
    won't fail the deploy either.

Patch
-----
  - OTHER_STATUS=$(curl -s -o /dev/null -w "%{http_code}" --max-time 5 \
  -     "http://${SERVER_IP}:10011/api/mobile/health" 2>/dev/null)
  + OTHER_STATUS=$(ssh -o ConnectTimeout=5 $SERVER \
  +     "curl -s -o /dev/null --max-time 5 -w '%{http_code}' \
  +      http://127.0.0.1:10011/api/mobile/health" \
  +     2>/dev/null || echo "000")

Latent same-class risk (NOT fixed in this PR)
---------------------------------------------
Lines 1095 and 1136 use the same `VAR=$(ssh ... curl ...)` pattern
without `|| echo "000"` fallback. If SSH to GATEWAY (139) ever fails
during a deploy, `set -e` will terminate the script with SSH's exit
code (likely 255) — the same root-cause class as exit 28 here.

In practice these have not failed because:
  - GATEWAY (139) is internal control-plane reachable and reliable.
  - The curl runs via nginx upstream from a whitelisted source.

Recommendation: in a follow-up PR, sweep both sites to add
`|| echo "000"` for defense-in-depth and consistency. Out of scope for
this PR (PR title is narrowly "exit 28 cosmetic from Java prod defensive
ping").
