## Findings for Task C (UX optimization audit)

### PROD-1 (P0): SmartBI Analysis enrichment times out on large datasets

200K-row POS uploads cannot be analyzed via the SmartBI Analysis page. The
FE axios timeout is 120s, but the Python `/enrich` endpoint takes longer for
200K rows. Result: customer sees a useless empty state on the most common
upload (POS export).

Customer impact: agg_strategy work is invisible to POS users on this page —
they never see the 营业额/实收金额 cards because enrichment never completes.

Suggested fixes for Task C:
- (a) raise FE timeout to 300s for SmartBI Analysis enrichment specifically
- (b) async/SSE pattern: stream KPIs as they compute, not single-shot POST
- (c) BE optimization: pre-materialize KPIs in agg_cache when upload is ingested
- (d) progress indicator with "约 N 秒" estimate, not generic skeleton

### PROD-2 (P1): Count column "评价门店 = 4,955 亿" — wrong unit applied

The 评价门店 card shows "4,955 亿" — the unit "亿" (100 million) is being
applied to a count that is presumably the number of stores reviewed (4,955 is
plausible for a count, not a monetary 亿-yuan value).

Root cause likely: getSmartKPIs / KPI builder applies "亿" formatting to any
numeric column above some threshold without checking if it's a count vs amount.
After agg_strategy work, count columns with `aggStrategy='count'` (or `'none'`)
should suppress the 亿/万 currency unit.

Customer impact: confusing — "4955 亿 stores" is non-sensical. The customer
either has to mentally strip the 亿 unit or assumes it's a real currency
metric. Erodes trust in other KPIs.

Suggested fix: in `getSmartKPIs` (or KPI value formatter), don't apply
万/亿 formatting when the column's `aggStrategy === 'count'` or when the
title indicates a count (contains 数/门店/订单数 etc. without 额/营业).

### PROD-3 (P2): Missing 平均口味分 card

Spec said 4 平均X cards (服务/星级/环境/口味) but live shows only 3 — 平均口味分
is missing. Either the column wasn't classified as a rating, or the field
wasn't promoted to a KPI.

Customer impact: incomplete picture for product/menu sentiment. 口味 (taste)
is arguably the most important review dimension for a restaurant.

Suggested investigation: check `column_field_definitions` for upload 4172 —
is 口味分 column present? Is it classified with `aggStrategy='mean'`? If yes,
why is it not in the top-N KPI selection?

### PROD-4 (P3): KPI strip shows 4 cards in 1 row (768px wide each)

On a 1920px viewport the 4 cards consume 4x ~480px columns. The 评价门店
count card looks cramped because "4,955 亿" wraps awkwardly when font size
is large. Consider: smarter column sizing, or 5-card layout for review
templates.

### PROD-5 (P3): Upload selector shows 360 options

The dropdown contains 360 historical uploads. While the search works, this
is overwhelming. Consider:
- Default to "Recent 30" with "Show all" expansion
- Group by month/file-name pattern
- Pin the user's most-used uploads to the top
