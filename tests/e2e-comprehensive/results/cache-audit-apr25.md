### Specific corruption-pattern probes

#### Probe 1: English-renamed entity column wrongly typed float64

```sql
WHERE c->>'type' = 'float64' AND c->>'name' IN
  ('platform','product','customer','store_name','employee','channel','product_name', ...)
```

**3 rows hit:**

| upload_id | file_name                          | col | sum    |
|-----------|------------------------------------|-----|--------|
| 4096      | qhj_demo.csv                       | product | 0.0 |
| 3598      | Restaurant-fish-normal-s42.xlsx    | product | 32545.6 |
| 3733      | Restaurant-hotpot-normal-s42.xlsx  | product | 32456.9 |

**Inspection:** Sampled raw `row_data->>'product'` for upload 3598 returned numeric
ratings (3.5, 4.8, 4.8, 6.2, 4.8). The `product` column IS genuinely numeric in
these test fixtures (likely a "rating" field generated by the test data generator
under a misleading column name). NOT corruption from the rename+coerce bug.

**All 3 are test/sample files**, not real customer production data.

#### Probe 2: 账单号 (bill #) wrongly typed float64

```sql
WHERE c->>'name' LIKE '%账单号%' AND c->>'type' = 'float64'
```

**4 rows hit:**

| upload_id | file_name                          | col | agg | note |
|-----------|------------------------------------|-----|-----|------|
| 4170      | gamma1c-smoke.xlsx                 | 账单号 | none | NEW classifier marked correctly: agg=none |
| 4171      | gamma1c-smoke.xlsx                 | 账单号 | none | Same |
| 3598      | Restaurant-fish-normal-s42.xlsx    | 门店名称:青花椒砂锅鱼_账单号 | sum | OLD pivot data |
| 3733      | Restaurant-hotpot-normal-s42.xlsx  | 门店名称:蜀大侠火锅_账单号  | sum | OLD pivot data |

**Inspection:** 4170/4171 (gamma smoke test) correctly tagged `agg: none` by the
new aggStrategy classifier — bills are IDs, not summable. The 3598/3733 rows have
`agg: sum` because the column has the pivot prefix `门店名称:storename_` which the
old classifier didn't unwrap. This is a pre-existing aggStrategy issue with the
pivot test fixtures, NOT the analysis.ts rename+coerce bug.

#### Probe 3: Real customer prod data (qhj uploads 4168/4169)

Inspected all 231 columns of upload 4169 (`qhj_order_detail.csv`, 200K rows, Apr 24
09:23:37 cache).

**All key columns correctly classified:**
- `账单号` → int64, `agg: none` (correct: bills are IDs)
- `外部单号` → float64, `agg: none` (correct: external order IDs)
- `折扣率` → object (correct: discount rates stored as text strings)
- `区域 / 品牌 / 城市 / 收银员 / 服务员 / 桌位` → object (text dimensions)
- `营业额 / 实收额 / 应收金额 / 客流量 / 收款金额` → float64, `agg: sum` (correct: monetary measures)
- 100+ payment-channel columns (微信/支付宝/美团/饿了么/银联) → typed correctly

**Two minor pre-existing issues (not Apr 25 scope):**
- `人均消费` (per-person spending) → float64, `agg: sum` — should be `mean`,
  not `sum`. Pre-existing semantic issue. Doesn't affect template materialization
  (templates use upstream POS columns directly, not this aggregated KPI).
- `商品折前金额 / 商品折后金额` → float64, `agg: none`, no sum — correctly
  flagged as "not summable" but should be `sum`. Minor.

These ARE NOT the analysis.ts rename+coerce bug pattern. They are aggStrategy
classifier semantic quirks affecting `kpiSummary` cards but not Gold templates.
