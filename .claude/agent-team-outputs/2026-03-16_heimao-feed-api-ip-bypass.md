# 黑猫投诉 Feed API IP 封禁绕过方案评估

## Executive Summary

**最优方案：降频分批 + 自愈重试 + Feed/图片分离（方案 C+F），零成本，5-6 小时后台无人值守完成。**

你的 IP 被封的根本原因是请求频率过高（0.5s/页 = 120次/分钟），而非技术对抗不足。新浪的封禁是短期动态封禁（5-60 分钟自动解封），意味着只要控制频率就能完全规避。阿里云服务器 IP 属于机房类型（ASN HOSTING），风控阈值比住宅 IP 更低，需要更保守的参数。

## 推荐实施参数（含 Critic 修正）

```python
PAGE_DELAY_MIN = 10      # 秒（机房IP需要更保守）
PAGE_DELAY_MAX = 18      # 秒
BATCH_SIZE = 15           # 每批页数
BATCH_SLEEP_MIN = 480     # 批间休眠 8 分钟
BATCH_SLEEP_MAX = 720     # 批间休眠 12 分钟
BAN_SLEEP = 600           # 遇到456等10分钟
IMAGE_CONCURRENCY = 15    # sinaimg CDN 并发
```

## 关键防御措施（Critic 补充）

1. 间隔 10-18 秒随机（比原建议 8-13 秒更保守）
2. 批间休眠 8-12 分钟（避免踩在 5 分钟解封边界）
3. 每批使用新的 `requests.Session()`（清空 Cookie 避免指纹追踪）
4. 随机 User-Agent（10-15 个常见浏览器 UA 池）
5. 校验每页返回条目数，异常触发暂停
6. **先跑 50 页验证轮**，确认参数后再全量
7. 基于 ID 去重 + 断点续爬

## 风险提醒

- 阿里云 47 服务器不要直接高频爬取，被封会影响其他服务
- 新浪可能有"降级响应"（返回200但少数据），需校验条目数
- 400 页跨 5-6 小时会有数据翻页偏移，需 ID 去重
