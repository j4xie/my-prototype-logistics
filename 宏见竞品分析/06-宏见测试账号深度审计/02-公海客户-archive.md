# 公海客户 — Archive (Tier 3 子模块, 浅 audit)

## 入口
顶部菜单 → 客户管理 → 公海客户

## 一句话定义
"客户回收池" — 销售员 N 天没跟进的客户自动回到公海, 其他销售员可"领养".

## 主要功能 (推测)
- 公海客户列表 (按时间排序)
- 自动回收规则配置:
  - N 天无跟进 → 自动回收
  - N 天无订单 → 自动回收
  - 主管手动回收
- 销售员"领养"按钮
- 领养限额 (每销售员同时持有 X 客户)
- 客户分级 (大客户优先公海)
- 回收历史 (审计追溯)

## 跟 Cretas 的潜在关联
Cretas 当前 Customer 表没有 owner_id 字段, 业务员客户隔离 (S-RBAC-1) 是 P1 但未 ship.

公海客户是 S-RBAC-1 的**进阶版**:
- S-RBAC-1: Customer 有 owner_id (业务员锁定)
- 公海客户: owner_id = null (公海) + 自动回收规则

## 未来场景假设
- 大销售团队 (50+ 销售员)
- 高竞争行业 (saas/医药/金融)
- 客户资源稀缺 (B2B 大客户)

## 跟 Cretas AI 优势的整合机会
- AI 自动判断"销售员 N 天没动作 + 没邮件 + 没电话" → 自动回收 + 推送钉钉给主管
- AI 评分客户优先级 (历史购买 + 行业 + 规模) → 大客户优先放公海
- AIChat 客户认领: "把今天公海的食品厂客户给我"

## 备注
- F006 卤制品工厂内销售员 < 5, 不需要公海
- Cretas 短期不抄
- 长期 (Sprint 7+) 配套销售部门多客户场景
- 标 P3 / Archive
