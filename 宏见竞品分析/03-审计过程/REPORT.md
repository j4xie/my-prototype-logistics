## 六、⭐ 用 Cretas Agent 简化使用：5 个可落地方案

> 这一节是**核心**。客户原话："你们那个系统的论证在论的太多了，成四个部门" — 这正是传统 ERP 的本质问题：**用户被迫学习单据之间的链路**。Cretas 已有 337 个 Tool + 16 个 Skill + 8 个场景化 AIChatScreen，把客户从"学单据流程"解放到"说人话"上，这是宏见无法跟的差异化。

### 方案 1: 一句话"销售→生产→采购"全链路 (核心)

**用户场景**：销售员收到订单"山姆 800 箱牛肉，3 天后交货"。

**传统 ERP 做法（含宏见）**：
1. 打开销售管理 → 新建销售订单 → 填客户/产品/数量/交期/价格
2. 打开 销售单需求 → 勾选 → 转生产
3. 打开 生产任务 → 看物料需求 → 转请购
4. 打开 采购请购 → 审批
5. 打开 采购订单 → 分供应商转化
*操作员要在 5 个页面间跳，记 5 个流程。*

**Cretas Agent 做法**（一段对话）：
```
用户语音/文字：山姆下单 800 箱牛肉，3 天交货
Agent: 
  → 识别 SHIPMENT 场景 + 解析参数 (customer=山姆, product=牛肉, qty=800, deadline=+3d)
  → 调用 ShipmentCreateTool 创建预销售单
  → 调用 MaterialBatchQueryTool 查库存 → 缺料 320 kg
  → 调用 BomExpansionTool 算应采购物料明细
  → 调用 SupplierRankingTool 推荐供应商
  → 富卡片渲染：
      [✓ 销售单 SO-260514-001 已建 (待审)]
      [⚠ 缺料 320 kg —— 已自动生成请购单 PR-001 (待你审批)]
      [建议生产任务 PT-001：5 月 16 日开工，3 工序 4 工人]
      [一键确认全部 / 修改 / 取消]
```

**实现要点**：
- 新建 `SalesToProductionSkill`（SKILL.md），编排 4 个 Tool
- 富内容渲染：在 `RichContentRenderer` 加 `chain-card` 类型
- 一键确认 = 调 `OrderApprovalTool` 批量审批
- 已有 90% 的零件，只是没编排起来

**ROI**：销售下单从 ~10 分钟 → ~30 秒。**这就是"让 agent 把繁琐 ERP 操作变成对话"的核心范式**。

---

### 方案 2: 摄像头视觉自动报工 (替代扫码)

**用户场景**：客户最大痛点——"7-8 万人一天报工"。

**宏见两种方案都不理想**：扫码（工人累，每人一台手机不现实）/ 统计员（专人电脑录入，加大工作量）。

**Cretas 独家方案**：已有 ISAPI/Dahua 摄像头集成 + `IsapiDetectionEventsQueryTool`。
- 工位摄像头 + 区域识别 (Line crossing + Field detection)
- 工人佩戴工号牌 (二维码胸牌 或 RFID)
- 摄像头识别到"工人 X 进入工位 A 区域 N 秒"→ 调用 `ProcessingWorkerCheckinTool`
- 计件：摄像头识别成品下线动作 → 自动累加产量
- **客户工厂"年龄大、素质偏低"的问题被绕过**——工人完全不动手机

**实现要点**：
- 已有 ISAPI 设备发现/配置 Tool
- 新增 `VisionWorkReportSkill`：编排 region-cross 事件 → 工人识别 → 自动报工
- 数据落 `WorkReport` 实体（已有）
- 异常需要管理员复核时推送到 AIAlertsScreen

**ROI**：把客户的"全场最大不爽"变成"亮点"。

---

### 方案 3: 异常驱动而非主动查询

**宏见**：用户每天打开 ERP → 进各模块 → 看报表 → 找问题。

**Cretas Agent**：主动推送 + 一句话处置。
- 库存预警：每日推送"3 种料即将断料 / 5 种料即将过期，推荐做 X"
- 设备告警：自然语言推送"3 号包装机维护工时到 → 立即排维护 / 推迟 1 天 / 切换 4 号机"
- 质检异常：摄像头识别 → 直接弹质检不合格 + 处置选项

**实现要点**：已有 `AIAlertsScreen` + `AlertTriageTool` + `AlertDiagnoseTool`，只需把"推送 + 三按钮选项"的密度提上来。

**ROI**：用户不需要"学操作"——重要事情找上门。

---

### 方案 4: 多轮对话 Slot-filling 补全表单

**用户场景**：用户说"建生产任务" → 缺 product/quantity/deadline。

**传统 ERP**：要打开完整表单，每个字段提示"必填"。

**Cretas Agent**（已在 AIChatScreen 实现 NEED_CLARIFICATION/NEED_MORE_INFO 路径）：
```
用户：建生产任务
Agent：好的，请告诉我：
  1. 生产什么产品？
  2. 数量多少？
  3. 什么时候交付？
  (或点击下方常用选项)
[盒马牛肉 1万份 5/16] [山姆牛肉 5000份 5/17] [...]
```

**实现要点**：现有 `slotFillingHandler` 在 `IntentExecutorService` 中已就绪，需要扩展到所有"create"类 Tool 的 slot 定义。

**ROI**：表单字段从"必填提示"变成"对话引导"，员工培训成本骤降。

---

### 方案 5: 智能默认值 + 模板命令

**用户场景**：每天的生产汇报 95% 类似——同样的产品、同样的工人、相似的产量。

**宏见**：每次重填。

**Cretas Agent**（已在 AIChatScreen 实现 `smartDefaults`）：
```
[今日生产汇报] 弹模板 → 自动填上次的 product/quantity → 用户只改差异 → 1 键提交
```

**实现要点**：`TemplateCommandSheet` + `smartDefaults.ts` 已经在 AIChatScreen 中实现，需要：
- 扩展模板类型到更多场景（领料、入库、出库、质检）
- 默认值学习从"上次记录"扩展到"该用户该班次该日历最常见"

**ROI**：高频操作 80% 时间节省。

## 七、不要借鉴的 ("此路不通")

- **左侧 12 模块横向菜单**：宏见菜单密度高，全部展开 200+ 子菜单。Cretas 现有的"场景化入口 + AIChat 触发"是更现代的范式，**不要**为了"功能对齐"加一遍菜单。
- **批量数据录入 by 统计员**：把数据录入责任转嫁到管理层，是 ERP 时代的妥协方案。Cretas 用视觉识别 + 对话 + 默认值绕开。
- **可视化打印模板编辑器**：低 ROI。用 PDF 模板 + 字段插值即可。

---

## 八、客户决策路径反推 (战略层)

宏见的销售流程：**线上看演示 → 派"授权"（销售经理）线下样板演示 → 试用账号 → 报价 → 签约**。客户在演示尾段反复表达"想要试用账号" "线下不方便" "需要内部讨论"。

**Cretas 应吸取的销售路径**：
- 让 AIChatScreen 本身成为"无门槛 demo"——用户上来就能"对话式体验"
- "全功能版本 vs 行业精简版本"的分级思路可以借鉴，但**Cretas 用 i18n + 角色 + Feature flag 已能动态裁剪**，技术上更优雅
- 把"装箱称重 / 模具 / 设备" 等用不上的功能在工厂初始化（`AIBusinessInitScreen`）阶段就关掉
