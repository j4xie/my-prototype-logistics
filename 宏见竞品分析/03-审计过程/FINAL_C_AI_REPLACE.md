> **评估时间**: 2026-05-14
> **评估员**: Claude Code (基于 AUDIT_FRESH_C_CODE + REVISED_STRATEGY + 4 次客户会议)
> **评估目标**: 严格评估 Cretas AI 栈 (AIChat 8 场景 / 18 Skill / 404 Tool / SmartBI / TraceFullTool / 摄像头集成 / VoiceMic / 钉钉) 替代传统 ERP UI 的真实边界
>
> **核心原则**: 客户原话 "底层 ERP 必须打好 + AI 做桥梁"。业务流不可压缩。AI 是录入/查询/感知的优化层。

## §1 评估框架说明

### §1.1 五档评估 (严格使用)

| 档位 | 含义 | 占比预期 |
|------|------|---------|
| 🟢 **AI 真替代** | Cretas AI 栈完全可单独完成此功能, UI 仅作 fallback | < 10% |
| 🟡 **AI 主 + UI 辅** | AI 是主入口, UI 是精细操作 / 异常处理 fallback | ~20% |
| 🔵 **UI 主 + AI 辅** | UI 是合规底座, AI 是录入/查询/感知优化层 | ~50% |
| 🔴 **纯 UI** | 合规 / 物理硬件 / 多人协作刚性约束, AI 无法替代 | ~15% |
| ⚪ **AI 价值评估为零** | 与 AI 范式无关 (数据迁移 / 报表配置 / 设计语言等) | < 5% |

### §1.2 严格判定标准 (客户会议锚点)

| 业务特征 | 强制档位 | 客户原话 / 业务约束 |
|---|---|---|
| 涉及审批 (财务双审 / 采购审核) | 🔴 / 🔵 | "财务审批通过这个" — 客户必须人审 |
| 涉及角色隔离 (采购员 vs 仓管员) | 🔵 | "采购跟入库是两个人吗? 两个人两个角色" |
| 涉及状态机 (草稿→审核→部分发货→完成) | 🔵 | 4 状态可视 + 状态守卫 = UI 边界 |
| 涉及多人协作 (销售→财务→采购→仓管→生产) | 🔵 | 7 步业务流不可压缩 |
| 涉及合规审计 (ISO/HACCP) | 🔵 | 单据追溯 = ISO 强制 |
| 涉及物理硬件 (扫码 / 摄像头 / 打卡机) | 🔴 / 🟡 | 物理世界入口必须 UI |
| 涉及单次填表 + 个人操作 + 自然语言可识别 | 🟡 / 🟢 | 真 AI 替代场景 |
| 涉及自然语言查询 (SmartBI NL Query) | 🟢 | Cretas 已真做 |
| 涉及异常推送 (AIInsightCard) | 🟢 | Cretas 已真做 |
| 涉及拍照 OCR (发票 / 单据 / 异物) | 🟡 | Cretas 有摄像头基础 |

### §1.3 客户 UX 哲学硬约束

> 张权 (六扇门) 2026-05-07 Part 2 原话:
>
> - **"做仓管的他年纪都比较大文化素质很低的, 你不能太伪赖他们"** — 仓管员 UI 必须极简 (扫码 + 数量 + 日期 3 字段封顶), 不是 AI 替代
> - **"价格类的不要让仓管员碰"** — 字段级 RBAC, AI 不能跨权
> - **"越写呢越越减少出错"** — 录入字段越少越好, AI 应预填而非问询
> - **"底层 ERP 必须打好 + AI 做桥梁"** — Hybrid 范式, 非 AI 替代

### §3.3 关键洞察

#### 洞察 1: AI 真替代 12.2% — 集中于"查询 + 录入 + 推送"三类

**12 项 🟢 AI 真替代**:
- **NL 查询类 (6 项)**: M2 缺料分析 / W2 多维库存 / W4 制效告警 / F1 AR/AP 账龄 / H1 月度考勤 / N18 分仓库存 — **全部走 SmartBI NL Query 路径**
- **NL 录入类 (2 项)**: H7 工作日报 / N5 钉钉自然语言录入 — **AIChat + Slot Filling 路径**
- **推送类 (2 项)**: N4 三价对比异常 / 部分 W4 制效告警 — **AIInsightCard 路径**
- **视觉识别类 (1 项)**: N7 异物识别 — **海康/大华摄像头 + 本地 VL 模型**
- **入口类 (1 项)**: N1 钉钉机器人 — **AIChat 复用现有 8 场景 + 404 Tool**

**核心结论**: AI 真替代的边界是 "查询 + 录入 + 推送 + 视觉识别", **不是替代审批/状态机/多人协作**.

#### 洞察 2: Hybrid (🔵 + 🟡) 占 46.9% — 这才是 Cretas 真实战场

**46 项 Hybrid**:
- 销售/采购/财务全链路: 业务流不可压缩, AI 是录入加速器 + 查询入口
- 生产/库存/设备深度: AI 算力替代手算, 多角色协作仍 UI
- HR 申请审批 (H4/H5/H6 + N19/N24): AI 一句话申请, 主管审批 UI

**客户原话验证**: "底层 ERP 必须打好 + AI 做桥梁" — Hybrid 范式与客户路线 100% 一致.

#### 洞察 3: 纯 UI (🔴) 18.4% — 全部是合规 + 物理刚性

**18 项 🔴 纯 UI**:
- **物理硬件 6 项**: M3 QR 扫码 / H3 GPS 外勤 / H8 考勤机 / N2 PDF 打印扫码 / W9 仓位 bin / C2 单据打印
- **会计合规 5 项**: F2/F3 凭证 / F4 多币种 / F6 折旧 / F7 汇率
- **数据权限 7 项**: S5/S6 客户隔离 / C4 4 维权限 / C6 IP 限制 / H2 班次配置 / H9 地理围栏 / N15 RBAC 隔离 (其中 H2 是配置, 严格属于半 UI 半 ⚪)

**核心结论**: 合规和物理世界入口是 AI 无法触及的硬边界, 占 18.4%, 比预期 (10-15%) 略高 — 食品行业 ISO/HACCP 强制比通用 ERP 多.

#### 洞察 4: ⚪ AI 无价值 22.4% — 大幅超预期, 全是设计语言 + 配置

**22 项 ⚪**:
- **UI 设计语言 8 项**: U1-U8 完全是 UI 模式, 与 AI 范式正交
- **配置 / Feature Flag 5 项**: Q1/Q2 模板 / C1/C3/C5 通用配置 / C7 设计模式
- **客户具体修补 5 项**: N8 字段隐藏 / N10 单位转换 / N12 列宽 / N13 字段展示 / N14 单点 bug
- **设计组件 4 项**: M5 状态色 / E2 三色灯 / C8 chip 体系 / N10 后台逻辑

**核心警示**: **这 22.4% 也不能不做** — 它们是 UI 体验的底座, 客户 UX 哲学要求 "字段越少越好" 必须靠这些 UI 模式实现. **不是 "AI 替代" vs "做不做" 的问题, 是 "AI 和 UI 各做各的"**.

#### 洞察 5: Cretas AI 栈真实壁垒 (vs 宏见)

Cretas 真正 🟢 真替代 12 项 (12.2%) 全部围绕:
1. **SmartBI NL Query** (Python + 26 Java→Python analysis 端点) — 6 项查询场景
2. **AIChat 8 场景 + 404 Tool + Slot Filling** — 2 项录入 + 1 项入口 (钉钉)
3. **AIInsightCard 推送** — 1 项异常推送
4. **TraceFullTool 食品溯源** (W5 流水追溯虽 🔵 但是 Cretas 独家)
5. **海康 ISAPI / 大华 / 通用 Camera 11 Tool + AutoLabelRecognitionService** — 1 项视觉识别

**这 5 块技术栈是 Cretas 的真壁垒**, 宏见 ERP 完全没有. 但同时也意味着, **AI 故事再强, 也只能撑 12.2% 的功能边界**. 剩下 87.8% 仍需要传统 ERP 业务流 + UI.
