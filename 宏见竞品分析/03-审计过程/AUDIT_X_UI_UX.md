## §2. UI/UX 设计模式（11 个）

### 模式 1 — 密集表格 + 行级 / 列级状态色块
**定义**：表格全行 pink 底色 = "待处理"，单元格内黄色色块 = "缺口需补"，红字 = "过期 / 低于警戒"。
**出现**：销售单需求表 (`000116`, `000121`)、库存查询 (`001353` 满屏红字)、销售退货入库 (`001215` pink 行)。
**意图**：让用户**扫一眼**就知道哪行该动 — 颜色 = 优先级。
**Cretas 评判**：**🟢 应抄**。Cretas 当前列表多为白底，状态用文字 ("待审核 / 已审核")。改成行底色 + 单元格高亮 + 红字异常，扫读速度可 5-10× 提升。
**警告**：颜色不要超 3 种，否则失去信息密度。

### 模式 2 — 右上角浮动头像 + 模块面包屑
**定义**：右上角始终显示当前主讲人头像（武汉、张权-昆山），顶部页面标题统一"③宏见软件演示系统"。
**出现**：所有截图。
**意图**：保持身份（哪个权限）+ 系统品牌（哪个模块）始终可见。
**Cretas 评判**：**🟡 已有但实现差**。Cretas RN App 有头像入口在右上，但 Web 端没有；Web 端的面包屑也缺。

### 模式 3 — 顶部水平 tab 累加（无限累加，可关闭）
**定义**：每次打开一个页面就在顶部累加一个 tab；用户可在多个工作上下文之间切换；最右"x"关闭。
**出现**：`000139` 起 3 个 tabs，到 `001215` 达 16+ tabs。
**意图**：避免"返回-丢失上下文"问题。生产/销售/采购员经常需要交叉查多张单 — 这个浏览器式 tab 是 ERP 必备。
**Cretas 评判**：**🟢 应抄**。Cretas RN 移动端走"返回到上一页"路径，Web 端不留多 tab。
**反例**：超过 10 个 tab 视觉过载 — 必须加 tab 滚动 + max 上限 + 关闭快捷。

### 模式 4 — 行级 hover 浮动多动作菜单
**定义**：表格每行右端鼠标悬停，弹出 8-10 项操作（查看 / 打印 / 状态查询 / 物料展开 / 成品入库 / 委外入库 / 委外加工 / 工序设置 / 生产打印）。
**出现**：生产任务列表 (`000607`, `000622`, `000711`)。
**意图**：避免 1 行 = 10 个按钮的拥挤；操作收敛在 hover drawer 里。
**Cretas 评判**：**🟢 应抄**。Cretas RN 用 Long Press 弹 BottomSheet，Web 端 hover drawer 还没有。

### 模式 5 — 底部固定操作栏（含批量按钮）
**定义**：选中表格行后，底部出现 "选中 N 条" + 5-8 个批量按钮（批量更新 / 生成请购单 / 生成委外单 / 批量取消提交 / 批量提交审核 / 批量审核确认）。
**出现**：物料需求放工序 (`000325`)。
**意图**：从单行 → 批量操作的无缝过渡。
**Cretas 评判**：**🟡 已有但实现差**。Cretas 部分页面有底部 sheet（如 BatchScreen），但批量按钮不全。

### 模式 6 — 内联 QR 弹出
**定义**：表格行内点击 QR 图标 → 浮层显示二维码 → 直接用手机扫。
**出现**：生产任务列表 (`000809`)。
**意图**：让网页端无缝衔接到 APP 端扫码报工。
**Cretas 评判**：**🟢 应抄**（这是 AUDIT.md §E 提到的 "QR 自动生成" 的下一步）。Cretas Label 实体支持 QR，但 UI 没有 inline QR 弹出。

### 模式 7 — flowchart 模块流程图（不可拖拽，只读）
**定义**：销售/采购/审批每个模块都有一张 readonly 的流程图（粉/绿/黄/蓝色块 + 连线），用户**点击节点**跳转对应表单。
**出现**：审批流可视化 (`000443`)、销售流程图 (`001333`)、采购流程图 (`001736`)。
**意图**：给"业务流程白盲"客户看一个总览 — "这是销售的 4 个状态、3 个分支"。
**Cretas 评判**：**🟢 应抄**。AUDIT.md 反对的是"可拖拽工作流编辑器" — 但**只读流程图作为模块首页是绝对值得**：它把"模块=列表"换成"模块=业务地图"。
**注意**：是只读 + 跳转 + 可视化，不是配置工具。

### 模式 8 — 分块表单 + 实时汇总
**定义**：长表单分 3-4 个色块 group (工资 / 应扣 / 五险一金 / 个人所得税)，右侧固定 "工资 40000 / 税前 33020" 实时数字。
**出现**：工资编辑 (`000949`)、生产领料单创建 (`000745`)。
**意图**：让填写者立即看到改一个数对总额的影响 — Cognitive load 降低。
**Cretas 评判**：**🟢 应抄**。Cretas 的 InvoiceCreate / OrderCreate 表单是 1 列 vertical scroll，无实时汇总。

### 模式 9 — 17-tab 客户详情（一站式 CRM）
**定义**：单客户详情页底部 16-17 个 sub-tabs（跟进 / 拜访 / 历史交易 / 通话 / 短信 / 邮件 / 文件 / 销售单 / 采购单 / 产品 / 活动 / 商机 / 商品网站 / 邮件转发 / 拨号 / 邮件列表）。
**出现**：公司客户管理详情 (`001052`)。
**意图**：客户 = "宇宙中心"，所有相关单据/记录都在这一页可点击查看，不用跳模块。
**Cretas 评判**：**🟢 应抄（部分）**。Cretas CustomerDetail 只有"基本资料 + 订单"两个 tab。**重要**：客户对话中销售提到的"工作手机查聊天记录"就藏在 17 tabs 里。
**警告**：客户演示时反而暴露太多 — 反映出"模块太多"的副作用（见 §4）。

### 模式 10 — 卡片式模块入口（彩色九宫格）
**定义**：人力资源主页 = 9 个彩色卡片图标（绿/粉/黄）= 9 个子模块。
**出现**：人力资源 (`000935`)。
**意图**：菜单太长（左侧 20+ 项）时，给一个"导引地图"。
**Cretas 评判**：**🟢 已超越**（Cretas HomeScreen 是卡片式 + 渐变色，已是这个模式）。

### 模式 11 — 库存全维度筛选（仓库 × 批号 × 日期 × 供应商 × 失效）
**定义**：多个下拉互相联动，结果表显示按 5 维度切割后的"批次/仓位/日期"明细库存。
**出现**：仓库管理 (`001309`, `001321`)。
**意图**：食品行业的"FIFO + 批号追溯"刚需。
**Cretas 评判**：**🟡 已有但实现差**。Cretas RawMaterialBatch 支持批号 / 日期，但筛选器 UI 还是单维度下拉。

## §3. 使用逻辑模式（6 个）

### 逻辑 1 — 列表→选中→底部批量操作（销售单二次处理）
**流程**：销售单需求表打开 → 全行 pink → 勾选 3 行 → 底部出现 "[转生产] [转外购] [转委外]" → 一键转换。
**心智成本**：低 — 客户在 `000043` 反复说 "理解，理解，理解" → 这个 paradigm 已被业界共识。
**痛点**：传统 ERP 是"销售单→生成生产单→人工填字段" 5 步，宏见缩到 2 步。
**Cretas 评判**：**🟢 应抄** — AUDIT.md §G 第 1 优先级"销售→生产→采购全链路" 完美匹配此 UX。

### 逻辑 2 — BOM 自动展开 + 缺料分析 + 一键请购
**流程**：下了生产任务 → 自动按 BOM 算物料需求 → 减库存 → 减总供应 → 减安全库存 = 当前缺口 → 选中缺口 → "生成请购单"。
**心智成本**：极低 — 客户在 `000139` 听到这里说 "很智能，这个很智能"。
**痛点**：传统流程"算缺料 → 跟采购说 → 采购填请购"用纸笔耗时半天。
**Cretas 评判**：**🟢 应抄**。AUDIT.md §E 的 BomExpansionTool 必须先修。

### 逻辑 3 — 工作流审批（销售单 / 请购单 / 领料单 触发不同审批人）
**流程**：生产 PMC 填请购单 → 提交 → 系统按规则路由到采购员 → 采购同意 → 自动生成采购订单。
**心智成本**：低 — 客户 `000418` 接受 "不同金额不同审核人" 是已知概念。
**Cretas 评判**：**🟡 已有但实现差**。Cretas Drools 工作流只接入 ProductionPlan 1 个场景。

### 逻辑 4 — 扫码报工 + APP/Web 双端切换
**流程**：生产单 → 自动生成 QR → 打印挂在工位 → 工人手机 APP 扫码 → 报工 / 入库 / 领料。
**心智成本**：客户 `000711` 立即想到 "包他的人员工时" — 这个 UX 触发了客户对 KPI 的联想。
**但客户 `000823` 表达担忧**："我们这边是无神之间的，只有组长操作设备" — **小组长代报会让 KPI 失去个人粒度**。
**Cretas 评判**：**🟢 应抄（含分歧处理）**。Cretas 已有 LabelScan + scan/report，但没有"小组长代报"双模式 — 必须加，否则食品厂客户用不上。

### 逻辑 5 — 客户记忆（同产品不同客户不同价、历史价自动带出）
**流程**：销售员选客户 + 选产品 → 系统从客户价格档案自动填入历史价 → 销售可手动覆盖。
**心智成本**：极低 — 客户 `001025` 听完直接接受。
**Cretas 评判**：**🟡 已有但实现差**。Cretas CustomerPrice 实体存在，但 OrderCreate 时没有自动 lookup + 显示历史价。

### 逻辑 6 — 全局搜索 + 历史搜索（手机号反查客户）
**流程**：输入手机号 → autocomplete 实时匹配 → 选中跳客户详情 → 下方"历史搜索时间线"作快捷复用。
**Cretas 评判**：**🟢 应抄**。Cretas 没有全局搜索（SearchScreen 限单模块），客户 `001137` 看到这个时没有特别反应——但这是销售员的高频操作。

### 关键证据 — 销售脚本的"画面错位"

1. **`001806`**：销售亲口说"**设备 / 模具 / 装箱称重**不一定用" — 但他当时停在采购流程图上，**没有立刻切到客户食品厂真实关注的"冷链批次 / 客户价格 / 销售报表"页面**。这是失败的销售话术 — 应"先 hide 不相关，再 show 相关"。

2. **19:18-22:13 期间画面停滞 `001918` → `002213`**（约 3 分钟在同一个 设备管理 page）：
   - 客户介绍 24h 生产、400-1000 箱/天、人员素质偏低 → 这本应触发销售点击"批次管理 / 多批号库存"页（`001309`），但销售按兵不动
   - 客户问"30-50 用户、销售/采购/仓库/生产" → 本应切到"权限矩阵 + 销售模块" 但仍冻结在设备
   - 客户问"试用账号" → 销售开始谈商务，**画面已经成为背景**

3. **整段没有出现的 KEY 页面**：
   - 冷链 / 食品批号过期管理（虽然系统有：`001321` 不同生产日期区分库存）
   - 客户毛利分析 / 销售排行
   - 商超对账（盒马 / 山姆 = 应收账款大户）
   - 整箱 vs 散件单位换算

### 暗示总结

- **客户被"模块太多"吓退**（`001653` 客户的原话："论资在论的太多了"）—**视频证实 11+ 顶部 tab 累加 + 17 tab 客户详情子页 + 20+ 左侧菜单都是恶化感**。
- **销售缺乏行业切片**：客户说"食品厂"4 分钟后画面还在"注塑机"。
- **flowchart 流程图是销售救命稻草**：每次客户提问被打断，销售退回到 readonly flowchart（`001722`, `001736`）— 但客户已无耐心。
- **没有 demo 录屏剪辑**：销售只能 "全景演示" 23 分钟，客户根本没看 "食品行业冷链批次 + 商超对账" 的 5 分钟 cut。
- **审批/权限演示空白**：客户问 30-50 用户分 4 部门时，权限矩阵页（`001639`）没被打开（演示者跳过了）。
