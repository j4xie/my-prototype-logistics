# 宏见 ERP — UX/UI 设计审计 (Round 9 · 纯 UX 视角)

**素材**: 140 张 HD 关键帧 (1600px), 40min 演示
**视角**: ONLY UI/UX 设计模式 — 不讨论功能/业务/战略
**目标**: 提取独立 UX 模式, 标注哪些值得抄

---

## 0. 整体视觉印象 (30 秒画风总结)

宏见 ERP 是一套**典型 2008-2014 windows-era 工业 web ERP** 的标杆延续 — 顶部蓝色 menu bar + 左侧手风琴菜单 + 中央累积式多 tab 工作区 + 列表为王。
配色 90% 蓝+白+灰, 10% 用粉/绿/橙做语义状态。文字密度极高 (一屏 200+ 数据点不是夸张), 走的是"上 PC、用键盘、超长会话"路线 — 没有手机优化的妥协。

整体风格 = **金蝶 / 用友 / 速达 那一脉** 的视觉血缘 — 工程师设计师做的, 满足"老板看得见所有数据"和"运营员一屏内做完一笔单"两个需求, 不在意美观。

下面 8 节是从这种密度里抽出来的具体模式。

---

## 1. 视觉语言 (Visual Language)

### 1.1 配色语义 — 软粉 + 软绿 + 软蓝的"任务状态三色"系统 ⭐
帧 `001149_s_0179.jpg` / `001551_s_0246.jpg` — 销售单/采购单列表行用整行背景色表示状态:
- **粉色行 (#F8D7DA-ish)** = 待入库 / 异常 / 待审批
- **紫色行 (#E8D5F5-ish)** = 已入库 / 已完成
- **白/浅灰** = 正常进行中

每行顶部还有一条 chip-bar 列出 "颜色标识: 未入库 / 已入库" 给出 legend。
**评判**: ⭐ 值得抄 — 不靠 chip 文字, 而是整行底色就能让运营员"扫一眼知道状态分布"。我们当前 web-admin 用 ant-design 默认 chip, 看一眼分不出来。

### 1.2 字号层级 — 极致密度的 11px / 12px / 14px 三档
帧 `000010_s_0010.jpg` — 一行任务单挤进:
- 任务单号 / 编号 (12px 加粗)
- 产品规格 + 客户 (11px 普通)
- 状态 chip 5 个 (11px)
- 操作下拉 (11px)
- 数量百分比 (12px 加粗)

行高仅 ~55px, 字宽 8-10px, padding 8/12px。
**评判**: 🟡 一般 — 这种密度对运营员效率确实高, 但对新员工/40+ 老板/触屏完全是灾难。我们目标客户餐饮老板大概率不要这种密度, 但 ERP 后台管理可借鉴。

### 1.3 表格边框 — "细灰线 + 浅米黄列分组" 双层视觉分组 ⭐
帧 `000754_s_0161.jpg` 生产领料单 — 表头列分组用 **#F5F1E0 浅米黄底色** 给 BOM 数量 / 申请数 / 补料数 / 余料退 / 废料退 / 实领数 6 列一组, 其他列普通白底。
**评判**: ⭐ 值得抄 — 比合并表头省垂直空间, 同时视觉上立即区分"这些列是 BOM 计算来源 vs 这些列是用户输入"。

### 1.4 单元格嵌套输入 — 输入框直接在表格行内, 无 inline-edit 动画
帧 `000754_s_0161.jpg` / `000849_dense_d_0178.jpg` — 实领数 / 完成比例 等单元格里直接是 `<input>`, 不需要双击编辑, 不需要"点击进入编辑模式"。
**评判**: ⭐ 值得抄 — 老 ERP 的杀手锏。比"点击单元格→弹出编辑器"快 5 倍。我们当前 web-admin 是 ant table 默认行为 (点击进入编辑), 应改成永久 inline input 模式。

### 1.5 蓝色高亮交互态 — selected/active row 用 #E5F0FF 浅蓝高亮 ⚪
帧 `000114_s_0042.jpg` — 第一行选中后整行变浅蓝, checkbox 打勾。
**评判**: ⚪ 中性 — 行业标准, 没新意但稳。

### 1.6 负数红 / 正数黑 ⭐
帧 `001417_s_0213.jpg` 库存查询 — 锁定库存 `-447` 红色, 其余黑色, 不加额外 chip。
**评判**: ⭐ 值得抄 — 财务/库存数字最朴素的状态语义, 一眼抓异常。

### 1.7 图标系统 — 极简描线 outline icon, 大量 emoji-style 业务图标 🟡
帧 `001722_dense_d_0348.jpg` 流程图 — 每个节点是 "蓝色文档 + 黄色折角" 风格的拟物图标 (销售订单 / 请购单 / 核价单 各一张), 不是统一 outline icon。
**评判**: 🟡 一般 — 业务流程图配拟物图标确实直观, 但跟左侧导航的 outline icon 风格冲突, 整体不统一。可保留拟物只用于流程图节点, 其他地方走 outline。

## 2. 信息架构 (Information Architecture)

### 2.1 ⭐⭐⭐ 累积式多 Tab — 一打开就不关 (核心交互范式)
帧 `001025_s_0176.jpg` 显示**同一窗口 18 个工作 Tab**: 工作台 / 流程图 / 生产任务管理 / 销售产品需求表 / 物料需求 / 请购汇总 / 请购单 / 销售订单 / BOM 列表 / 工作流设置 / 采购订单 / 工序流转 / 工资管理 / 计时工资 / 计件工资 / 个人客户管理 — 全在顶部 tab 条, 每个 tab 末尾 `×` 关闭。
- Tab 顺序 = 用户打开顺序, 不重排
- 切 tab 不丢页面状态 (滚动位置/筛选/编辑中表单都保留)
- Tab 太多时右侧 `▼` 下拉显示溢出
- Tab 视觉上靠紧凑的小标签 (~12px 字, 5/3 padding), 一行可放 12-14 个

**评判**: ⭐⭐⭐ 真值得抄 — 这是宏见整个系统**最值钱的交互**。运营员一天打开 20 个表单/列表来回切, 不像 SAP/Oracle 每次 nav 切走丢上下文。我们餐饮老板可能用不上 (单流程为主), 但 ERP 后台/管理员页是绝对该有。**建议: web-admin 加 chrome-tab 模式, 路由级 tab 持久化。**

### 2.2 双层 Tab — 主 tab 条 + 子 tab 条
帧 `001134_dense_d_0233.jpg` 销售退货 — 主 tab `客户查询(按手机)` 下面又有二级 tab `销售出库列表 / 报价单 / 销售退货入库 / 客户退货入库`。
**评判**: 🟡 一般 — 解决了 tab 过多, 但视觉上两条 tab 容易混乱。可以做但 web 端层级控制要严格 (我们 web-admin 现在大量复用 ant tabs 是 OK 的)。

### 2.3 顶部 12 模块 + 左侧二级菜单 — 经典 "T 字形" 切换 ⚪
帧 `000051_s_0039.jpg` 顶部 12 蓝色大模块: 客户管理 / 销售管理 / 采购管理 / 仓库管理 / 财务管理 / 生产管理 / 委外管理 / 工程管理 / 品质管理 / 人力资源 / 办公自动化 / 系统管理。点哪个, 左侧菜单整个换掉 (折叠的二级菜单)。
**评判**: ⚪ 中性 — 行业标准, 没什么可抄, 但稳。

### 2.4 左侧菜单 — 自折叠手风琴 ⚪
帧 `000208_s_0059.jpg` — 二级菜单是手风琴, 一次只展开一组 (生产管理 / 工序流转 / 称重管理 / 装箱管理 ...), 二级菜单图标是 outline 小图标。
**评判**: ⚪ 中性 — 行业标准。

### 2.5 树形分类 — 列表左侧 inline 分类树 ⭐
帧 `000114_s_0042.jpg` 产品列表 — 列表区域**左侧塞一个产品分类树** (成品 / IV 类产品 / I 类产品 / II 类产品 / III 类产品 / 半成品 / 物料), 点节点过滤右侧列表。**树和列表是同一屏并排**, 不是抽屉, 不是 modal。
**评判**: ⭐ 值得抄 — 比 "点击筛选→弹分类树→选择→关闭" 快 3 倍。我们 web-admin 的物料/产品页应加这种 inline 分类树, 现在是用顶部 selector 切换很慢。

### 2.6 无面包屑 — 用 tab 标签做位置指示 ⚪
帧 — 全程没看到面包屑。位置感全靠"当前激活的 tab + 左侧菜单 highlight"。
**评判**: ⚪ 中性 — 累积 tab 模式下面包屑确实多余。如果我们抄 tab 模式, 面包屑也可以省。

## 3. 列表设计 (List Patterns)

### 3.1 一行 = 一个"卡片" — 行高 70-110px, 行内 8+ 数据点 ⭐
帧 `000010_s_0010.jpg` 生产任务列表 — 每行不是传统 ant-table 的 "一行一列一值", 而是行内分 6 区:
1. checkbox + 日期 + 单号 + 类型标签
2. 产品代号 + 规格 + 缩略图 (32x32)
3. 优先级 + 交期 + 计划/实际 双行
4. 数量×单价=金额 + 文件(N) 链接 + 图片(N) 链接
5. 客户名 + 备注
6. 状态 5-chip 垂直堆叠 (订单类型 / 订单审核 / 生产状态 / 车间 / 物料状态 / 已领 / 负责人) + 操作下拉

一行能同时表达"我做不做 / 谁负责 / 进度多少 / 物料齐不齐"。
**评判**: ⭐ 值得抄 — 比 ant-table "一行一列一值" 信息密度高 5 倍, 老板手机扫一眼能定位异常。**建议: 我们 web-admin 销售订单/采购订单列表行可以重新设计成 multi-zone 行, 借鉴这种 layout。**

### 3.2 多层 chip 状态 — 顶部 4 chip + 行内 7 chip ⭐
同帧 — 每行的右侧"状态区"有 5-7 个 mini chip 垂直堆叠:
- 订单类型: 已审核 (绿)
- 生产状态: 准备中 (黄)
- 车间: 默认车间 (灰)
- 物料状态: 已领 (绿) / 0% (红进度条)
- 负责人: 工二 (灰带头像)

每个 chip 是独立"维度", 5 个并排表示同一行的多面状态。
**评判**: ⭐ 值得抄 — 我们当前 SO/PO/MO 列表只显示一个总状态 chip ("已审批"/"待审批"), 信息不够。可以分维度展示。

### 3.3 行末操作下拉 — 12-14 选项的隐藏菜单 ⭐⭐
帧 `000036_s_0025.jpg` / `000607_dense_d_0124.jpg` — 每行末尾 "操作 ▾" 下拉, 点开是 13 个选项:
```
查看 | 任务修改
物料(3) | 物料需求
工序流转 | 成品完工
成品入库 | 明细
成品入库(不良) | 明细
成品返工 | 调拨延边仓 | 明细
生产领料 | 明细
生产补料 | 明细
余料退回 | 废料退回 | 其他物料 | 其他物料 | 边角料入库
```
**评判**: ⭐⭐ 值得抄 — 不用占行内空间(否则每行要 14 个按钮), 又能在一行级别上做完所有衍生动作。我们 web-admin "操作" 列只有 编辑/删除/详情 3 项, 严重浪费。
**建议**: SO/PO 行末加"操作"下拉, 把"转生产 / 转外购 / 转委外 / 退货 / 撤销 / 复制" 等次要动作收到下拉里, 主流程只留 ⊙审核/⊙详情。

### 3.4 进度条 inline — 0% 红 / 100% 绿色填充 ⭐
帧 `000010_s_0010.jpg` — "已完成: 0 良品率: 0.00% 已入库: 0 未入库: 200" 后面跟一个 80px 宽的进度条 inline, 0% 是空灰条, 红色边框。
**评判**: ⭐ 值得抄 — 数字 + 进度条同时呈现, 老板扫一眼知道这单"卡在哪里"。

### 3.5 列头排序 — 列名右侧 ↕ 双箭头, 点击切换 ⚪
帧 `001849_dense_d_0378.jpg` 设备列表 — 列头"设备图片 ↕ 设备编号 ↕ 设备名称 ↕ ..." 全部带排序箭头。
**评判**: ⚪ 中性 — 行业标准。但有意思的是**每一列都默认可排序**, 不需要 column config。

### 3.6 多选 checkbox + 底部批量操作浮动栏 ⭐
帧 `000114_s_0042.jpg` 产品列表 — 选中第一行 (checkbox ✓), 底部出现固定栏: `已选 1 条 [转请购▾] [转采购▾] [转生产▾] [转委外申请▾] [转预备▾] [转出库] [可用库存] (?)`。
**评判**: ⭐ 值得抄 — 比"右键菜单"或"顶部 toolbar 始终显示"清晰。我们 web-admin 大量列表的批量操作隐藏在右上角, 不直观。

### 3.7 空状态 — 灰底 "暂无数据" / "暂无图片" 占位 ⚪
帧 `001417_s_0213.jpg` 库存查询 — 没有缩略图的行显示 32x32 灰底框, 写 "暂无图片"。
**评判**: ⚪ 中性 — 标准。

### 3.8 分页 — 经典 "首页/末页/页码输入 + 每页 50 条" ⚪
帧 `001551_s_0246.jpg` 底部: `共 3 条 上一页 [1] 下一页 到第 [1] 页 [确定] 总金额: ¥6,525.00 总数量: 122`。
- 总金额 + 总数量直接渲染在分页栏旁边 — 这一招实用
**评判**: ⭐ 总金额/数量与分页同栏, 值得抄。

### 3.9 行边框 — 浅灰 1px 横线 + 行间无垂直线 ⚪
所有列表 — 横向分隔靠 1px 灰线, 列之间无垂直线 (ag-grid 风格)。
**评判**: ⚪ 中性 — 标准。

### 3.10 行内附件 chip — "文件(0) | 图片(0)" 内联标签 ⭐
帧 `000010_s_0010.jpg` — 每行有 "📎 文件(0) | 🖼 图片(0)" 蓝色文字链接, 数字括起来表示数量, 点击进入附件管理。
**评判**: ⭐ 值得抄 — 比单独开附件 tab 直观。SO/PO 都该加。

## 4. 表单设计 (Form Patterns)

### 4.1 分组式 collapsible section ⭐
帧 `001029_s_0177.jpg` 客户详情:
```
▼ 订单属性
  开票税率 | 发票类型 | 支付方式
  默认币种 | 对账日期 | 常用快递公司
  订单总个数 | 订单总金额 | 回款总次数

▼ 客户属性
  客户来源 | 属性 | 分类
  重要程度 | 客户类型

▼ 系统信息
  负责人 | 负责人部门 | 跟单人员
  ...

▼ 自定义信息
  联系人.qweqweq | 联系人手机 | 联系人地址
  开户银行 | 公司英文名称
```
每组用 `▼` 折叠/展开, 组名加粗。
**评判**: ⭐ 值得抄 — 比"长长一屏 50 个字段"清爽 3 倍。当前 web-admin 客户详情就是平铺, 应分组。

### 4.2 字段密度 — 一行 3 字段, 字段名靠左 ⭐
同帧 — `客户来源 [--不选择-- ▾]  属性 [--不选择-- ▾]  分类 [--不选择-- ▾]` 一行 3 列, 字段名 60px label + 输入区。每行 ~12 字段名, 4 输入区。
**评判**: ⭐ 值得抄 — 比 ant 默认的 "vertical: 一行一字段" 节省 70% 空间, 老板一屏看完。

### 4.3 sticky 底部操作栏 ⭐
帧 `000754_s_0161.jpg` 生产领料单 — 顶部按钮区固定: `[提交] [保存草稿] [返回列表] [审批历史] 生产领料 当前节点: 生产领料单创建`。底部表格右下角永远显示 `合计 89`。
帧 `001029_s_0177.jpg` 客户表单 — 中间固定一行: `[返回] [保存] [保存并关闭] [更多 ▾] [已成交]`。
**评判**: ⭐ 值得抄 — 长表单滚动时按钮永远可见。我们 web-admin 长表单经常底部按钮要滚到底才看见, 体验差。

### 4.4 必填星号 / placeholder / help text 🟡
帧 — 必填字段没有红星标记 (老 ERP 通病), placeholder 直接是 `--请选择--`, help text 几乎没有。
**评判**: 🔴 太老旧 — 不要抄。我们应坚持红星 + 清晰 placeholder + tooltip help。

### 4.5 字段联动 — "选 A → B 自动带出"
帧 `000023:33` 字幕提到: 销售订单的产品勾选后, 转请购单时自动带产品/数量/客户。视觉上没有动画反馈, 数据直接出现。
**评判**: 🟡 一般 — 联动有, 但反馈不够。我们做应加 toast "已自动填入 X 字段"。

### 4.6 下拉选择 — 普通 select + 搜索 select + 级联 select 三种共存 ⚪
帧 `001106_dense_d_0223.jpg` 客户查询 — 手机号输入框点击后弹出 `历史搜索记录` 下拉, 显示之前搜过的 6 个号码。
**评判**: ⭐ "历史搜索记录" 自动联想 — 值得抄。

### 4.7 日期范围 — 起始日期 + 终止日期两个独立 input, 中间一个 `到` ⚪
帧 `001551_s_0246.jpg` 采购收货单 — `收货时间 [2026-02-13] 到 [2026-05-31]`。
**评判**: ⚪ 中性 — 比 ant DatePicker.RangePicker 笨拙但兼容性好。

### 4.8 数字输入 — 纯文本框, 无 +/− 步进
帧 `000754_s_0161.jpg` 申请数量 — 直接输入框 `89`, 没有 ant InputNumber 的步进按钮。
**评判**: 🟡 一般 — 对批量录入员有效, 对老板/触屏不友好。

### 4.9 文件上传 — 行内文件 (N) 链接打开附件 modal ⚪
帧 — 没看到拖拽上传, 全是点击"文件(0)" → 弹窗 → 点击上传。
**评判**: 🟡 一般 — 模式陈旧, 不要抄。

### 4.10 ⭐ "自动计算 / 重新初始化" 显式按钮
帧 `000942_dense_d_0195.jpg` 工资管理 — 表单底部 4 个按钮:
```
[自动计算] [重新初始化] [保存] [保存并关闭]
```
不是"输入数字 → 自动更新计算值", 而是**显式让用户点"自动计算"按钮**才触发个税 / 实发工资刷新。
**评判**: ⭐ 值得抄 — 财务/工资场景, 用户怕"自动算" 把刚改的数字覆盖。显式按钮 = 用户掌控感。

### 4.11 ⭐ 表单顶部"当前节点: 生产领料单创建"流程指示
帧 `000741_s_0153.jpg` — 审批表单的顶部除了按钮, 还有一行 **生产领料 当前节点: 生产领料单创建** + `意见 [-请选择-▾] 同意 ⚙`。
**评判**: ⭐ 值得抄 — 工作流场景, 告诉审批人"你现在在第几步、要不要批准"。比独立的 progress 步骤条更紧凑。

## 5. 弹窗 / 对话框 (Modal Patterns)

### 5.1 QR 码弹窗 — modal 中心, 仅二维码 + 标题 ⭐
帧 `000553_s_0144.jpg` 任务列表 — 点击某图标弹出小 modal: `App 扫码查看订单 [×]` + 200x200 QR 码。
**评判**: ⭐ 值得抄 — 移动端协同的典型, 我们 web-admin 也该有"扫码在手机查看"的入口。

### 5.2 错误 modal — 居中, 红色 X icon + 错误原因 + 红字字段 ⭐
帧 `001106_dense_d_0223.jpg`:
```
⊗  出现错误
错误原因: 开通工作手机相关业务,如需开通请咨询相关业务人员!
[返回]
```
- 红色 X icon (28px)
- 错误原因是红字 + 加粗
- 单按钮 "返回" — 不让用户继续操作
**评判**: ⭐ 值得抄 — 比 ant Modal.error 的图标 + 文字组合更克制, 红字字段醒目。

### 5.3 加载状态 — 中心粉色 loader "数据加载中请稍候..." 🟡
帧 `000139_s_0057.jpg` 销售单需求 tab — 整个内容区中心显示一个粉色加载圈 + `数据加载中请稍候...` (粉色字)。
**评判**: 🟡 粉色字配粉 loader 颜色太花哨, 改成 grey 即可。不抄。

### 5.4 操作下拉 — popover 而非 modal ⭐
帧 `000036_s_0025.jpg` — 行末"操作"下拉是从图标位置展开的 popover (类似 ant Dropdown), 而不是 modal。覆盖在内容上, 点外部关闭。**没有遮罩**。
**评判**: ⭐ 值得抄 — 比 modal 轻量, 适合短动作菜单。

### 5.5 modal 关闭 — 仅右上角 `×`, 无 ESC 提示 ⚪
帧 — 没看到 ESC 关闭提示, 没有"点击外部关闭"的视觉暗示。
**评判**: ⚪ 中性 — 不需要抄。

## 6. 状态反馈 (Feedback Patterns)

### 6.1 列表内联状态 chip + 整行底色 双重表达 ⭐
见 1.1 与 3.2 — 同一状态信息用 chip + 整行底色 + 进度条三种方式表达, 视觉冗余但容错率高。
**评判**: ⭐ 值得抄 — 即使用户色盲, chip 文字仍可读。

### 6.2 文件 / 图片附件计数 ⭐
帧 `000010_s_0010.jpg` — `📎 文件(0)` 和 `🖼 图片(0)` 数字 0 灰色, 有附件时变蓝且 underline。
**评判**: ⭐ 值得抄 — 一眼知道哪一行有附件。

### 6.3 业务状态 chip 配色
帧 — 状态 chip 配色:
- **绿色** (#5FB371-ish) = 已审核 / 正常 / 已完成
- **黄色** (#F5B461) = 准备中 / 进行中 / 待处理
- **红色** = 拒绝 / 异常 / 0%
- **灰色** = 默认 / 未指派 / 空值

**评判**: ⭐ 标准 + 一致 — 值得抄, 我们 web-admin 各模块状态色不统一是大问题。

### 6.4 提示 / 警告 — 灰色 inline 文字, 没有 banner ⚪
帧 `000915_dense_d_0186.jpg` 工序流转下方:
```
注: 系统设置了工序流转数量必比计划数量多了 10%。流入数量 = 上一道工序流出的数量。
    库存数量 = 所有工序状态的库存之和。待流出数量 = 合格数量 - 工序完成状态的库存数量 - 已流出数量。
如果开启序列号产品 设置绑定 (蓝标识) 的工序后不可其他操作仅供查看数据!
```
- 蓝色文字 "注:" + 黑色正文
- 没有图标, 没有 banner 框
**评判**: 🟡 一般 — 比 alert banner 占空间小, 但 attention 不够。可以学习风格 (灰底窄行 + "注:" 前缀), 但加个 info icon。

### 6.5 空数据 — 整个工作区空白 + 列名占位 ⚪
帧 `001003_s_0171.jpg` 计时工资 tab — 数据为空时:
```
日期 | 工作人数 | 总金额 | 查看
汇总:                    0
[计时工资 _______]
```
表头存在, 表体一片灰色拖底色 + 折叠的 "—" 图标占位。
**评判**: 🟡 一般 — 太冷清。比 ant Empty 组件丑。

## 7. 操作动线 (Action Flow)

### 7.1 "创建"入口 — 顶部右上角 "新增" 按钮 (绿色) ⚪
帧 `000010_s_0010.jpg` — 列表上方 `生产任务列表 ▾ [+ 新增] [+ 批量新增]`。
- 新增 = 绿色按钮 + `+` icon
- 批量新增 = 同色 + icon
**评判**: ⚪ 中性 — 行业标准。但 **同时提供"单个新增"和"批量新增"** 这个细节, 值得抄。

### 7.2 "返回" — 表单顶部 `[返回列表]` 按钮 + 浏览器后退共存 ⭐
帧 `000741_s_0153.jpg` — 编辑页顶部按钮区有显式 `[返回列表]` 按钮, 不依赖浏览器后退。
**评判**: ⭐ 值得抄 — 累积 tab 模式下"浏览器后退"会跳出整个 ERP, 用户不敢点。显式 "返回列表" 按钮必备。

### 7.3 批量操作 — 顶部 + 底部双触发点 ⭐
帧 `000114_s_0042.jpg` — 选中行后:
- 底部固定栏: `已选 1 条 [转请购▾] [转采购▾] [转生产▾] ...`
- 顶部不变 (依然是 `[+新增]`)

帧 `001551_s_0246.jpg` 采购收货单底部:
```
[批量操作 ▾]    [税前总金额: 176.057522 总金额: 191 总数量: 23]
```

**评判**: ⭐ 值得抄 — 浮动选择条比右键菜单/顶部 toolbar 都更突出。

### 7.4 关键确认 — modal 二次确认 (审批 / 删除) ⚪
帧 — 没特别展示二次确认弹窗, 但帧 `000741_s_0153.jpg` 审批是 `[意见 [-请选择-▾] 同意]` 主动让用户先填意见。
**评判**: ⚪ 中性 — 审批要求填意见是合理的, 不让"无脑通过"。

### 7.5 工作流可视化 — 流程图 + 节点指示 ⭐⭐
帧 `001722_dense_d_0348.jpg` 采购管理 流程图:
```
       销售订单 ──┐
                  ├──→ 采购底稿 ──┐
       请购单 ───┘                ├──→ 采购订单 ──→ 采购变更单
                  询价单 ─────────┘
                                              ↓
                                          质检单
                                              ↓
        采购退货 ←── 采购入库 ──→ 报表
```
- 节点是带图标的卡片 (粉/绿/蓝代表流程阶段)
- 箭头连接 (淡绿色 stroke)
- 可点击节点 → 直接跳到对应模块
- **每个模块都有自己的流程图** (采购 / 品质 / 销售 / 生产 ...)
**评判**: ⭐⭐ 值得抄 — 新员工 onboarding 必备。我们 web-admin 完全没有这种"模块业务流程图"。**建议**: 在每个模块的工作台顶部, 加一个可缩略/展开的流程图导航。

### 7.6 多步骤指引 — "当前节点: XXX" 内联文本 ⭐
见 4.11 — 不用 ant Steps 组件那样的横向步骤条, 而是一行内联文字 "生产领料 当前节点: 生产领料单创建"。
**评判**: ⭐ 值得抄 — 比 step bar 省垂直空间。当节点 < 4 个时, 文字描述 + 当前 highlight 即可。

### 7.7 撤销 / 重做 — 无 ⚪
帧 — 没看到 undo/redo, 主要是表单保存草稿模式。
**评判**: ⚪ 中性 — ERP 一般不需要 undo, 靠"保存草稿"和审批回退即可。

## 8. 微交互 (Micro-interactions)

### 8.1 Hover tooltip — 字段名后的 ⓘ icon ⭐
帧 `000942_dense_d_0195.jpg` 工资管理 — `请假 0.00  迟到 0.00 ⓘ  借款 0.00 ⓘ`, 每个字段后跟一个 ⓘ 小图标, hover 显示说明。
**评判**: ⭐ 值得抄 — 比 placeholder 长说明清爽。复杂业务字段 (税率 / 五险一金计算公式 / BOM 用量公式) 都该有。

### 8.2 行内 hover — 整行轻微浅蓝 ⚪
帧 — 鼠标 hover 一行, 行底色变浅蓝 (#F2F8FF-ish)。
**评判**: ⚪ 中性 — 标准。

### 8.3 拖拽 — 几乎不可见, 没看到拖拽列宽 / 拖拽排序 🔴
帧 — 没看到任何拖拽支持。列宽固定, 行不能拖排序, 看板模式没有。
**评判**: 🔴 太老旧 — 不要抄。我们 web-admin 应有列宽拖拽、列显示配置、可拖拽看板列。

### 8.4 双击 — 行双击进详情 ⚪
帧 — 双击行的反馈不可见, 但根据业务习惯应该是双击行 → 进详情 tab。
**评判**: ⚪ 中性 — 标准, 但应给视觉提示 (hover 时显示 "双击查看")。

### 8.5 右键菜单 — 无, 全靠"操作 ▾" 下拉 ⚪
帧 — 没看到任何右键菜单。
**评判**: ⚪ 中性 — Web 系统不强求, 行末"操作"下拉够用。

### 8.6 键盘快捷键 — 不可见 🔴
帧 — 没有 ⌘/Ctrl 提示, 没有 hot key 浮层。
**评判**: 🔴 太老旧 — ERP 老员工是键盘党, 应有 Ctrl+S 保存 / Ctrl+N 新建 / Tab 跳字段等。我们 web-admin 至少做 Ctrl+S 即可。

### 8.7 复制 / 粘贴 / 搜索 — 顶部 Ctrl+F 浏览器原生 ⚪
帧 — 没有应用级搜索框, 全靠浏览器 Ctrl+F。
**评判**: 🔴 缺失 — 应有全局搜索 (⌘K) 跳模块/记录。

### 8.8 顶部 sticky — 列表表头不 sticky? 🔴
帧 `001417_s_0213.jpg` 库存查询 — 滚动到 30+ 行下方时, 列头消失了 (推断, 因为帧上没看到 sticky 行)。
**评判**: 🔴 太老旧 — 必须 sticky header, 不抄这种。我们 web-admin 用 ant Table.sticky 就行。

### 8.9 顶部 12 模块切换 — 切换无动画, 即时跳转 ⚪
帧 — 顶部 menu hover 没有下拉预览, 点击直接换左侧菜单 + 主区域。
**评判**: ⚪ 中性 — 适合熟练用户, 不适合新员工。

### 8.10 通知 / 红点 — 隐约可见
帧 `001722_dense_d_0348.jpg` 顶部右侧 — 用户头像 + admin(系统管理员), 没看到通知红点 / 待办数。
**评判**: 🟡 一般 — 应有顶部待办通知红点 + 下拉显示。

### 8.11 audio 视频 meeting 录制 ⚪
帧 `002327_s_0296.jpg` 是 VooV Meeting 自身的录制通知列表 — 不是宏见 ERP 内容。
**评判**: ⚪ 不相关。

## 9. 总结表 — 30+ UX 模式优先级清单

按 ⭐⭐ / ⭐ / 🟡 / 🔴 / ⚪ 分级:

### ⭐⭐⭐ 真值得抄 (Top 3)
1. **累积式多 Tab + 持久状态** (§2.1) — chrome-tab 风格, 1 个 window 可开 20+ tab 不丢上下文
2. **行末操作下拉 14 选项** (§3.3) — 把次要 action 收起来, 列表行内不挤
3. **业务流程图导航** (§7.5) — 每个模块都有可点击节点的流程图, onboarding 神器

### ⭐⭐ 强烈推荐抄 (Top 10)
4. **整行底色 + chip + 进度条** 三重状态表达 (§1.1, §3.4, §6.1)
5. **行内分类树** (§2.5) — 列表左侧并排树, 不用抽屉
6. **多区域大行布局** (§3.1) — 一行 6 区, 信息密度 ×5
7. **多维 mini chip 状态** (§3.2) — 一行 5-7 个 chip 表达多维度状态
8. **sticky 底部按钮栏 + 实时合计** (§3.6, §4.3) — 长表单/长列表的金牌模式
9. **inline 编辑单元格** (§1.4) — 表格里直接是 `<input>`, 不用进编辑模式
10. **同行附件 chip "文件(N) 图片(N)"** (§3.10) — 比单独 tab 直观
11. **米黄底色列分组** (§1.3) — 用列底色暗示列类型, 比合并表头省垂直空间
12. **表单分组折叠** (§4.1) — 长表单分 4-5 组, 大幅减少认知负担
13. **每行 3 字段紧凑布局** (§4.2) — 比 ant vertical 节省 70% 空间

### ⭐ 值得参考 (Top 15)
14. 负数红色 (§1.6)
15. 显式"自动计算"按钮 (§4.10)
16. "当前节点: XXX" 流程文字 (§4.11, §7.6)
17. QR 码扫码 modal (§5.1)
18. 红色 X 错误 modal (§5.2)
19. popover 操作下拉无遮罩 (§5.4)
20. 浮动批量操作底栏 (§7.3)
21. 显式 "返回列表" 按钮 (§7.2)
22. 字段后 ⓘ tooltip (§8.1)
23. 历史搜索记录联想 (§4.6)
24. 单个新增 + 批量新增 双按钮 (§7.1)
25. 总金额/数量与分页同栏 (§3.8)
26. 状态颜色统一 (绿正常 / 黄进行 / 红异常 / 灰默认) (§6.3)
27. 双层 tab 子 tab (§2.2)
28. 列默认全部可排序 (§3.5)

### 🟡 一般 / 部分参考
- 极致密度 11/12px 字号 (§1.2) — ERP 后台 OK, 客户端慎用
- 拟物图标流程图 + outline 导航不统一 (§1.7)
- inline 灰色提示文字 (§6.4) — 风格可学但加 info icon
- 强联动反馈缺失 (§4.5) — 应加 toast

### 🔴 太老旧 / 别抄
- 必填星号缺失 (§4.4)
- 拖拽几乎无 (§8.3)
- 键盘快捷键缺失 (§8.6)
- 应用级搜索 ⌘K 缺失 (§8.7)
- 列表表头不 sticky (§8.8)

### ⚪ 中性 / 行业标准
- T 字形导航 / 手风琴菜单 / hover 浅蓝 row / 错误关闭 modal 等

## 10. 与 Cretas 当前 web-admin 的差距 — 抄哪三件最划算?

按 "迁移成本 vs 用户体验提升" ROI 排序:

| 优先级 | 模式 | 迁移成本 | 体验提升 | ROI |
|---|---|---|---|---|
| P0 | **累积式多 tab + 路由级 tab 持久化** | 高 (需重做 router) | 极高 (老板/运营每天 50 次切页) | ⭐⭐⭐ |
| P0 | **行末"操作 ▾"下拉 + 多区域行布局** | 中 (改 ant Table render) | 高 (单页信息密度 ×3) | ⭐⭐⭐ |
| P1 | **sticky 底部按钮 + 实时合计** | 低 (CSS sticky) | 高 (长表单/长列表用户痛点) | ⭐⭐⭐ |
| P1 | **整行底色 + 多 chip 状态** | 低 (Tailwind class) | 中 (列表扫一眼定位异常) | ⭐⭐ |
| P1 | **表单分组折叠** | 低 (component wrap) | 中 (新员工易上手) | ⭐⭐ |
| P2 | **业务流程图导航** | 高 (画图 + 路由 wire) | 高 (onboarding 一键搞定) | ⭐⭐ |
| P2 | **行内分类树 + 列表并排** | 中 (layout 改造) | 中 (物料/产品筛选) | ⭐⭐ |
| P3 | **inline 编辑单元格** | 高 (table 重写) | 中 (运营员效率) | ⭐ |
| P3 | **QR 扫码 modal / 字段 ⓘ tooltip** | 极低 | 低 | ⭐ |
