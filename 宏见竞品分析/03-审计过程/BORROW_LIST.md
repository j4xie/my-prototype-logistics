> 整合 4 路审计后的最终借鉴清单。每项含**功能描述 + 战略意义 + 工时 + Phase 归属 + 实施要点**。
>
> 标记：
> - 🟢 必抄（客户决策关键 + 食品行业刚需）
> - 🟡 应抄（提升完整度 + 客户日常 80% 使用）
> - 🔵 选抄（看客户群和业务形态）
> - ⚪ Cretas 后端已有，只需 UI 暴露（最高 ROI！）
> - ❌ 反对抄（详见末尾 §11）

## 一、销售 / CRM (10 项)

### S1 🟢 销售单需求 → 三向分流 ⭐
- **功能**：销售单勾选 SKU → 底部 "批量提交生产 / 批量提交采购 / 批量提交外购" 一键转化
- **战略意义**：客户**唯一主动赞叹**的功能（"很智能"，音频 1:04）；MRP 链路的脊柱
- **工时**：7 人天（含 4 stub 修复 + 跨域 Skill 编排）
- **Phase**：1
- **实施要点**：
  - 修 BomExpansionTool productName stub (0.5d)
  - 创建 SalesToProductionPurchaseSkill (1d)
  - RichContentRenderer 加 chain-card type (0.5d)
  - 整合 4 处缺料分析到 ShortageAnalysisService (2d)
  - E2E 测试 (2d)

### S2 ⚪ 报价单 → 销售单转化链路
- **功能**：销售先发报价单，客户接受后一键转销售单
- **战略意义**：销售流程的起点，没这个"对话式销售"故事不完整
- **工时**：4.5 人天（**仅前端**，因为后端已有 OperationalQuote）
- **Phase**：1
- **实施要点**：
  - QuoteListScreen 列表页 (1d)
  - QuoteCreateScreen 创建表单 (2d)
  - 报价单 → 销售订单转化按钮 (0.5d)
  - AIChat：QuoteCreateTool (1d)

### S3 🟢 同产品 × 多客户价目记忆
- **功能**：客户 A 历史价 100，客户 B 价 95，下次建单自动带历史价
- **战略意义**：食品行业谈判常态；销售员每天都用
- **工时**：3 人天
- **Phase**：1
- **实施要点**：新建 `customer_product_price_history` 表 + 建单时查询并建议 + AIChat 集成

### S4 ⚪ 客户跟踪记录 + 文件附件
- **功能**：拜访 / 电话 / 邮件 / 合同 / 价格表 附件管理
- **战略意义**：销售员日常 30% 时间花在跟进
- **工时**：3 人天（**仅前端**，因为后端 CustomerTrackingRecord 完整）
- **Phase**：2
- **实施要点**：CustomerDetail 加跟踪 Tab + 创建表单 + AIChat 集成

### S5 🟡 业务员客户隔离权限
- **功能**：业务员只能看自己负责的客户
- **战略意义**：避免业务员撞客户、防止数据泄露给离职员工
- **工时**：3 人天（基于现有 RBAC 扩展）
- **Phase**：2

### S6 🔵 客户撞重 + 申请争取审批
- **功能**：撞了别人的客户可以申请认领
- **战略意义**：大销售团队才需要
- **工时**：3 人天
- **Phase**：3

### S7 🟡 业绩管理 + 提成自动计算
- **功能**：销售业绩看板 + 月度提成规则配置 + 自动计算
- **战略意义**：销售员每天看自己数据；月底自动算提成省 HR 工作
- **工时**：5 人天
- **Phase**：2

### S8 🟡 月结对账单（多订单汇总）
- **功能**：销售可选"单单结"或"月底汇总" 2 种模式
- **战略意义**：大客户都用汇总结算
- **工时**：5 人天
- **Phase**：3

### S9 🟢 销售订单 4 阶状态 + 6 按钮批量
- **功能**：状态 tab (草稿/审核/部分发货/完成) + 行末 6 按钮 (转生产/转采购/转外购/复制/取消/打印)
- **战略意义**：销售员高频操作的入口，影响日常使用感
- **工时**：5 人天
- **Phase**：1
- **实施要点**：依赖 S1（chain skill）

### S10 🔵 租赁 / 寄卖 / 借出 / 样品 / 微信网店
- **功能**：5 种销售形态扩展
- **战略意义**：看客户业务形态（食品厂通常不需要租赁/寄卖）
- **工时**：每种 5 天，合计 25 天
- **Phase**：3（选）

## 二、采购 (5 项)

### P1 🟢 采购订单二次处理（按供应商拆单）
- **功能**：请购单审批后，同一物料分配给不同供应商，自动拆成 N 张 PO
- **战略意义**：MRP 链路关键节点；客户**唯一主动赞叹**机制的下游延伸
- **工时**：5 人天
- **Phase**：2
- **实施要点**：请购单通过 → 按物料-供应商映射拆分 → 用户审核后批量发出

### P2 🟡 采购全链路 6 阶段单据

- **工时**：8 人天（补缺失环节）
- **Phase**：2

### P3 🔵 采购协同 + 询价管理
- **功能**：多供应商比价单
- **战略意义**：大采购量客户才需要
- **工时**：5 人天
- **Phase**：3

### P4 🟡 采购退货 / 退换货 + 对账
- **功能**：收货后质量问题处理
- **战略意义**：食品行业退换货常见
- **工时**：5 人天
- **Phase**：2

### P5 🟡 按订单结算 vs 多订单汇总对账
- **功能**：财务两种结算模式
- **战略意义**：与 S8 配对
- **工时**：3 人天
- **Phase**：3

## 三、生产 (9 项)

### M1 🟢 物料需求按工序展开 ⭐
- **功能**：销售单/生产任务 → 按 BOM 工序级拆分原料/辅料/包材清单
- **战略意义**：食品 SKU 40-80 种原料，工序拆分是核心
- **工时**：3 人天（依赖 P0-T1 BomExpansion stub 修复）
- **Phase**：1

### M2 🟢 缺料分析统一视图 ⭐
- **功能**：当前需求 − 总供应 + 库存预警 = 缺口 → 一键转请购/采购
- **战略意义**：客户唯一赞叹的机制；MRP 中心页面
- **工时**：包含在 S1 7 天里
- **Phase**：1

### M3 🟢 生产任务专属 QR 码 ⭐
- **功能**：每张生产任务带 QR，工人扫码即报工/领料/入库
- **战略意义**：解决"老员工不会复杂操作"——客户痛点
- **工时**：3 人天（Label 实体已有 QR 字段，需 ProcessingBatch 生成 + 路由）
- **Phase**：1

### M4 🟢 领料单按 BOM 自动展开 + 多列进度 ⭐
- **功能**：计划数/申请/已领/未领/退料/实领 多列展示
- **战略意义**：食品厂 40-80 种料的领料效率
- **工时**：5 人天（含工序级筛选 + 套数批量调整）
- **Phase**：2

### M5 🟢 生产任务列表 4 列状态色编码
- **功能**：生产状态/物料状态/订单审批/已交，行级色块
- **战略意义**：管理层扫描友好
- **工时**：5 人天（依赖 C8 多层 chip 体系建立后）
- **Phase**：1（与 S9 一起做）

### M6 🟢 批量电脑报工（统计员模式） ⭐
- **功能**：多选员工 + 输入产量 + 一键提交
- **战略意义**：**客户原话要求**——"7-8 万人扫码不现实，可以电脑批量录"
- **工时**：5 人天
- **Phase**：1

### M7 🟡 小组长代报工
- **功能**：组长一次扫码代填全组 5-10 人
- **战略意义**：宏见 + 客户对话中提到的中间方案
- **工时**：3 人天
- **Phase**：2

### M8 🟡 报工 → 计件工资联动
- **功能**：报工自动累加到员工工资单
- **战略意义**：食品厂普遍用计件工资
- **工时**：5 人天
- **Phase**：2

### M9 🔵 工程 BOM 版本管理
- **功能**：配方变更审批 + 历史回滚
- **战略意义**：精细化食品厂需要
- **工时**：5 人天
- **Phase**：3
