# 34. 数据完整性 + 业务规则

**来源**: R3 Agent 5 审计

## 34.1 10 大数据完整性缺失 (P0-P4)

### 34.1.1 字段级规则 (P1)
| 字段 | 规则 | 测试 |
|------|------|------|
| 批次号 | BATCH-YYYYMMDD-XXXX 格式 | 建 `invalid123` 应拒 |
| SKU | 同工厂唯一 | 跨工厂 SKU 重复应区分 |
| 税号 | 18 位 | `short123` 应拒 |
| 手机号 | 员工/客户唯一 | 建两员工同手机应拒 |
| 邮箱 | 格式校验 | `not-email` 应拒 |

### 34.1.2 业务规则 (P0) ⭐⭐

| 规则 | 测试 | 严重度 |
|------|------|--------|
| SO 必须关联客户 | customerId=null 应拒 | P0 |
| 采购单 ≥1 行明细 | 空明细审批应拒 | P1 |
| **发货累计 ≤ SO** | 发 SO 要 100, 第一次 70 + 第二次 40 = 110 应拒 | P0 ⭐ |
| **收款累计 ≤ SO** | SO 100, 收 80 + 40 = 120 应提示超收 | P0 ⭐ |
| 发票累计 ≤ SO (扣作废) | 作废后可重开 | P0 |
| 完工 = 良品 + 次品 | 完工 100 + 良品 60 + 次品 50 应拒 (超) | P1 |
| 批次数量 ≥ 0 | 发货超库存提示 | P0 |
| hireDate < contractEndDate | 顺序颠倒应拒 | P2 |
| 组织无循环父子 | F1.parent=F2 && F2.parent=F1 应拒 | P2 |

### 34.1.3 级联删除策略 (P1)
- 删客户: 有 SO → 软删 + "[已删除]" 标记; 无引用 → 物理删
- 删供应商: 有采购 → 阻止; 无 → 物理删
- 删部门: 有员工 → 阻止
- 删产品: 有 SO/库存 → 阻止

### 34.1.4 冗余字段 (P2, 历史数据显示)
- SO 应存 `customerName` 冗余 (客户改名后 SO 显示当时名称)
- PO 应存 `supplierName`
- SO items 应存 `unit` (产品单位改后历史显示原值)
- 测试: 客户改名后, 历史 SO 仍显示原名称

### 34.1.5 精度 (P2)
| 场景 | 测试 |
|------|------|
| 金额 2 位小数 | 33.33 × 3 = 99.99, 总应 100.00 (round) |
| 数量 4 位小数 | 100.0001 kg 可存储 |
| 税率单位 | 13 (百分比) vs 0.13 (小数) 约定明确 |
| 10 亿金额 | `999999999.99` 不截断 |

### 34.1.6 时区 (P3)
- TIMESTAMP WITH TIME ZONE 使用
- 跨时区查询一致
- UTC 存储, 本地显示

### 34.1.7 事务原子性 (P0) ⭐
| 流程 | 若中途失败, 应整体回滚 |
|------|---------------------|
| 发货 | 批次扣减 + 送货单 + SO 状态 (全回滚) |
| 开票 | 发票记录 + SO 开票状态 |
| 收款 | AR 冲销 + 客户余额 |

### 34.1.8 重复数据检测 (P1)
- Excel 导入: 重复行提示 "第 5-7 行重复, 已跳过"
- SO 同客户同日期: 提示合并 or 独立

### 34.1.9 外键一致性 (P1)
- SO.customerId 必须存在于 customers
- 软删 customer 后 SO 仍能显示 "[已删除]"

### 34.1.10 币种汇率 (P4, 国际化)
- purchase_orders 无 currency 字段 (gap)
- 跨币种订单统计方式未定义
