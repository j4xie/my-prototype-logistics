# 03. 段 1 — 研发样品 → BOM 自动生成 → 报价推送

**会议来源**: `研发样品至财务回款全流程文档.md` §1.1-1.4
**涉及角色**: sales (需求) / admin (研发+审核) / sales 或 finance (报价)
**业务价值**: 从客户 raw 需求到可下 SO 的报价起点
**耗时**: 15-20 min

---

## 3.1 流程总览图

```
销售发起研发需求 (sales)
    ↓ [request_id]
研发新建样品档案 (admin/rd)
    ↓ [sample_id, status=DRAFT]
研发填写追踪记录 (多次)
    ↓
研发提交审核
    ↓ [status=SUBMITTED]
审核人审核样品
    ├─ 通过 → status=APPROVED, 自动创建报价任务 ⭐
    └─ 驳回 → status=REJECTED, 退回研发
    ↓
销售提交报价申请 ⚠️ (后端 endpoint 缺失, 跳过)
    ↓
报价人员执行报价
    ↓ [quotation_id, status=CONFIRMED]
输出: 可关联到销售订单的样品+BOM+报价
```

---

## 3.2 3.2 发起研发需求

### 前置
- **账号**: `sales / 123456`
- **页面**: `/rd/samples`

### 步骤
1. 登录 `sales` 账号
2. 侧边栏 "**研发管理**" (or 地址栏 `/rd/samples`)
3. 顶部 tab 切 "**研发需求**"
4. 点右上角 "**新建研发需求**" 按钮

### 字段 (全部在一个对话框)
| 字段 | 组件 | 必填 | 示例值 |
|------|------|------|-------|
| 客户名称 | el-input | ✅ | `永辉超市` |
| 联系方式 | el-input | ⚪ | `13800138000` |
| 紧急程度 | el-select (HIGH/MEDIUM/LOW) | ⚪ | `普通 MEDIUM` |
| 需求描述 | el-input textarea (4行) | ✅ | `开发新口味辣椒酱, 目标成本 200 元/kg, 要求色泽红亮, 辣度中等` |

### 操作
1. 填 **客户名称** `永辉超市`
2. 填 **需求描述** (多行, 尽量详细)
3. 选 **紧急程度** (可选)
4. 点 "**提交**" 按钮

### ✅ PASS
- Toast: "**研发需求已创建**"
- 列表刷新, 出现新需求行
- 状态列显示 `SUBMITTED` (待分配)
- **Network**: `POST /api/mobile/F001/rd/requests` 返回 200

### ❌ FAIL
| 现象 | 可能原因 |
|------|---------|
| 客户名称为空点确定能过 | 前端未校验必填 (bug) |
| 502/503 | 后端 RdController 未部署 |
| 403 | sales 角色无 `rd:create_request` 权限 (数据库配) |

### 记下
- **研发需求 ID** (从列表或响应 json 拿), 后续步骤可能用到

## 3.3 研发新建样品

### 前置
- **账号**: `admin / 123456` (当前系统没 rd 角色, 用 admin 代替)
- **页面**: `/rd/samples` → Tab "**样品管理**"

### 步骤
1. (如果是 sales 账号接着做, 先退登登 admin)
2. Tab 切 "**样品管理**"
3. 点 "**新建样品**" 按钮

### 字段
| 字段 | 组件 | 必填 | 示例值 |
|------|------|------|-------|
| 样品名称 | el-input | ✅ | `黑胡椒牛肉酱-V1` |
| 客户名称 | el-input | ⚪ | `永辉超市` |
| 业务员 | el-select (可搜索/自建) | ⚪ | `sales` |
| 成品规格 | el-input | ⚪ | `200g/盒, 310g×42 袋/箱` |
| 产品级别 | el-select (A/B/C/D) | ⚪ | `A` |
| 储存方式 | el-select (冷冻/冷藏/常温) | ⚪ | `冷藏` |
| 关联需求 | el-input (需求 ID) | ⚪ | `{3.2 的 request_id}` |

### 操作
1. 填 **样品名称** (必填)
2. 其他字段尽量填全 (为后续 BOM 生成提供数据)
3. 点 "**创建**" 按钮

### ✅ PASS
- Toast "**样品已创建**"
- 自动切回样品管理列表
- 新样品行状态 `DRAFT` (待研发)

### ❌ FAIL
- 样品名称为空能提交 → 必填校验 bug
- 创建后列表不刷新 → 前端 loadData() 未调用

### 记下
- **样品 ID** (后续追踪/审核都要用)

## 3.4 添加追踪记录 (可重复 2-3 次, 模拟研发进度)

### 前置
- **账号**: `admin` (研发人员)
- **前置状态**: 样品存在, 状态 `DRAFT` / `IN_PROGRESS` / `TESTING`

### 步骤
1. 样品列表找到 3.3 创建的样品行
2. 点操作列 "**追踪记录**" 按钮
3. 弹对话框

### 字段
| 字段 | 组件 | 必填 | 示例值 |
|------|------|------|-------|
| 日期 | el-date-picker (**禁用**) | - | 自动今日 |
| 追踪内容 | el-input textarea (3行) | ✅ | `完成 V1 配方调试, 外观红亮, 口味达标, 辣度适中` |
| 附件 | el-input (URL) | ⚪ | 可留空, 或填图片 URL |
| 记录员 | el-input (**禁用**) | - | 自动当前用户 |

### 操作
1. 输入追踪内容
2. 点 "**添加记录**"

### ✅ PASS
- Toast "**追踪记录已添加**"
- 详情页追踪记录列表多一行

### 🔁 重复 2-3 次
模拟多日研发进展, 追踪内容示例:
- Day 1: `完成 V1 配方调试`
- Day 2: `V2 调整辣度, 增加花椒 5%`
- Day 3: `试生产 5kg, 口感稳定, 准备送审`

## 3.5 研发提交审核

### 前置
- **账号**: `admin`
- **前置状态**: 样品状态 `DRAFT` / `IN_PROGRESS` / `TESTING`

### 步骤
1. 样品列表找到目标样品
2. 点操作列 "**提交审核**" 按钮 (蓝色)
3. 弹确认框 "确定提交审核?"
4. 点 "**确定**"

### ✅ PASS
- Toast "**提交审核成功**"
- 状态变 `SUBMITTED` (待审核)
- 列表操作列按钮变化 (通过/驳回 显示)

### ❌ FAIL
- 点按钮无反应
- 状态未变

---

## 3.6 审核人审核样品 ⭐ (核心环节)

### 前置
- **账号**: `admin` (审核人, 实际生产环境应是独立审核角色)
- **前置状态**: 样品状态 `SUBMITTED`

### 路径 A: 审核通过

#### 步骤
1. 样品列表找状态 "**待审核**" 的样品
2. 点操作列 "**通过**" 按钮 (**绿色**)
3. 弹输入框: "**审核意见 (可选)**"
4. 输入 `配方合格, 同意量产` (或留空)
5. 点 "**确定**"

#### ✅ PASS ⭐
- Toast: "**审核通过成功, 报价任务已自动创建**"
- 样品状态变 `APPROVED` (**样品通过**)
- **关键验证**: Tab 切 "**报价任务**", 应看到**自动创建**的报价任务 (状态 `PENDING`)

#### Network 验证
- `POST /api/mobile/F001/rd/samples/{sampleId}/approve` 返回 200
- Response: `{"code":200,"success":true,"message":"样品审核通过，报价任务已自动创建"}`

#### ⚠️ 已知限制
- **BOM 自动生成不在 UI 显示**. 会议说 "自动生成 BOM 清单 (包含原料/规格/用量)", 但前端无直观体现. 只有后端 event 处理. 这是**产品缺陷**, 不算 bug, 客户问起告知 V2 roadmap.

### 路径 B: 审核驳回

#### 步骤
1. 点 "**驳回**" 按钮 (**红色**)
2. 弹输入框: "**请输入驳回原因**" (**必填**)
3. 输 `辣度不够, 需调整配方`
4. 点 "**确定**"

#### ✅ PASS
- Toast "**驳回成功**"
- 状态变 `REJECTED`
- 研发人员可在列表看到驳回原因

## 3.7 ⚠️ 销售提交报价申请 (后端缺失, 跳过)

### 会议需求
销售看到 "样品通过" 后, 点 "**提交报价申请**" 触发报价流程.

### 实际情况
- **前端按钮存在** (样品 APPROVED 状态的 "提交报价申请" 按钮)
- **后端 endpoint 缺失**: `POST /rd/samples/{id}/request-quotation` **未实现**
- 点击会报 404 错误

### 当前处理
- **跳过此步**, 报价任务在 3.6 审核通过时**已自动创建** (后端自动), 可直接到 3.8 报价人员执行.
- **V2 需补**: 后端实现此 endpoint, 让销售可以补充报价优先级/期望交期等信息.

## 3.8 报价人员执行报价

### 前置
- **账号**: `sales` 或 `finance` (根据组织分工)
- **URL**: `/rd/samples` → Tab "**报价任务**"

### 步骤
1. Tab 切 "**报价任务**"
2. 找 status=`PENDING` 的任务 (3.6 自动创建的)

### 字段显示
| 字段 | 来源 | 说明 |
|------|------|------|
| 任务编号 | 自动生成 | - |
| 样品名称 | 关联样品 | `黑胡椒牛肉酱-V1` |
| **总成本** | 后端计算 BOM 成本 | 应有数字 (否则 BOM 未生成) |
| **建议售价** | 自动推荐 (margin rate) | - |
| **最终报价** | 人工调整 | - |
| 毛利率 | 计算 | % |
| 状态 | PENDING/IN_PROGRESS/QUOTED/CONFIRMED | - |

### 操作 (简化版)
1. 点任务行 "**开始报价**"
2. 状态变 `IN_PROGRESS`
3. 调整 "**最终报价**" 字段
4. 点 "**确认报价**"
5. 状态变 `CONFIRMED`

### ✅ PASS
- **总成本有值** (证明 BOM 生成了, 能算成本)
- 最终报价可编辑
- 确认后状态 `CONFIRMED`

### ❌ FAIL
- 总成本为 0 或 null → BOM 自动生成失败 (后端 bug)
- 无法编辑最终报价
- **Network**: `GET /api/mobile/F001/rd/quotations?status=PENDING` 200

## 3.9 跨模块数据流 (段 1 → 段 2)

完成段 1 后, 下游段 2 (销售订单) 能做什么?

- 新建 SO 时, "**产品**" 下拉可选择 `APPROVED` 状态的样品 (关联 sampleId)
- SO 提交财务审核时, 后端拉取样品 BOM 计算预估成本
- 关联报价后, SO 单价可自动填充 (取报价 `最终报价`)

### 验证
跳到 [04-sales-order.md](04-sales-order.md) §4.2 新建 SO 时, 产品下拉里应能看到刚审核通过的样品.
