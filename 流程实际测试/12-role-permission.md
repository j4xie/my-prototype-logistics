# 12. 16 角色权限验证矩阵

**目的**: 确认每个角色能看/能操作的范围符合 RBAC 设计
**耗时**: 30 min (每角色 ~2 min)
**用途**: 安全验收 / 防越权验证

---

## 12.1 权限设计原则

- **factory_super_admin (admin)**: 全权限 (`*:*`)
- **部门经理** (finance_manager / sales_manager 等): 本部门读写 + 跨部门读
- **操作员** (operator / inspector): 仅执行功能, 不改核心数据
- **viewer**: 只读全局, 不能任何 写操作
- **跨工厂**: 所有非 super_admin 账号**不能访问其他工厂数据**

---

## 12.2 通用验证方法 (每角色适用)

### 通用步骤 (每角色跑一遍)
1. 退登 admin → 登该角色 (密码 `123456`)
2. Ctrl+Shift+R 强刷
3. **侧边栏检查**: 看到哪些菜单, 没看到哪些
4. 对每个菜单点进去, 检查:
   - 列表能否加载
   - "**新建 / 编辑 / 删除**" 按钮是否可见
   - 点无权操作是否友好提示
5. 尝试 URL 直接访问不在菜单里的页面 (看是否 403)
6. F12 Network 看有无 403 接口调用

## 12.3 角色 1: admin (factory_super_admin) ⭐

### 预期
- 全部菜单可见
- 所有按钮可见可点
- 所有接口 200

### 验证
- ☐ 侧边栏: 10+ 模块 (首页/销售/采购/生产/仓储/质量/财务/研发/数据分析/系统管理)
- ☐ 全局按 "新建" 按钮都可见
- ☐ 任何 URL 直接访问不 403
- ☐ 能看其他角色看不到的: 用户管理 / 角色管理 / Canvas 编辑器

## 12.4 角色 2: sales_manager (sales)

### 预期
- **可**: 销售订单 (CRUD) / 客户管理 / 发货单 / 开票申请 / 研发需求发起
- **不可**: 财务审核 SO / 采购 / 生产计划 / 系统管理
- **只读**: 数据分析 / 产品信息

### 验证
- ☐ 看得到: 销售管理菜单
- ☐ 看不到: 采购管理 / 系统管理
- ☐ 新建 SO 成功
- ☐ 进财务审核页 (`/finance/invoices`) → 看到按钮但点审核应 403 或按钮隐藏
- ☐ 进采购单 → 403 或隐藏

## 12.19 跨工厂越权验证 (安全关键) ⭐⭐⭐

### 场景
所有 F001 账号**不能**访问 F002 / F003 / FOOD_3101_048 等其他工厂数据.

### 验证方法
1. 登录任意 F001 账号 (如 sales)
2. 浏览器地址栏**手动改 URL**:
   - `/api/mobile/F001/customers` → 改为 `/api/mobile/F002/customers` (直接 API 调)
   - 或 URL 参数 factoryId 改

### ✅ PASS (安全!)
- 返回 **403** "无权访问该工厂数据"
- 或登出重定向

### ❌ FAIL (严重安全漏洞)
- 能看到其他工厂数据 → 立即上报, **P0 bug**
- 返回 200 + 其他工厂数据

### 已修复的相关 bug
- [02-regression-17bugs.md #4](02-regression-17bugs.md) URL 双前缀会让 factoryId 解析为 `api`, 触发跨工厂检查
- [02-regression-17bugs.md #7](02-regression-17bugs.md) JwtAuth 排除列表需要含 `workflow`
