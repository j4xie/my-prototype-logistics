# 09. ⭐⭐⭐ 杀手锏 G1 — 税率分组开票

**客户原话** (Apr 7 5049s): "**9% 的 2500, 13% 的 800, 分开开两张票**"
**实现**: `TaxGroupInvoiceDialog.vue` (372 行独立组件)
**入口**: 2 处 (SO 列表行按钮 + SO 详情 Tab)
**这是客户最强调的需求, 演示必跑**
**耗时**: 10 min

---

## 9.1 为什么重要?

餐饮/食品行业常见场景:
- 一张销售订单含**不同税率的商品**:
  - 原料 (农产品): 9% 税率
  - 加工服务: 13% 税率
  - 某些冷链物流: 6% 税率
  - 免税类: 0%
- 开票需按税率**分开开具多张发票** (符合税务要求)
- 手工拆分易错, 系统自动分组是核心痛点解决方案

---

## 9.2 前置准备 (制造测试数据)

### 关键: SO 的产品明细要**多税率**

### 步骤
1. `sales` 账号创建 SO (参考 [04-sales-order.md](04-sales-order.md) §4.2)
2. 添加**多行产品明细**, 每行不同税率:

| 行 | 产品 | 数量 | 单价 | 税率 (tax_rate) | 小计 (不含税) |
|---|------|------|------|---------------|--------------|
| 1 | 原料A (农产品) | 50 kg | 30 | **9%** | ¥1500 |
| 2 | 原料B (农产品) | 40 kg | 25 | **9%** | ¥1000 |
| 3 | 加工服务 | 1 | 500 | **13%** | ¥500 |
| 4 | 成品包装 | 1 | 300 | **13%** | ¥300 |

**总计**:
- 9% 组: ¥1500 + ¥1000 = **¥2500** → 税额 ¥225 → 含税 ¥2725
- 13% 组: ¥500 + ¥300 = **¥800** → 税额 ¥104 → 含税 ¥904
- **SO 总不含税 ¥3300**, 含税 ¥3629

### ⚠️ 如何设置不同税率?
检查产品明细表单是否有 **税率** 字段:
- 如果产品 select 联动的单位/税率, 选不同产品自动
- 如果明细行有 `taxRate` 字段直接填
- 如果 SO 没这个功能 → 只能单税率, 演示时**模拟**这个场景给客户看

### 完成 SO 审核通过 + 发货
确保 SO 状态 `SHIPPED` (段 2-5 全部走完)

## 9.5 TaxGroupInvoiceDialog 操作流程 ⭐

### 对话框初始状态
弹出后显示**订单信息**:
- 订单号: `SO-xxxx`
- 客户: `永辉超市`
- 订单总金额: `¥3629` (含税)
- 不含税金额: `¥3300`
- (还没点"一键分组"前, 下方是空的)

### 核心操作
点对话框里的 "**一键按税率分组开票**" 按钮

### 后端处理
系统自动:
1. 读 SO items[]
2. 按 `taxRate` 聚合分组
3. 每组计算:
   - `taxableAmount` (不含税合计)
   - `taxAmount` (税额 = taxable × rate)
   - `invoiceAmount` (含税 = taxable + tax)
   - `lineCount` (行数)
4. 返回 `taxBreakdown[]`:

```json
{
  "invoiceNumber": "INV-20260416-001",
  "taxBreakdown": [
    {
      "taxRate": 9,
      "taxRateLabel": "9% · 原料",
      "taxableAmount": 2500,
      "taxAmount": 225,
      "invoiceAmount": 2725,
      "lineCount": 2
    },
    {
      "taxRate": 13,
      "taxRateLabel": "13% · 加工费",
      "taxableAmount": 800,
      "taxAmount": 104,
      "invoiceAmount": 904,
      "lineCount": 2
    }
  ]
}
```

### 对话框展示结果 ⭐⭐⭐
**多张卡片**, 每张对应一个税率组:

**卡片 1** (9% 原料):
```
┌─────────────────────────────┐
│  🟢 9% · 原料                │
│                              │
│  不含税金额    ¥2,500.00     │  ← 大字
│  税额          ¥225.00       │
│  ────────────────────────    │
│  发票金额      ¥2,725.00     │  ← 红粗体
│                              │
│  明细行数: 2                  │
└─────────────────────────────┘
```

**卡片 2** (13% 加工费):
```
┌─────────────────────────────┐
│  🔵 13% · 加工费             │
│                              │
│  不含税金额    ¥800.00       │
│  税额          ¥104.00       │
│  ────────────────────────    │
│  发票金额      ¥904.00       │  ← 红粗体
│                              │
│  明细行数: 2                  │
└─────────────────────────────┘
```

### 底部操作
| 字段 | 说明 |
|------|------|
| 发票类型 (选择) | 普通发票 / 增值税专票 |
| 客户信息 (自动填) | 开票抬头 + 税号 |
| 备注 (可填) | 额外说明 |
| **提交按钮** | "**确认生成分组发票**" |

点提交

### ✅ PASS ⭐⭐⭐ (核心验证!)
1. **卡片渲染正确**:
   - 至少 2 张卡片 (如示例 2 种税率)
   - 每张显示 **税率 tag + 不含税金额 + 税额 + 发票金额**
   - 9% / 13% / 6% 使用不同颜色 tag (区分视觉)
2. **金额计算正确**:
   - 每组税额 = taxableAmount × taxRate
   - 每组发票金额 = taxableAmount + taxAmount
3. **Toast**: "**已按税率生成 2 组开票明细**"
4. **返回 SO 详情 Tab "开票申请"**, 列表多 2 条记录:
   - 每条 status=`PENDING_REVIEW`
   - **税率分组列**显示: `9% × 2 行 = ¥2500 (税 ¥225) | 13% × 2 行 = ¥800 (税 ¥104)`

### ❌ FAIL
| 现象 | 可能原因 |
|------|---------|
| 对话框只显示 1 张卡片 | SO items 全是同一税率 (准备问题) / 后端聚合逻辑 bug |
| 金额算错 | 税率计算公式错误 |
| taxBreakdown 为空 | 后端返回错误 |
| 对话框不弹 | 入口按钮未绑事件 |

### Network 验证
- `POST /api/mobile/F001/finance/invoices/request-from-order` 200
- Body: `{"salesOrderId":"xxx","invoiceType":"NORMAL","remark":"税率分组开票"}`
- Response 包含 `taxBreakdown[]`

## 9.6 后续流程 (审核 + 开具 + 收款)

### 9.6.1 财务审核 (2 条发票, 都要审)
**账号**: `finance`
**操作**: 对每条发票点 "**审核通过**" (参考 [08-finance-invoice.md](08-finance-invoice.md) §8.3)

### 9.6.2 开具发票 + 上传 PDF (2 次)
- 两张发票**分别开具**, 各上传 1 份 PDF
- 通常 9% 那张叫 `XX-普通发票-农产品-9-2725.pdf`
- 13% 那张 `XX-普通发票-加工-13-904.pdf`

### 9.6.3 SO 回写验证
**账号**: `sales`
**页面**: SO 详情 Tab "开票申请"

### ✅ PASS
- 2 条发票都 `ISSUED`
- 每条都有 "**下载**" 按钮, 都能下
- SO 总状态 "**已开票**" (全量)

### 9.6.4 收款 (分开或合并)
**账号**: `finance`
- **方案 A**: 分 2 笔录入 (对应每张发票)
  - 第 1 笔 ¥2725 (关联 9% 发票)
  - 第 2 笔 ¥904 (关联 13% 发票)
- **方案 B**: 合并 1 笔 ¥3629 (关联 SO, 不指定发票)

## 9.7 演示话术 (给客户看时)

**场景设置**:
> "这是一张真实订单, 永辉超市下单 3629 元. 里面既有农产品 (9% 税率) 又有加工费 (13% 税率), 按税法必须分开开票. 过去我们人工核对+拆分, 1 张单可能拆错. 现在系统自动."

**演示流程** (3 分钟完成):
1. 进 SO 详情 → Tab "开票申请" (30s)
2. 点 "**一键开票申请 (按税率分组)**" (演示 1 键搞定)
3. 对话框弹出 → 点 "一键按税率分组开票" (3s)
4. **重点解说**:
   - "看, 系统**自动**分成了 2 张: 9% 的 2725, 13% 的 904"
   - "每组的**行数/金额/税额**清清楚楚"
   - "无需人工核对, 金额一定对"
5. 点 "**确认生成分组发票**"
6. 回 Tab 列表, 2 条发票 `PENDING_REVIEW`
7. (快速切 finance 审核通过 + 开具, 或跳过)
8. 回 SO 看 2 条发票都挂到订单, 可下载 PDF

### 客户常问
| 问题 | 回答 |
|------|------|
| "支持 3 种以上税率吗?" | 支持, 按 items taxRate 字段聚合, 几种就几张 |
| "可以手动调整分组吗?" | V2 规划 (当前按系统自动) |
| "发票号怎么生成?" | 后端规则, 如 INV-YYYYMMDD-NNN, 可配 |
| "如果客户要合并开成一张?" | 按需开发, 目前默认分开 (符合税法) |
