## 51.2 配方管理 (`/restaurant/recipes`)

### 51.2.1 新建配方
**账号**: restaurant_manager / admin
1. 点 "新建配方" 按钮 (列表右上, type=primary)
2. 弹对话框, 字段 (R6 补 UI 组件类型):

| 字段 | 组件类型 | 必填 | 示例 |
|------|---------|------|------|
| 配方名 | el-input | ✅ | `麻辣牛肉锅底-V1` |
| 菜品 productTypeId | el-select (远程) | ✅ | 下拉选 |
| 原材料组成 | **el-table 子表** | ✅ | 每行 2 列 |
| - 食材 | el-select (行内) | ✅ | 下拉选 (从 raw_material_types) |
| - 数量 | el-input-number (行内) | ✅ | 100 |
| 标准产量 servings | el-input-number | ✅ | 2 |
| servings 单位 | el-select | ⚪ | 份/kg |
| 净成品率 netYieldRate | el-input-number | ✅ | 0.85 (0-1) |
| 单位 | el-input | ✅ | kg |
| 成本预算 | el-input-number | ⚪ | 80 |

3. 子表 "原材料组成" 添加行: 点 "+ 添加食材" 按钮, 每行填食材+数量
   - 行 1: 牛肉 100 g
   - 行 2: 辣椒 20 g
   - 行 3: 花椒 10 g
   - 行 4: 香料包 5 g
4. 点底部 "保存"

### ✅ PASS (Bug #10 回归)
- 防御校验: 必填空不能过
- 空串 id 不会提交
- Toast "创建成功"

### 51.2.2 配方 vs 实际消耗对比
- 实际报工消耗原料 vs 配方标准
- 偏差 > 10% 预警 (浪费检测)

## 51.3 盘点管理 (`/restaurant/stocktaking`)

### 51.3.1 新建盘点 (Bug #11 回归)
1. 点 "新建盘点"
2. 对话框**必含** "盘点日期" 字段 (默认今日, Bug #11 修复点)
3. 原材料类型 + 盘点数量
4. 保存

### ✅ PASS
- 盘点日期字段存在默认今日
- 不报 "null 为空" NPE

### 51.3.2 盘盈盘亏分析
- 系统库存 vs 实盘数量 → 差异
- 差异率 > 5% 预警
- 原因分析 (变质/损耗/盗窃/录入错误)

### 51.3.3 连续盘点趋势
- 每月盘点差异率
- 异常门店识别

## 51.4 损耗分析 (`/restaurant/wastage`) ⭐

### 51.4.1 新建损耗记录
**场景**: 食材变质 / 过期 / 客户退菜

1. 点 "新建损耗" 按钮 (`/restaurant/wastage` 列表右上)
2. 字段:

| 字段 | 组件 | 必填 | 示例 |
|------|------|------|------|
| 日期 wasteDate | el-date-picker | ✅ | 今日 (默认) |
| 食材 materialId | el-select (远程搜索) | ✅ | 牛肉 |
| 损耗数量 quantity | el-input-number | ✅ | 5 |
| 单位 | 只读, 跟食材 | - | kg |
| **损耗金额 wasteAmount** | el-input-number (**只读计算**) | - | = 前端实时算: `quantity × 采购均价` (从 `/warehouse/material-price/{materialId}` 取均价 API 调用) |
| 损耗原因 wasteReason | el-select | ✅ | 变质 / 过期 / 操作失误 / 客户退菜 / 其他 |
| 备注 | el-input textarea | ⚪ | `冰箱故障 8h` |
| 附件照片 | el-upload | ⚪ | 多张 |

3. 填数量后, 损耗金额**前端自动计算显示** (调均价 API + JS 乘法)
4. 点 "保存"

### 51.4.2 下游联动 (§25)
- 库存自动扣减
- 成本核算自动冲销
- 审计日志

### 51.4.3 损耗率
- = 损耗金额 / 采购金额
- 门店对比
- 行业基准 (餐饮 3-5%)
- **> 5% 预警**

### 51.4.4 趋势
- 日/周/月损耗率
- TOP 损耗食材
- 异常门店 / 异常时段

## 51.5 菜品四象限 ⭐ (`/restaurant/analytics/menu`)

### 51.5.1 BCG 矩阵
X 轴: 销量 / Y 轴: 毛利率 → 4 象限
- **明星** (高销高利): 主推
- **金牛** (高销低利): 走量
- **问题** (低销高利): 需营销推广
- **瘦狗** (低销低利): 建议下架

### 51.5.2 散点图交互
- 每菜品一个点
- 悬停 → 显示菜品名 + 销量 + 毛利率
- 点击 → 跳菜品详情

### 51.5.3 筛选
- 时间范围
- 门店 (多选)
- 菜品类别 (凉菜/热菜/主食/饮品/特色)

### 51.5.4 决策建议 (AI 自动)
- 瘦狗菜品 TOP5 → "建议下架, 节省 ¥N 成本"
- 问题菜品 → "建议加强营销, 潜力 ¥M"

## 51.6 门店对比 (`/restaurant/analytics/stores`)

### 51.6.1 多维度指标

- 客单价
- 翻台率
- 人效 (每员工产出)
- 食材成本占比
- 损耗率

### 51.6.2 排名
- 按任一指标排
- TOP 3 / BOTTOM 3

### 51.6.3 时间序列
- 各门店同期对比 (本月 vs 上月 vs 去年)

### 51.6.4 异常识别
- 某门店指标偏离均值 2σ → 标红 + AI 分析原因

## 51.7 大众点评差距 (`/restaurant/analytics/dianping-gap`)

### 51.7.1 数据源
- 大众点评爬取: 评分/评价数/客流
- 门店自报数据
- 差距分析

### 51.7.2 典型分析
- "某门店线上评分 4.2, 低于区域均值 4.5"
- "自报客流 500/天, 大众点评推算 350/天, 差距 30%"

### 51.7.3 Action 建议
- 低评分门店: 改善菜品质量 / 培训员工
- 数据差距门店: 核查收银系统准确性

## 51.11 配方-盘点-损耗-菜品四象限 链路 ⭐

### 餐饮全链路
```
配方 (标准)
    ↓
盘点 (实际库存 vs 系统)
    ↓
实际消耗 (报工) + 损耗 (变质)
    ↓
食材成本
    ↓
菜品毛利 (售价 - 成本)
    ↓
菜品四象限 (销量 × 毛利率)
    ↓
决策 (下架/推广)
```
