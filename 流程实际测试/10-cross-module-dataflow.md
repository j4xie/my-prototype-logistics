# 10. 跨模块数据流验证

**目的**: 验证不同模块之间的**数据联动**正确
**耗时**: 30 min
**前置**: 单模块 (03-08) 各自跑通

---

## 10.1 8 条核心数据链路

| # | 数据源 | 流向 | 验证点 |
|---|--------|------|-------|
| 1 | 样品 APPROVED | → 报价任务 | 自动创建 |
| 2 | 样品 APPROVED | → SO 产品下拉 | 可关联 |
| 3 | SO 创建 | → 库存原料扣减触发检查 | 库存不足预警 |
| 4 | SO FINANCE_APPROVED | → 采购单关联 SO | 可关联 |
| 5 | 采购收货 | → 原料库存 + 批次 | 库存更新 |
| 6 | 生产完工审批 | → 成品库存 + 批次 + 扣原料 | 多方联动 |
| 7 | 确认发货 | → SO 状态 SHIPPED + 成品扣减 + 批次扣减 | 三方联动 ⭐ |
| 8 | 发票开具 | → SO 开票状态 + PDF 回写 | 回写 |
| 9 | 收款录入 | → SO 结清状态 | 状态变化 |

## 10.2 链路 1: 样品审核 → 报价任务自动创建

### 步骤
1. (前置) [03-rd-sample.md](03-rd-sample.md) §3.6 审核通过 1 个样品
2. **立即**切 Tab "**报价任务**"
3. 查看是否有**新任务**出现, status=`PENDING`

### ✅ PASS
- Tab 切换后列表多 1 行
- 任务关联 sampleId = 刚审核的样品

### ❌ FAIL
- 报价任务列表不刷新 (前端未 reload)
- 任务没关联 sampleId (后端 event bug)

---

## 10.3 链路 2: 样品 → SO 产品下拉

### 步骤
1. (前置) 样品状态 `APPROVED`
2. 切 `sales`, 进 `/sales/orders` → "**新建**"
3. 点 "**产品**" 下拉

### ✅ PASS
- 下拉选项**包含**刚审核的样品名称
- 选中后, 单位/规格**自动联动**

### ❌ FAIL
- 产品下拉没有新样品 → 筛选条件漏 (可能未过滤 APPROVED)

### 额外验证
- 同一下拉中, `REJECTED` 样品**不应出现**
- `DRAFT` 样品**不应出现**

---

## 10.4 链路 3: SO 创建时库存检查

### 步骤
1. 新建 SO, 产品数量设为**超大** (如 100000 kg)
2. 提交

### 预期行为
- **方案 A (严格)**: 阻止提交, 提示 "原料库存不足: 辣椒 缺 50 kg"
- **方案 B (宽松)**: 允许提交, 后续采购环节补料

### ✅ PASS (视产品配置)
- 不管 A/B, 行为一致, 不崩溃

### ❌ FAIL
- 允许创建但后续生产时才报错 (用户体验差)

## 10.5 链路 4: SO 审核通过 → 采购单关联

### 步骤
1. SO `FINANCE_APPROVED` (04 完成)
2. `purchase` 账号创建采购单
3. 在 "**关联销售订单**" 下拉中找

### ✅ PASS
- 下拉**包含**刚审核的 SO
- 选中后, 行项目**可自动预填** (根据 BOM 拉取原料列表)

### ❌ FAIL
- SO 审核通过后下拉不出现 → 过滤条件漏

---

## 10.6 链路 5: 采购收货 → 原料库存 + 批次

### 步骤
1. (前置) 采购单 `FINANCE_APPROVED`
2. warehouse 收货 + 确认入库 (05.6 + 05.7)
3. **同步验证**库存 + 批次

### 验证 A: 原料库存
1. 进 `/warehouse/materials` 或对应原料详情
2. 找对应原料 (如 `辣椒`)
3. 库存应 **+ 实收数量**

### 验证 B: 批次
1. 进 `/warehouse/materials` (或材料详情的批次列表)
2. 应有新批次:
   - batchNo: `BATCH-YYYYMMDD-XXXX`
   - quantity: = 实收数量
   - status: `ACTIVE`
   - sourceType: `PURCHASE`
   - sourceId: = 收货单 ID

### 验证 C: 采购单状态回写
- 采购单状态变 `PARTIAL_RECEIVED` (部分) 或 `RECEIVED` (全量)

### ✅ PASS (3 点都对)

---

## 10.7 链路 6: 生产完工审批 → 三方联动 ⭐

### 核心验证点
生产审批通过后, **同时发生**:
1. **成品库存 + 完工数量**
2. **成品批次**生成
3. **原料库存 - BOM 消耗**

### 步骤
1. (前置) 06 完工 + 审批通过
2. 分别验证 3 点:

### 验证 A: 成品库存 +
- `/sales/finished-goods` → 对应产品
- 库存 **+100** (= outputQuantity)

### 验证 B: 成品批次
- `/warehouse/materials` → 成品
- 新批次:
  - quantity: 100
  - sourceType: `PRODUCTION`
  - sourceId: = 生产计划 ID

### 验证 C: 原料扣减 ⚠️
- BOM 里每 1 kg 成品需要 0.5 kg 辣椒
- 完工 100 kg → 应扣 50 kg 辣椒
- 检查原料辣椒库存 **- 50** (如 6.2 入库 50 后为 0)

### ⚠️ 已知问题
生产领料 UI 未实现, 扣减逻辑在**报工审批时批量执行** (而非领料时). 所以:
- 扣减时机晚
- 若有多工序, 各工序领料无法精细追踪

### ✅ PASS
- 3 点都对 = 成功
- 原料扣减数量 = BOM 消耗 × 完工数

### ❌ FAIL
- 只有成品库存增加, 原料库存没扣 → BOM 消耗逻辑 bug (严重!)

---

## 10.8 链路 7: 确认发货 → 三方联动 ⭐⭐

### 核心验证点
确认发货后, **同时发生**:
1. **SO 状态 = SHIPPED**
2. **成品库存 - 发货数量**
3. **批次状态更新** (DEPLETED / PARTIAL_USED)

### 步骤
1. (前置) 07.3 批次已分配, 07.4 warehouse 确认发货
2. 同时验证 3 点

### 验证 A: SO 状态
- 进 `/sales/orders/{id}/detail`
- 基本信息显示 `status=SHIPPED`
- 时间线有 "发货" 事件

### 验证 B: 成品库存
- `/sales/finished-goods`
- 库存 **- 100**

### 验证 C: 批次状态
- 进批次列表
- 发货用的批次:
  - 若完全用完 → `DEPLETED`
  - 若部分用 → `PARTIAL_USED`, 剩余数量减少

### ✅ PASS ⭐⭐
- 3 点联动正确

### ❌ FAIL
- SO 状态未变 SHIPPED → trigger chain 漏配
- 成品库存未扣 → 批次分配未真正关联 ship API
- 批次状态未变 → 发货逻辑漏扣批次

## 10.9 链路 8: 发票开具 → SO 回写

### 步骤
1. (前置) 08.4 发票 `ISSUED`, PDF 上传
2. 切 sales 进 SO 详情

### 验证
- Tab "开票申请" 发票状态 `ISSUED`
- 行末有 "**下载**" 链接 (`invoicePdfUrl` 不为空)
- SO 基本信息 "开票状态" 列 = "**已开票**"

### ✅ PASS
- 3 点都对

### ❌ FAIL
- 发票状态没变 → 后端回调未触发
- 下载链接空 → PDF 上传未写回字段

## 10.10 链路 9: 收款 → SO 结清状态

### 步骤
1. (前置) 08.6 录入收款金额 = SO 总额
2. 进 SO 详情

### 验证
- 基本信息 "**收款状态**" = "**已结清**"
- 时间线有 "收款" 事件

### 部分收款场景
- 录入金额 < SO 总额
- 状态应为 "**部分收款**"
- 再录一笔补齐后 → "**已结清**"

### ✅ PASS
- 状态联动正确

## 10.11 反向验证 (可追溯性)

### 从发票反查完整链路
1. 进 `/finance/invoices/list`
2. 找 09 生成的发票
3. 点 "**详情**" 或点发票号

### ✅ PASS
能看到关联链路:
```
发票 INV-xxx
  ← 销售订单 SO-xxx
      ← 发货单 DEL-xxx
      ← 生产计划 PLAN-xxx
      ← 采购单 PO-xxx (如有)
      ← 样品 SAMPLE-xxx (如有)
      ← 研发需求 REQ-xxx (如有)
  ← 收款记录 PAY-xxx
```

点任一链接应能跳转到对应详情页.

### ❌ FAIL
- 发票详情只有基本信息, 无关联链
- 跳转链接失效 404
