## 24.1 10 类边界规则

所有操作 (新建/编辑/删除/提交/审核) 都应满足:

| # | 类别 | 期望行为 |
|---|------|---------|
| 1 | 重复提交 | 按钮 loading 时 disabled, 反复点应只提交 1 次 |
| 2 | 空/非法输入 | 必填校验, 负数阻止, 日期顺序校验 |
| 3 | 超大输入 | 数量超库存预警, 文件 > 50MB 阻止 |
| 4 | 已终态再操作 | 已取消/已审核/已结清, 按钮隐藏或禁用 |
| 5 | 跨模块规则 | SO 发货后不能改数量, 开票后不能改客户 |
| 6 | 并发编辑 | A B 同编, 乐观锁 / 后保存提示冲突 |
| 7 | 删除保护 | 有引用的主数据 (供应商/部门/产品) 阻止删除 |
| 8 | 离页保护 | 填一半离开, 浏览器提示 "离开此页?" |
| 9 | 权限边界 | 越权访问 403 友好页 (不是技术 stack) |
| 10 | 批量操作 | 0 条不能触发, > 100 条警告 |

## 24.2 反复提交防护 (P0, 最高频)

### 测试方法 (任选一个 CRUD 操作)
1. 进入新建页 (如 SO 新建)
2. 填完必填
3. **连续快速点 "保存" 按钮 5 次** (< 1s)

### ✅ PASS
- 按钮点第 1 次后变 `loading...` 状态, **disabled**
- 后续 4 次点击**无反应**
- 最终只创建 **1 条记录** (不是 5 条)
- 若后端去重: Network 显示 1 个 POST 成功 + 4 个被前端拦截

### ❌ FAIL
- 创建了 2+ 条重复订单
- 按钮持续可点
- Network 多次 POST

### 覆盖操作
必须测:
- SO 创建 / 审核通过 / 驳回
- 采购单创建 / 审核 / 收货
- 发货单创建 / 确认发货
- 生产计划创建 / 报工 / 审批
- **⭐ 税率分组开票**: 对话框里反复点 "一键按税率分组" → 应只生成 1 批发票
- 收款录入 (可能导致重复扣账)

## 24.3 空/非法输入 (P0)

### 场景 1: 必填为空
- 所有必填标 `*` 的字段, 留空点保存
- ✅ 前端立即显示字段红框 + 错误提示
- ❌ 后端返 400 才提示 (体验差)

### 场景 2: 数量/金额 ≤ 0
- SO 数量填 `0` 或 `-5`
- 采购单价填 `-10`
- 报工完工数量 `0`
- ✅ 前端 `:min="0.01"` 阻止输入
- ✅ 校验 message: "请输入大于 0 的数"

### 场景 3: 日期逻辑
- **交货日期 < 下单日期** → 应提示
- **结束日期 < 开始日期** (报表筛选)
- **过期日期 < 入库日期** (批次)
- ✅ 实时校验, 不等到提交

### 场景 4: 格式校验
- 邮箱: `not-an-email` → 提示
- 手机: `12345` (不足 11 位) → 提示
- 税号: 长度不对 → 提示
- ✅ 一致的校验规则 (可能在 `@/utils/validators.ts`)

### 场景 5: 超长文本
- 备注字段输 5000 字符
- ✅ 前端截断到 max 或提示 "备注最多 XXX 字"

## 24.4 超大输入 (P1)

### 数量超库存
- SO 数量 `100000` (远超成品库存)
- ✅ 选项 A: 前端预警 "当前库存仅 100 kg"
- ✅ 选项 B: 允许提交, 后续采购环节补料 (V1 选此)
- 至少一致一个行为, 不能崩

### 文件上传超大
- 上传 100MB+ 的 Excel
- ✅ 前端阻止 (size limit 提示)
- ✅ 后端流式处理不 OOM (Bug-2 已修)

### 批量导入
- 导入 10000 行 Excel 员工
- ✅ 前端显示进度条
- ✅ 分批提交后端
- ✅ 完成报告成功/失败数

## 24.5 已终态再操作 (P0, 高风险)

### 测试方法
每个操作后, 再次尝试**相同**操作

### 覆盖
- **已取消 SO** 再点 "审核通过" → 按钮不该在
- **已 FINANCE_APPROVED 的 SO** 再点 "审核" → 按钮隐藏
- **已 SHIPPED 的 SO** 再点 "修改数量" → 禁用字段
- **已 ISSUED 的发票** 再点 "审核" → 按钮隐藏 (只能作废重开)
- **已结清 SO** 再点 "录入收款" → 提示 "订单已结清"
- **已 DEPLETED 的批次** 再点 "发货使用" → 不在 FIFO 候选
- **已 RECEIVED 全量采购单** 再点 "收货" → 按钮隐藏
- **已 REJECTED 样品** 再点 "通过" → 隐藏

### ✅ PASS
- 按钮消失或 disabled
- 尝试直接调 API → 后端 409 "状态不允许"

## 24.6 跨模块状态锁定 (P0)

### 规则
一旦关键事件发生, 上游数据**锁定**不可改:

| 锁定事件 | 锁定字段 |
|---------|---------|
| SO 审核通过 | 不能改金额/数量 (只能驳回后改) |
| 采购单审核通过 | 不能改供应商/单价 |
| 生产下达 | 不能改产品/数量 |
| 确认发货 | SO 所有字段锁 |
| 开票 | 不能改客户/金额 |
| 收款后 | SO 完全锁 |

### 测试
- SO 审核通过后, 点 "编辑" 按钮
- ✅ 字段变 readonly 或按钮消失
- ❌ 还能改 → 严重 bug

## 24.7 并发编辑 (P1)

### 场景
A 用户 + B 用户同时打开同 SO 编辑:
1. A 改单价 50 → 保存
2. B 改数量 100 → 保存

### 方案 A (乐观锁, 推荐)
- 实体含 `rowVersion` 字段
- A 保存成功, rowVersion +1
- B 保存时 rowVersion 不匹配, 后端返 409
- **前端提示 "数据已被其他用户修改, 请刷新重试"**

### 方案 B (悲观锁)
- A 打开时加锁, B 不能打开
- ✅ UI 显示 "此记录正在被 A 编辑"

### 测试
- 2 个浏览器 2 个账号, 同时打开同 SO
- 各改不同字段 + 保存
- ✅ 至少一方看到冲突提示

### ❌ FAIL
- 后保存悄无声息覆盖 (数据丢失)

## 24.8 删除保护 (P1)

### 测试
| 删除目标 | 有引用时 | 期望 |
|---------|---------|------|
| 供应商 | 有采购单 | 阻止 + 提示 "有 N 条采购单" |
| 部门 | 有员工 | 阻止 |

| 角色 | 有用户 | 阻止 (需先转角色) |
| 工厂 | 有任何数据 | 不能删 |

## 24.10 权限边界 (P0)

### URL 直接访问
1. 登 `operator` 账号
2. 地址栏输 `/system/users` (超管才能进)

### ✅ PASS
- 跳转到 `/403` 友好提示页
- 显示 "您没有权限访问此页面" + 返回按钮

### ❌ FAIL
- 技术 stack trace 暴露
- 白屏
- 页面加载但数据空 (权限漏洞)

### API 直接调
- 用 operator 的 token, 调 `DELETE /users/{id}`
- ✅ 后端 403 + 友好 message
- 前端拦截器显示 "权限不足"
