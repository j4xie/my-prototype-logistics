# 83. 品控流程 (摄像头 AI 异物识别)

> **🟡 R18 QA Partial (2026-04-17)**: §20 质检深度覆盖 + Bug #254/#255 fixed. 但**摄像头 AI 异物识别**部分未测 (camera SDK disabled). 品控流 Plan→批次→QC→FG 的 FG 环节 404 (/warehouse/finished-goods/batches 路径差异).

**来源**: 六扇门 Mar 18 会议
**原话**:
> "我们可能会在某一个工序段去设一个图像采集, 主要是异物类的"
> "透过塑料盒子识别, 难度会上升"

**耗时**: 40 min
**涉及模块**: §20 质量 + §40 摄像头 VL
**V1 范围**: 人工质检 + 摄像头 RTSP 实时流 + 不合格批次处置. AI 异物识别 → V2.
**后端** (真实路由, 已核对 controller):
- `QualityCheckItemController` @ `/api/mobile/{factoryId}/quality-check-items/*` (质检项**配置**: 模板/绑定/启停)
- `QualityDispositionController` @ `/api/mobile/{factoryId}/quality-disposition/*` (**处置** evaluate/execute/approve/pending/apply/history)
- `CameraController` @ `/api/mobile/{factoryId}/cameras/*` (V1 注册/RTSP; V2 AI 分析)
- **质检结果提交**: 走 `MobileController` / `ProcessingController` 的报工质检字段 (无独立 inspection POST 端点)

---

## 83.1 流程总览

```
[工序段] 摄像头持续采集 (或关键帧)
    ↓
[AI 识别] VL 模型扫异物 (金属/塑料/毛发/虫)
    ↓
[告警] 检出 → 工位屏红色 + RN 推送 inspector
    ↓
[RN 质检员] 扫批次 + 拍照 + 标记不合格
    ↓
[Web] 异常批次进 `/quality/disposals`
    ↓
[处置] 隔离 / 返工 / 报废 → 批次状态 FAILED
    ↓
[追溯] 影响的上下游 SO/出货单标记
```

---

## 83.2 Step-by-Step

### Step 1: 摄像头配置 (§40)
1. Web `/camera/devices` → 注册设备 + RTSP URL
2. 绑定工序 "分拣" 工位
3. 配置 AI 模型 (异物识别) + 阈值

### Step 2: 实时监控
1. `/quality/live` → 多路视频
2. 检出异物 → 画面圈红 + 记录帧

### Step 3: 告警分发
- 工位屏 WebSocket 推送
- RN inspector 推送 "请复检批次 B-xxx"

### Step 4: RN 现场复检 (V1 核心)
1. RN inspector 扫批次 QR → 拉质检项配置 `GET /quality-check-items/bindings/product/{productTypeId}`
2. 拍照上传 (走通用 upload 端点)
3. 提交质检结果: 走**报工/加工流程** (MobileController/ProcessingController) 的质检字段
4. 质检不合格 → 触发处置评估 `POST /quality-disposition/evaluate` body `{batchId, defectType, severity}`
5. 跨端 (§14.6): ≤3s 到 Web 待处置列表

### Step 5: Web 处置 (V1 核心)
1. foreman `/quality/dispositions` → `GET /quality-disposition/pending`
2. 评估处置动作 `GET /quality-disposition/actions?batchId=xxx` → 系统基于规则推荐
3. 执行处置: `POST /quality-disposition/execute` body `{batchId, action, reason}` (action: QUARANTINE/REWORK/SCRAP)
4. 或批量应用规则: `POST /quality-disposition/apply`
5. 管理员审批: `POST /quality-disposition/{id}/approve`
6. 处置历史: `GET /quality-disposition/history/{batchId}`
7. 批次 `status` 枚举流转 (真实 `MaterialBatchStatus`):
   - QUARANTINE → `INSPECTING` (冻结观察, 不可领料)
   - REWORK → 批次回 `AVAILABLE` (重工后)
   - SCRAP → `SCRAPPED` (库存 -, 成本损失记入差异)
8. `batch_status_history` 日志 + `quality_disposition_logs` 审计

### Step 6: 追溯联动
- 已出货部分 → 召回清单
- 原料批次 → 供应商评分扣分 (§19)

## 83.4 演示话术

> "我们可能会在某一个工序段去设一个图像采集, 主要是异物类的" — 张权原话.
> V1 现状: inspector 手机扫批次, 拍 3 张照, 标记不合格 + 备注. foreman 电脑秒见, 一键处置 (隔离/返工/报废). 批次状态自动变 INSPECTING/SCRAPPED, 库存联动.
> **V2 规划**: 摄像头接 AI 模型自动识别金属/塑料/毛发, 画面圈红告警. "透过塑料盒识别" 是难点 (张权原话), V2 会训练专用模型.

**客户常问**:
- "AI 识别准确率?" → V2 目标 95%+, V1 靠人工 (见 §40 VL 路径图)
- "识别到异物后批次怎么走?" → 自动进 disposition/pending, 规则引擎推荐处置动作
- "召回已出货的?" → 批次溯源 (§85.5 SQL) + 召回清单生成
