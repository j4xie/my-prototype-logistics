# V2.2 Fine-tune Guide — Client Data Adaptation

**Baseline**: V2.1_primary (refine2, TTA 0.708 on ULTRA val, ~33% on P1 holdout)
**Target**: V2.2 fine-tuned on YOUR production line images → expect 60-80% real production accuracy

---

## 1. Why fine-tune?

V2.1 对 **ULTRA 数据风格** 优化 (Roboflow/Kaggle 源). **真实产线摄像头图**的光照/角度/背景/食品类型可能与训练数据显著不同.

测试证明:
- ULTRA val (同风格): 0.708 mAP50
- P1 holdout (Bing/Baidu 真实图): 0.079 mAP50 — **断崖式下降**

**Fine-tune 是突破 30% 瓶颈的唯一路径**.

---

## 2. 数据采集规范 (客户端)

### 最低要求
- **每类至少 30 张**, 推荐 50-100 张 (6 类 × 50 = 300 张)
- 文件格式: JPG/PNG, 最低 1024×1024 (产线摄像头原始分辨率即可)
- 编号清楚: `<类>_<序号>.jpg` (e.g. `mold_001.jpg`)

### 拍摄条件 (与产线一致)
- ✅ 用**实际产线摄像头** (不是手机)
- ✅ 保持**训练时的光源** (白光/侧光/顶光都行, 保持一致)
- ✅ 拍食品在**正常运送姿态** (传送带上/分拣位/包装前)
- ✅ 异物**大小多样** (从几毫米小点到 1cm 大块都覆盖)

### 拍摄内容
对**每类**采:

| 类 | 要采的场景 |
|---|---|
| **insect** | 苍蝇/蟑螂/蚂蚁等常见入侵; 虫卵/幼虫; 小黑点状 |
| **color_anomaly** | 褐变/发黄/发黑斑; 异色污渍; 不均匀变色 |
| **bone** | 小碎骨片; 黄白色硬块; 不同大小 |
| **glass** | 透明碎片; 反光条纹; 夹在食品中 |
| **hair** | 单根长发; 卷曲毛团; 动物毛 |
| **mold** | 绿白色毛霉; 黑色斑点; 面包上绒毛 |

### 标注格式 (YOLO)
每图配一个 `.txt` 文件, 每行:
```
<class_id> <x_center> <y_center> <width> <height>
```
- class_id: 0=insect, 1=color_anomaly, 2=bone, 3=glass, 4=hair, 5=mold
- 坐标归一化到 [0, 1] (除以图片宽/高)

**推荐工具**:
- **CVAT** (web, 免费): https://cvat.org
- **Label Studio** (本地): https://labelstud.io
- **Roboflow** (简单快速, 有免费额度): https://roboflow.com

## 4. Fine-tune 命令 (V2.1 → V2.2)

### 服务器 (8 GPU 推荐, ~1h 训练)
```bash
cd /root
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 yolo train \
    model=/path/to/V2.1_primary_best.pt \
    data=/path/to/my_production_data/data.yaml \
    epochs=15 \
    imgsz=1280 \
    batch=32 \
    device=0,1,2,3,4,5,6,7 \
    project=/root/runs \
    name=V2.2_client_ft \
    workers=3 \
    patience=8 \
    save_period=5 \
    optimizer=SGD \
    lr0=0.0001 \
    lrf=0.01 \
    warmup_epochs=0 \
    mosaic=1.0 \
    mixup=0.1 \
    scale=0.4 \
    erasing=0.2 \
    close_mosaic=3
```

### 单卡 (本地测试, RTX 3090/4090, ~3-5h)
```bash
yolo train \
    model=V2.1_primary_best.pt \
    data=my_production_data/data.yaml \
    epochs=15 \
    imgsz=1280 \
    batch=8 \
    device=0 \
    name=V2.2_local \
    lr0=0.0001 \
    mosaic=1.0 \
    mixup=0.1 \
    scale=0.4 \
    close_mosaic=3
```

### 关键参数解释
- `model`: **必须**是 V2.1_primary_best.pt (warm-start, 不是从零)
- `epochs=15`: 对小数据集 (~300 张) 合适, 更多会过拟合
- `lr0=0.0001`: **比基础训练低 10 倍** (微调用小 lr)
- `scale=0.4`: 强 scale augmentation (防产线尺寸变化)
- `close_mosaic=3`: 最后 3 epoch 关 mosaic (稳定收敛)

## 6. 常见问题

**Q: 数据太少 (<100 张) 能 fine-tune 吗?**  
A: 可以但效果不佳. 建议至少 30 张/类, 尽量 50+. 数据不够时可配合 Copy-Paste augmentation.

**Q: 标错了/漏标能 fine-tune 吗?**  
A: 标注质量比数量重要. 宁可 50 张精标, 不要 200 张粗标. 标错会让模型学错误.

**Q: Fine-tune 后原始 ULTRA val mAP50 会降吗?**  
A: 会, 因为模型向客户数据适应. 这是**正常的** — V2.2 不再是通用模型, 而是**你的产线专用模型**.

**Q: 要不要冻结层?**  
A: 一般不需要 (15 epoch 小 lr 足够). 如果想尝试, 加 `freeze=10` 冻结前 10 层 (backbone), 只训 head. 适合数据极少时 (<30 张).

## 7. 交付流程

1. **客户**: 采 300 张真实产线图 + 标注 → 打包 `my_production_data.zip`
2. **我 (或你)**: 上传到服务器 → 跑 fine-tune (1h on 8 GPU) → 出 V2.2 best.pt
3. **我**: 生成 V2.2 inference config (同 V2.1 格式) + 测试可视化
4. **交付**: `V2.2_client_ft_fp16.onnx` + 配置 + 可视化报告

ETA: **客户采数据 1-2 周 → 训练 1 天 → 总 V2.2 交付 2 周**.
