扫码流程说明
  1. 工牌上的二维码内容 = 员工的 employeeCode 字符串（例如 EMP-001）

「原料类型」与「原料批次」的区别
  • 原料类型：定义这种原料「是什么」 — 名称、单位、保质期等属性。只需创建一次。
  • 原料批次：记录这种原料「来了多少」 — 每次入库产生一个批次，包含数量、批次号、采购价、到期日。一种原料类型可以有多个批次。

例如：「墨鱼」是一个原料类型，而「2026年3月25日从舟山渔业进了300kg墨鱼，批次号 MB-20260325-001」是一个原料批次。

5 产品模板与 BOM 配置 (Product Templates & BOM)

CORE CONCEPT 理解「模板」与「SKU」的关系

在本系统中，产品分为两个层级：

产品模板 (Template)
→
SKU (客户专属产品)
  • 产品模板：定义产品的通用信息（名称、单位、配方 BOM）。不关联任何客户，不能直接用于排产。
  • SKU：将模板 + 客户绑定，形成可销售、可排产的最终产品。一个模板可以组装出多个 SKU（分别给不同客户）。
为什么要分两层？ 因为同一个产品（如「墨鱼圈」）可能同时供应多个客户（汇庭、盒马、叮咚），每个客户的规格可能略有不同。模板定义通用配方，SKU 继承模板配方并关联具体客户。

计算公式详解

核心公式（系统内部计算逻辑）：

1. 标准用量（不含损耗）

standardUsage = 1 / conversionRate

例：转换率 0.80 → 标准用量 = 1/0.80 = 1.25（生产 1kg 产品需要 1.25kg 原料）

2. 实际用量（含损耗）

actualUsage = standardUsage × (1 + wastageRate/100)

例：损耗率 5% → 实际用量 = 1.25 × 1.05 = 1.3125

3. 排产需求量

requiredAmount = plannedQuantity × actualUsage

例：计划生产 200kg 墨鱼圈 → 需要 200 × 1.3125 = 262.5kg 墨鱼

转换率设置常见误区
  • 不要把转换率搞反：转换率是「1 单位原料产出多少产品」，不是「1 单位产品需要多少原料」。如果 1kg 墨鱼产出 0.8kg 产品，转换率填 0.80，不是 1.25。
  • 辅料的转换率通常很大：比如食盐，1kg 盐够做 50kg 产品，转换率就是 50.0。
  • 包装材料注意单位：如果包装袋单位是「个」，1 个袋子装 0.5kg 产品，转换率就是 0.5。
  • 损耗率设太高会导致原料需求虚高：正常生产损耗一般在 2%-10%，超过 15% 建议复核。
小技巧：如何验证 BOM 是否正确
  1. 在 Web Admin 的 BOM 页面，找到刚配置的产品
  2. 查看系统自动计算的「标准用量」列，确认数值合理
  3. 心算验证：如果计划生产 100kg，需要的原料量是否符合实际经验
  4. 如有偏差，直接编辑转换率修正

系统自动计算新的移动平均价：
新均价 = (原库存量 × 原均价 + 入库量 × 入库单价) / (原库存量 + 入库量)

例：原有库存 200kg @ 26元/kg，本次入库 300kg @ 28元/kg
新均价 = (200×26 + 300×28) / (200+300) = (5200+8400) / 500 = 27.2 元/kg

自动计算 填写入库数量和单价后，系统自动计算并显示本批次的总重量和总金额（数量 x 单价），方便核对。

调拨单是连接「排产」和「仓储」的桥梁。生成调拨单后，系统自动根据 BOM 配方计算所有原辅料需求，并通知仓库备货。

点击蓝色「生成」按钮确认。
系统后台自动执行以下操作（约 1-3 秒完成）:

第 1 步 — BOM 展开: 读取该 SKU 绑定的 BOM 配方 (转换率表)，根据计划数量反算每种原料的需求量。
    计算公式: 原料需求量 = 计划产量 / 转换率 x (1 + 损耗率)
    例如: 200kg 墨鱼圈，转换率 0.80，损耗 5% → 需要墨鱼 200/0.80 x 1.05 = 262.5 kg

第 2 步 — FEFO 库存校验: 检查仓库当前库存是否足够，按先到期先出 (First-Expire-First-Out) 原则分配批次。

第 3 步 — 创建调拨单: 生成一张 InternalTransfer 调拨单，包含所有原辅料的行项目 (line items)，每项标注: 物料名称、需求数量、单位。

第 4 步 — 自动提交审批: 调拨单状态设为「已申请」(REQUESTED)，自动推送给仓库端。仓储主管在手机 App 上会看到新的待处理调拨。

查看操作结果

"产品类型不存在" — 选择的产品已被删除或ID无效。解决: 重新选择正确的产品类型。

[取消] — 弹窗输入取消原因（必填）后取消计划。取消原因会记录在计划备注中，方便后续查询。

Step 10.4 补充: 累计报工机制

报工是累计的，不是覆盖的:
同一个工序、同一天内可以多次报工。每次提交都会创建一条独立的报工记录。

示例:
9:00 报工: 陈工 50 箱
10:30 报工: 陈工 45 箱
12:00 报工: 李工 60 箱
系统累计: 50 + 45 + 60 = 155 箱（显示在工序概况的「待审批」中）

审批流程: 每笔报工记录都需要管理员在 Web Admin「生产管理 → 报工审批」页面逐一审批。审批通过后才计入「已完成」数量。

12.3 常见问题 (FAQ)

Q1: 点击「生成调拨单」报错 "该产品无BOM配置"
原因: 选择的产品 (通常是基础模板而非 SKU) 没有配置 BOM 转换率。
解决:
1. 确认排产时选的是 SKU (带 "CP-" 前缀)，不是基础模板
2. 如果确实是 SKU，检查是否已配置转换率: 到「生产管理 → 转换率配置」查看
3. 如果没有转换率，需先为该产品配置 BOM（见第一部分 Section 5B 配置 BOM 转换率）
4. 配置完成后重新生成调拨单
Q2: 仓储发货时报错 "库存不足"
原因: 仓库中该原料的可用库存量不足以满足调拨需求。
解决:
1. 检查原料是否已完成入库: 到「仓储管理 → 原材料批次」查看库存
2. 如果是采购的新物料尚未入库，需先完成采购入库操作（见第一部分 Section 6B 原料入库）
3. 如果库存确实不够，需联系采购补货，或调整生产计划数量
4. 库存充足后再回到调拨单点击「确认发运」
Q3: 员工扫码签到失败，提示 "无法识别此工牌"
原因: 工牌二维码无法解析为有效的员工信息。
排查步骤:
1. 确认工牌是否是系统生成的（在 Web Admin「系统管理 → 员工工牌生成」页面生成）
2. 确认该员工已在「人事管理 → 员工管理」中创建且处于启用状态
3. 确认工牌没有破损导致二维码不可读
4. 尝试在光线充足的环境下重新扫码
5. 如果工牌损坏，需要在 Web Admin 重新生成并打印
Q4: 在报工界面看不到已签到员工列表（蓝色标签为空）
原因: 该工序当前没有员工签到。
解决:
1. 员工必须先扫码签到（Step 10.3）才会出现在列表中
2. 确认签到的工序与当前选择的工序一致（员工签到了「拆箱分拣」但你看的是「包装」）
3. 尝试点击返回后重新进入该工序，触发数据刷新
4. 如果不需要关联员工，可使用「方式C: 主管自己报」
Q5: 报工提交后在哪里审批？
审批入口: 管理员登录 Web Admin → 左侧菜单「生产管理 → 报工审批」
审批列表显示所有待审批的报工记录，管理员可逐一通过或驳回。
只有审批通过的报工才会计入工序的「已完成」数量。
Q6: BOM 达成率显示为 0% 或全部为空
原因: 车间主管没有录入实际原料用量（Step 9.2）。
解决: 必须在 App 中进入批次详情 → 点击「原料领料」→ 为每种物料录入实际用量。
没有实际用量数据，系统无法计算达成率。
Q7: SKU 毛利率显示为 0 或数据不完整
可能原因及解决:
1. 缺少原料成本: 检查原料入库时是否录入了单价 → 在「仓储管理 → 原材料批次」中查看
2. 缺少实际用量: 同 Q6，需录入 BOM 实际用量
3. 缺少销售价格: 需在客户定价或 SKU 配置中设置销售单价
4. 缺少人工工时: 员工需完成签到+签退，系统才能计算人工成本
Q8: 员工签退提示 "未签到此工序"
原因: 该员工没有在当前选择的工序中签到，或者已经签退过了。
排查:
1. 确认员工签到的是哪道工序（可能签到了其他工序）
2. 使用扫码定位功能（工序列表页右上角扫码图标）扫描员工工牌，系统会显示该员工签到的工序
3. 如果确实没有签到记录，可能是签到时操作失败或从未签到
Q9: 如何修改已提交的报工数量？
已提交的报工记录无法直接修改。如果数量有误:
1. 如果尚未审批: 让管理员在 Web Admin 驳回该笔报工
2. 在 App 中重新提交正确的数量
3. 如果已审批通过: 需联系管理员在后台处理
Q10: 调拨单审批后能否撤回？
审批通过但尚未发运的调拨单，在 Web Admin 的「调拨管理 → 调拨单列表」中可以进行取消操作。
已经确认发运的调拨单（库存已扣减），无法直接撤回，需要管理员通过反向调拨或库存调整来处理。

数据分析 (Analytics)

工厂管理员 Web Admin 分析模块主要面向管理层和调度员使用

数据分析模块提供多维度的生产运营数据可视化，包括生产 KPI、人效分析、趋势图表、进销存闭环等。帮助管理者快速把握工厂运营状态并发现问题。

生产数据分析

生产分析 › 生产数据分析
菜单路径: 生产分析 → 生产数据分析 (/production-analytics/production)

生产数据分析页面集中展示工厂的核心生产指标，支持按时间范围和产线维度切换查看。

用户看到什么

1
核心 KPI 卡片
页面顶部展示关键数据卡片：当日/本周/本月产量、计划完成率、良品率、设备稼动率。每个卡片带环比变化箭头（涨/跌）。
2
产量趋势图
折线图展示选定时间段内的每日产量趋势，支持按产线叠加展示。可切换日/周/月粒度。
3
产线对比柱状图
柱状图横向对比各产线的产量、良品率等指标，直观展示哪条产线表现更优。
4
时间范围选择器
页面顶部提供快捷按钮（今天/本周/本月/自定义），切换后所有图表和 KPI 卡片同步刷新。
数据来源 生产数据分析的数据来自员工报工记录和生产批次表。确保车间员工正常签到、报工、签退后，数据才会完整呈现。

人效分析

生产分析 › 人效分析
菜单路径: 生产分析 → 人效分析 (/production-analytics/efficiency)

人效分析页面从劳动效率角度分析各产线和员工的生产效率，帮助发现效率瓶颈和优秀员工。

用户看到什么

1
人效 KPI 概览
人均产量、人均工时、单位人工成本等核心人效指标。
2
员工效率排名
表格列出各员工在选定时段内的产量、工时、人均产出，支持按指标排序。
3
产线人效对比
横向对比各产线的人员配置和产出效率，用于评估产线人力分配是否合理。
计算口径 人均产量 = 总产量 / 参与人数。工时数据来自员工签到签退记录。若员工忘记签退，工时数据可能不准确，建议管理员定期检查考勤记录。

KPI 看板

数据分析 › KPI 看板
菜单路径: 数据分析 → KPI 看板 (/analytics/kpi)

KPI 看板以仪表盘形式一屏展示工厂最核心的运营指标，适合大屏投放或管理层每日查看。

用户看到什么

1
核心仪表盘
多个 KPI 卡片以网格布局展示：日产量、良品率、订单完成率、设备稼动率、库存周转天数、人均产出等。每个 KPI 带颜色编码（绿/黄/红表示达标/临界/告警）。
2
环比/同比变化
每个 KPI 指标下方显示与上一周期的对比变化（箭头 + 百分比），快速判断趋势方向。
3
自动刷新
看板数据默认每 5 分钟自动刷新一次，也可手动点击右上角刷新按钮立即更新。

趋势分析

数据分析 › 趋势分析
菜单路径: 数据分析 → 趋势分析 (/analytics/trends)

趋势分析页面提供可配置的多指标时间序列图表，用于发现长期运营趋势和周期性规律。

用户看到什么

1
多指标折线图
支持同时选择多个指标在一张图上叠加展示（如产量 + 良品率 + 订单量），使用双 Y 轴适配不同量纲。
2
时间粒度切换
支持日/周/月三种时间粒度。月粒度适合查看季节性趋势，日粒度适合排查具体问题。
3
指标选择器
左侧或顶部的指标勾选面板可勾选/取消感兴趣的指标类别（生产、质量、仓储、财务等），图表实时更新。
建议用法 周报/月报时使用趋势分析页面，选择过去 4 周或 3 个月的数据，对比产量和良品率的变化。如果发现良品率持续下降，结合质检记录查找原因。

进销存闭环总览

数据分析 › 进销存闭环总览
菜单路径: 数据分析 → 进销存闭环总览 (/analytics/supply-chain)

进销存闭环总览是一张全局视图，将采购（进）、生产+仓储（存）、销售+出货（销）三大环节串联起来，帮助管理者看清全链路的物料和资金流动。

用户看到什么

1
三大环节概览卡片
页面顶部三个大卡片分别展示：采购金额/数量汇总、当前库存价值/周转天数、销售金额/出货量汇总。
2
流转示意图
以桑基图或流程图形式展示物料从采购入库到生产消耗再到成品出库的流转路径和数量比例。
3
异常预警
当出现库存积压（周转天数过长）、采购与消耗不匹配等情况时，页面会以红色/橙色标注提醒。
闭环逻辑 进销存闭环的核心是确保：采购量 ≈ 生产消耗量 + 安全库存调整，销售量 ≈ 生产产出量。如果两侧数据长期偏差过大，说明供应链存在浪费或短缺风险。

调度管理 (Scheduling)

工厂管理员 / 调度员 Web Admin

智能调度模块提供可视化的排产调度能力，整合生产计划、设备、人员三个维度，辅助调度员做出更合理的排产安排。

调度中心

智能调度 › 调度中心
菜单路径: 智能调度 → 调度中心 (/scheduling/overview)

调度中心是调度模块的总览仪表盘，一屏展示当前排产状态、产线负载和待处理事项。

用户看到什么

1
产线负载概览
以甘特图或进度条形式展示各产线当前和近期的排产负载，直观判断哪条产线有余量、哪条过载。
2
待排任务
未排入产线的生产计划以列表形式展示在侧边栏，调度员可拖拽或选择分配到具体产线和时间段。
3
告警与冲突提示
当排产出现时间冲突、人员不足、设备维护冲突时，顶部告警条会提示需要调整的计划。

调度计划

智能调度 › 调度计划
菜单路径: 智能调度 → 调度计划 (/scheduling/plans)

调度计划列表管理全部已创建的调度计划，支持创建新计划、查看计划详情和调整计划状态。

关键操作

1
查看计划列表
列表展示所有调度计划，包含：计划编号、计划日期、关联生产计划、状态（草稿/已发布/执行中/已完成）。支持按日期和状态筛选。
2
创建新调度计划
点击「新建计划」按钮（或从调度中心直接创建），选择计划日期、关联的生产计划和产线，配置人员分配后保存。路径：/scheduling/plans/create
3
查看计划详情
点击计划行进入详情页，查看完整的时间线、产线分配、人员安排。可在详情页内修改和发布计划。
调度与生产计划的关系 生产计划（Section 7）定义了「做什么、做多少」，调度计划在此基础上进一步确定「什么时间、哪条产线、谁来做」。调度计划创建后需发布才能生效，发布后相关人员可在 App 端看到当日排班。

补充模块 (Additional Modules)

工厂管理员 Web Admin

以下模块是系统运营中的辅助功能，涵盖质检标准配置、废弃处理、采购价格表、成品库存、考勤、部门管理、角色权限和系统日志等。按需使用。

质检标准管理

质量管理 › 质检标准
菜单路径: 质量管理 → 质检标准 (/quality/standards)

质检标准定义了不同产品或原料的质量检验项目和合格范围。创建质检记录时，系统会自动关联对应的质检标准。

关键操作

1
查看标准列表
列表展示全部质检标准，包含标准名称、适用对象（产品/原料类型）、检验项目数量、状态（启用/停用）。
2
创建质检标准
点击「新建标准」，填写标准名称、适用的产品或原料类型，然后逐项添加检验指标（如温度范围、微生物限值、外观要求等）及其合格范围。
3
编辑 / 停用标准
对已有标准可以修改检验项目和合格范围。停用后该标准不再出现在新建质检时的关联选项中，但历史记录不受影响。

废弃处理

质量管理 › 废弃处理
菜单路径: 质量管理 → 废弃处理 (/quality/disposals)

废弃处理记录不合格品的处置过程和结果。质检不合格后需创建废弃处理记录，确保不合格品有据可查。

关键操作

1
查看废弃记录
列表展示所有废弃处理记录，包含：关联质检单号、产品/原料名称、废弃数量、处理方式（销毁/退回供应商/降级使用）、处理日期。
2
创建废弃记录
点击「新建废弃处理」，选择关联的质检记录（或直接选择批次），填写废弃数量、处理方式和原因说明后提交。
溯源要求 食品安全法要求不合格品处理必须有完整记录。废弃处理记录会关联到质检记录和对应的生产批次，确保可追溯。

价格表管理

采购管理 › 价格表管理
菜单路径: 采购管理 → 价格表管理 (/procurement/price-lists)

价格表管理维护各供应商对不同原材料的报价信息，创建采购订单时系统自动引用最新价格。

关键操作

1
查看价格表列表
列表展示所有价格条目，包含：供应商名称、原料名称、单价、币种、有效期（起止日期）、最小起订量。支持按供应商或原料筛选。
2
新增 / 更新报价
点击「新增」按钮，选择供应商和原料，填写单价、有效期等信息。同一供应商和原料可以有多条历史报价，系统自动使用有效期内最新的一条。
3
价格对比
选择某种原料后，可以横向对比各供应商的报价和历史价格变化，辅助采购决策。

成品库存

销售管理 › 成品库存
菜单路径: 销售管理 → 成品库存 (/sales/finished-goods)

成品库存页面展示已完成生产并入库的成品库存情况，是出货管理的基础数据来源。

用户看到什么

1
成品库存列表
列表展示所有成品的当前库存：产品名称（SKU）、规格、批次号、库存数量、库位、入库日期、保质期截止日期。
2
库存预警
临近保质期的成品行以橙色标注，已过期的以红色标注。库存不足（低于安全库存）的产品也会高亮提示。
3
搜索与筛选
支持按产品名称搜索、按批次号精确查找、按库存状态（正常/预警/过期）筛选。

考勤管理

人事管理 › 考勤管理
菜单路径: 人事管理 → 考勤管理 (/hr/attendance)

考勤管理页面汇总展示员工的签到签退记录。数据来自 App 端员工的签到/签退操作。

用户看到什么

1
考勤记录列表
列表按日期展示每位员工的签到时间、签退时间、工时、出勤状态（正常/迟到/早退/缺勤）。
2
日期与员工筛选

数据来源 考勤数据由 App 端员工操作产生。车间主管在 App 点击「签到」开始当班，「签退」结束当班。Web 端只做查看和统计，不支持手动补签。

人事管理 › 部门管理
菜单路径: 人事管理 → 部门管理 (/hr/departments)

部门管理用于配置工厂的组织架构，创建和维护各部门信息。员工创建时需要关联所属部门。

关键操作

1
查看部门列表
以树形结构或平铺列表展示所有部门，包含部门名称、部门编号、上级部门、负责人、人数。
2
创建 / 编辑部门
点击「新增部门」，填写部门名称、编号、选择上级部门（可为空表示顶级部门）和部门负责人后提交。

删除部门

角色管理

系统管理 › 角色管理
菜单路径: 系统管理 → 角色管理 (/system/roles)

角色管理页面配置系统中的角色和对应的权限。系统内置了常用角色（工厂管理员、调度员、仓储主管、车间主管等），管理员可查看和调整权限分配。

用户看到什么

1
角色列表
列表展示所有角色，包含：角色名称、角色代码（如 factory_super_admin、dispatcher 等）、描述、关联用户数。

点击角色行的「权限」按钮，以树形勾选框形式展示所有功能模块和操作权限。勾选/取消勾选即可调整该角色的访问范围。

新建自定义角色
如果内置角色不满足需求，可以点击「新建角色」创建自定义角色并配置权限。
注意 修改角色权限后，已登录用户需要重新登录才能生效。内置角色（factory_super_admin 等）建议不要删除，可以修改其权限范围。

系统设置

系统管理 › 系统设置
菜单路径: 系统管理 → 系统设置 (/system/settings)

系统设置页面管理当前工厂的基础配置、通知配置和安全配置。配置项按分类分组为多个 Tab 页签。

配置分组

1
基础设置
工厂名称、工厂编号、联系方式、地址等基本信息。修改后全局生效（如报表中的工厂名称）。
2
通知设置
配置系统通知的发送规则，如：库存低于安全线是否发送提醒、设备告警是否推送到 App、质检不合格是否通知管理员等。
3
安全设置
密码策略（最小长度、过期时间）、登录安全（失败锁定次数）等安全相关配置。
建议 新工厂接入后第一步应完善基础设置中的工厂信息，确保报表和打印输出的工厂名称正确。通知设置可根据实际管理需求逐步启用。
