§1 智能数据分析 (AI Query)

智能数据分析 (AI Query) 是白垩纪 SaaS 的核心分析入口，允许用户用自然语言直接提问，例如"本月畅销菜品是什么？"或"哪家门店毛利率最低？"，无需编写 SQL 或配置报表。系统自动识别数据集字段、执行聚合计算、生成图表并输出文字解读。解决了传统 BI 工具需要专业配置人员的痛点，适用于经营分析、成本监控、门店对比等日常场景，让前台员工和管理层都能独立获取数据洞察。

§1.1 进入路径

进入 AI Query 有两条路径：

  1. 菜单导航路径（推荐）：登录系统后，点击左侧导航栏"智能 BI"分组，再点击"智能数据分析"，即可进入 AI Query 主页面。
  2. Dashboard 快捷入口：在首页 Dashboard 右上角区域，找到"快捷分析"卡片，点击其中的分析场景按钮（如"畅销品 Top 5"、"本月营业额"），系统会直接带着预设问题跳转到 AI Query 并自动发送提问。
新员工提示：第一次使用前，请确认负责人已为你的账号配置了数据集访问权限。若进入后看不到任何数据集，联系门店管理员开通权限。

§1.2 主界面 layout

AI Query 页面由四个主要区块组成：

区块位置功能说明
顶部工具栏页面顶部数据集选择下拉菜单（选择已上传的 Excel 数据集）、上传新 Excel 按钮、历史对话按钮
中央查询输入区页面中部自然语言输入框 + 发送按钮；下方显示快捷问题按钮（系统根据数据集字段自动推荐）
结果展示区输入区下方AI 回答文字 + 可视化图表（柱状图/折线图/饼图，图表右上角有下载按钮）
左侧历史面板页面左侧历史问答列表，按时间倒序排列，点击可重新加载该次对话上下文
快捷问题按钮会根据当前选择的数据集动态变化。切换数据集后建议先看一眼新出现的快捷问题，了解该数据集适合回答哪类问题。

§1.3 常用操作步骤

  1. 选择或上传数据集：点击顶部工具栏"数据集"下拉，选择已上传的数据集；若没有合适数据集，点击"上传 Excel"按钮，上传 .xlsx / .xls / .csv 文件（详见 §3）。
  2. 确认数据预览：系统上传后会自动识别字段并显示数据预览（前 5 行），检查列名和数据是否正确。
  3. 输入自然语言问题：在中央输入框输入问题，如"本月各门店营业额对比"或"上周食材成本最高的五个菜品"。也可点击下方快捷问题按钮直接提问。
  4. 发送并等待：点击发送按钮（或按回车），AI 处理通常需 5-15 秒，期间显示"正在分析中..."。
  5. 查看回答：结果展示区出现 AI 文字回答，下方附带对应图表（图表类型由 AI 自动选择）。
  6. 追问：可直接在输入框继续追问，如"刚才最高的那家门店上个月呢？"，AI 会引用上一轮回答的上下文。
  7. 导出结果：点击图表右上角下载图标，可保存图表为 PNG；点击数据表格右上角导出图标，可下载 CSV。
  8. 查阅历史：点击左侧历史面板中的记录，可重新加载该轮对话，继续追问或分享截图。

§1.4 常见错误处理

错误提示原因处理方法
"未找到数据集" / "请先上传数据"当前账号下没有可用数据集，或数据集权限未开通前往 §3 上传 Excel 文件；若权限问题联系管理员
"分析超时" / 长时间无响应数据量过大（超 5 万行）或问题过于复杂先筛选时间范围（如指定"本月"而非"全年"），分批提问；或先在 Excel 里按条件过滤后再上传
"回答内容与预期不符"问题描述不够具体，AI 选错字段或聚合维度问题中加入门店名称、日期范围、具体指标名称；例如把"最近业绩"改为"2026年4月各门店营业额"
"字段未识别" / AI 回答不认识某列Excel 列名为英文缩写、空格或语义模糊检查并修改 Excel 列名为清晰中文（见 §3.2），重新上传
"图表无法显示"数据行数不足（<3 行）或浏览器渲染异常刷新页面；若数据集确实只有少数行，图表不会生成，查看文字回答即可
若 AI 回答中出现数字与看板明显不符，优先核对所选数据集的时间范围和来源是否一致，见 FAQ §4。

§1.5 关键指标速查

以下为餐饮经营核心 KPI，在 AI Query 中直接用指标名提问即可获取对应数据：

营业额 (Revenue) — 时段内所有订单收入合计，是经营健康度的第一信号。见 指数字典 §营业额
客单价 (ATV, Average Transaction Value) — 营业额 ÷ 成交笔数。餐饮行业均值约 ¥45-80（快餐偏低，正餐偏高），持续低于均值需关注菜单结构和套餐设计。见 指数字典 §客单价
翻台率 — 桌位在一天内被使用的次数（翻转次数）。正餐均值 3-4 次/天；低于 2 次需排查服务流程效率或门店动线。见 指数字典 §翻台率
毛利率 — (营业额 - 食材成本) ÷ 营业额。餐饮正常区间 55-70%；低于 50% 表示食材成本或损耗偏高，需介入菜品结构审查。见 指数字典 §毛利率
食材成本率 — 食材采购成本 ÷ 营业额。健康区间 28-35%；超过 38% 必须介入，优先排查高成本菜品（见 §11）和损耗记录（见 §10）。见 指数字典 §食材成本率
复购率 — 回头客占总顾客数的比例。低于 30% 说明顾客粘性不足，需关注服务质量和会员运营（见 §16）。见 指数字典 §复购率
外卖占比 — 外卖订单营业额 ÷ 总营业额。超过 60% 说明堂食流量不足，需关注门店体验和营销（见 §15）。

§1.6 业务判断框架

当 AI Query 返回数据后，按以下路径进行业务判断：

营业额下滑

先问 AI "本月 vs 上月营业额各门店差异" → 定位下滑门店 → 再问"该门店客单价和客流量趋势"：

  • 客单价正常，客流量下滑 → 转 §16 会员分析 看老客流失率；看 §15 外卖平台 评分是否下降
  • 客单价下滑，客流量正常 → 转 §11 菜品管理 检查高价菜品点单率；审查促销活动是否过度折扣（见 §18）
  • 客单价和客流量均下滑 → 查 §17 评价管理 和 §19 投诉记录 是否有集中负面反馈

食材成本率超警戒线 (38%)

问 AI "本月食材成本率最高的 5 个菜品" → 找出毛利倒挂菜品 → 转 §11 配方管理 核实配方用料成本 → 联系供应商（见 §9）议价，或调整菜品定价、暂停该菜品。

某门店翻台率突然降低

问 AI "该门店近 7 天翻台率趋势" → 排查 §21 排班记录 是否人员不足 → 查 §17 客诉 是否出现服务问题 → 对比该门店外卖单量变化（见 §15），判断是堂食问题还是整体流量问题。

§1.7 跨章节联动

AI Query 是数据分析的起点，发现问题后通常需要跳转到专项章节深入处理：

联动章节触发场景联动方式

§1.8 常见决策场景

场景 A：月度营收下滑 5%

背景：月末数据出来后，老板/店长发现本月营业额同比上月下滑 5%，需要快速定位原因。

分析步骤：

  1. 在 AI Query 选择本月销售数据集，问："本月 vs 上月营业额差异来自哪些门店？"
  2. AI 回答列出各门店差异后，追问表现最差的门店："该门店本月客单价和客流量趋势如何？"
  3. 若客单价正常但客流量下滑，转 §16 会员分析，问"该门店近 30 天新客与回头客比例变化"。
  4. 若同时发现外卖评分下滑（见 §15），联合判断：是服务问题导致差评，还是平台流量政策变化。
  5. 形成改善方案后，在 AI Query 设置跟踪问题（如"本周该门店日均营业额"），每日跟踪恢复进度。

场景 B：食材成本率突破 38%

背景：财务月报显示食材成本率从上月 32% 升至本月 39%，需要找出根因。

分析步骤：

  1. 在 AI Query 上传本月采购和销售数据，问："本月食材成本率最高的 5 个菜品是什么？"
  2. 找出毛利倒挂菜品（成本率 > 40%）后，转 §11 菜品配方管理，核查该菜品理论用料量与实际用料量的偏差。
  3. 若理论与实际偏差 > 10%，检查 §10 库存损耗记录，判断是损耗过高还是配方本身不合理。
  4. 联系供应商（§9）查询原材料近期涨价情况，决定是议价、换供应商还是调整菜品定价。
  5. 处理后下月在 AI Query 跟踪"食材成本率环比变化"，确认改善效果。

场景 C：新店开业数据监控

背景：新门店开业第 1 周，老板需要每日监控经营健康度，与预期目标对比。

分析步骤：

  1. 每日将当天收银数据导出上传到 AI Query，问："今日营业额、翻台率、客单价达标情况如何？"（设定目标值参考：开业首周营业额目标、翻台率 ≥ 2 次）
  2. 前 7 天建立基线数据，第 8 天起追问："本周各日营业额趋势，是否有明显波动？"
  3. 若发现某天数据异常（如翻台率骤降），立即排查当日排班（§21）和设备状况（收银机/厨房设备）。
  4. 开业第 30 天，在 §13 多门店对比模块，把新店与同区域老店同期数据横向对比，定位差距所在维度。
  5. 前 30 天数据积累后，AI Query 可开始回答趋势类问题（"本店客单价增长趋势"），指导后续运营策略。

FAQ

Q：AI Query 支持哪些数据格式？
目前支持 Excel 文件（.xlsx / .xls）和 CSV 文件（.csv）。上传后系统自动解析字段并生成预览。详细上传规范见 §3。单文件建议不超过 30MB，超大文件请先按时间段拆分。
Q：历史问答能保留多久？
系统保留当前账号最近 50 条问答记录（含追问轮次）。超出后最早的记录会被清除。重要分析结论建议截图或导出 CSV 保存。
Q：为什么不同时间问同一问题会得到不同答案？
最常见原因是切换了数据集，或上传了新数据覆盖了旧版本。建议每次提问明确指定时间范围（如"2026年4月"）和门店，避免歧义。也可检查顶部工具栏当前选中的数据集名称是否一致。
Q：AI 给出的数字和财务 PBI 看板不一样，哪个准确？
两者数据源不同：AI Query 计算依赖你上传的 Excel 文件（静态快照），PBI 看板（见 §2）直连实时数据库。若 Excel 导出时间与看板口径不一致，数字会有差异。核对方法：确认 Excel 的导出时间范围与看板显示时间范围完全一致。
Q：能否让 AI 一次分析多个 Excel 文件的跨文件关联？
目前每次分析基于单一数据集。若需要跨文件关联（如销售数据 + 采购数据联合分析），请先在 Excel 中手动合并为一个文件，再上传。跨 Sheet 分析功能请参考 §2 财务 PBI 看板。

§2 财务 PBI 看板

财务 PBI 看板是白垩纪 SaaS 的固定格式财务仪表盘，实时汇总门店营收、食材成本、毛利润、应收账款 (AR) 和应付账款 (AP)。与 AI Query (§1) 的自由问答不同，PBI 看板以卡片+折线图形式呈现预设 KPI 趋势，无需配置即可使用。主要受众：财务文员（日常对账）、店长（每周回顾）、老板（月度复盘）。一眼看出门店财务健康状况，无需手动汇总报表。

§2.1 进入路径

进入财务 PBI 看板有两条路径：

  1. 菜单导航路径（推荐）：登录系统后，点击左侧导航栏"智能 BI"分组，再点击"财务 PBI 看板"，即可进入主页面。
  2. Dashboard 快捷入口：在首页 Dashboard 的"财务摘要"卡片右下角，点击"查看详情"链接，直接跳转到财务 PBI 看板，并自动定位到当前门店当月数据。
权限提示：AR/AP 面板默认仅对财务文员及以上角色可见。若看不到该面板，请联系管理员在"设置 → 角色权限"中开通"财务数据查看"权限。

§2.2 主界面 layout

财务 PBI 看板页面由五个主要面板组成：

面板位置内容说明
顶部筛选栏页面顶部门店选择下拉（单店 / 全部门店汇总）；时间范围选择（日 / 周 / 月 / 自定义区间）；点击"刷新"手动更新数据
营收总览卡片第一行左侧显示所选时段的总营业额大数字；右侧展示同比（去年同期）和环比（上月）变化百分比；下方折线图显示日/周趋势
成本结构卡片第一行右侧环形图展示食材成本、人工成本、运营成本各自占比；可点击某类成本高亮对应折线
毛利润面板第二行左侧显示毛利额（元）和毛利率（%）；与上期对比的涨跌箭头；折线图显示毛利率近 30 天趋势
AR/AP 面板第二行右侧应收账款余额、应付账款余额；逾期应收（>30 天）高亮显示；点击金额可下钻到明细列表
折线图交互：点击任意数据点可下钻到该日/周的明细数据，双击折线图背景可还原到汇总视图。

§2.3 常用操作步骤

以下是财务 PBI 看板的标准操作流程（建议每周一例行执行）：

  1. 选择目标门店：在顶部筛选栏的门店下拉中选择"全部门店"（看整体）或指定单店（看具体问题）。多门店老板建议先看"全部门店"汇总，再逐店下钻。
  2. 设置时间范围：点击时间选择器，选"本月至今"作为起点。若需对比，可切换到"上月"或自定义日期区间。
  3. 查看营收总览卡片：确认整体营业规模，注意同比/环比箭头方向。环比下滑超 5% 需要进一步分析原因。
  4. 点击"成本结构"展开：重点关注食材成本占比是否在 28-35% 正常区间内。若超过 38%，立即进入 §11 菜品成本模块排查。
  5. 查看毛利率面板：确认毛利率是否在 55-70% 正常区间。毛利率低于 55% 为预警信号，需结合成本结构卡片定位原因。
  6. 下拉查看 AR/AP 面板：确认有无逾期应收款（橙色/红色高亮）。逾期 30 天以上的应收款项需逐一核查并安排催收。

可选操作：点击折线图任意数据点，可下钻到日维度明细，查看某天营收波动的原因（如节假日、促销活动）。

§2.5 关键指标速查

以下是财务 PBI 看板中六个核心 KPI 的定义、正常区间和预警阈值：

指标定义正常区间预警阈值

食材成本率 食材采购成本 ÷ 营业额 × 100%。详见 指标字典 §食材成本率 28% – 35% >38% 需立即介入

食材成本率 = 食材采购成本 ÷ 营业额 × 100%

§2.6 业务判断框架

场景一：食材成本率突破 38%

当 PBI 看板显示食材成本率超过 38% 时，按以下步骤排查：

  1. 第一步 — 定位问题菜品：进入 §11 菜品成本模块，按毛利率升序排列，找出毛利率为负或极低的菜品（毛利倒挂菜品）。
  2. 第二步 — 判断成本上涨来源：打开 §9 采购模块，查看近 3 个月同类食材的进价趋势。若进价已显著上涨，问题在供应商；若进价稳定，问题在菜品定价。
  3. 第三步 — 采取行动：
    • 如果是供应商涨价 → 在 §9 采购模块重新询价，对比至少 2 家供应商，协商返点或切换供应商。
    • 如果是菜品定价过低 → 将分析结果提交老板，调整菜单定价（建议同步更新 §11 菜品成本中的目标成本率）。

场景二：毛利率低于 55%

毛利率低于 55% 不一定全由食材成本导致，还需排查：

  1. 查看成本结构卡片中运营成本占比是否异常，特别关注外卖平台佣金是否突增（结合 §15 外卖平台对接模块核查）。
  2. 查看 AR/AP 面板有无大额退款拉低营业额分子（退款会减少营收但成本不变，导致毛利率虚低）。
  3. 如以上都正常，则可能是节假日客流异常或大额团购优惠影响，结合 AI Query (§1) 自由分析具体原因。
注意：毛利率低于 45% 属于财务危机信号，需要老板和财务总监共同介入，不要仅由店长自行处理。

§2.8 常见决策场景

场景 A：营收环比下滑 8%

分析步骤：

  1. 在 PBI 看板"营收总览卡片"确认下滑的具体时段（是整月均滑还是某周突降）。
  2. 跳转到 §1 AI Query，提问"上月哪个门店营收下滑最多？"，获得门店维度分析。
  3. 定位到问题门店后，查看该店翻台率（§1 AI Query 提问）和外卖订单量（§15 外卖平台对接）。
  4. 结合 §16 会员分析确认是否有会员流失（回头客减少）。根据根因制定恢复方案（促销活动、菜品调整等）。

场景 B：食材成本率从 31% 升至 41%

分析步骤：

  1. 在 PBI 看板"成本结构卡片"确认成本异常的月份，点击折线图定位具体拐点日期。
  2. 进入 §11 菜品成本模块，按食材成本率降序排列，找到成本超标的菜品类别。
  3. 进入 §9 采购模块，查看涉及食材近 3 个月的进价变化曲线。
  4. 与主供应商协商返点，或在系统内发起重新询价比价（§9 询价单功能）。若成本持续超标，向老板提交涨价申请。

场景 C：月末财务对账

操作步骤：

  1. 在 PBI 看板将时间范围设为"本月"，选择"全部门店"，截图或导出营收/成本汇总数据。
  2. 下拉至 AR 面板，筛选逾期 >30 天的应收款，逐一导出明细，安排催收跟进。
  3. 查看 AP 面板，确认本月应付账款中临近账期的款项，安排付款计划避免逾期违约。
  4. 进入 §6 报表中心导出财务明细 Excel，与 POS 系统数据核对，确认无差异后归档。

FAQ

Q: PBI 看板和 AI Query 有什么区别？什么时候用哪个？
A: PBI 看板是固定指标固定格式的例行监控工具，适合每日/每周例行检查标准 KPI（营收、成本、毛利、AR/AP）。AI Query 是自由问答工具，适合临时分析非标准问题（如"哪位员工的班次与营收最相关"）。两者互补，建议先用 PBI 看板发现异常，再用 AI Query 深挖根因。
Q: 为什么我的数据总是延迟一天？
A: 财务数据默认 T+1 同步，当日销售数据在次日凌晨 2:00 刷新到看板。如需实时数据，需要 POS 系统开启直连模式（涉及技术配置，请联系技术支持）。
Q: AR 面板一直显示 0，是系统 bug 吗？
A: 不是 bug。纯现金收款或扫码支付的门店，所有收款即时到账，AR（应收账款）= 0 完全正常。AR 面板主要针对有对公账单或月结企业客户的门店。如果你的门店有月结客户但 AR 显示 0，请检查"报表中心（§6）→ 财务明细"中是否有未同步的月结记录，并联系技术支持。
Q: 不同门店之间的毛利率差异很大，这正常吗？
A: 正常。不同区域（租金成本）、店型（堂食/外卖占比）、菜系的成本结构差异显著。不建议跨门店横向比较毛利率绝对值，应与该门店自身的历史均值对比，同比/环比变化才是真正有参考价值的信号。可在 §13 多门店对比分析模块查看标准化后的对比视图。

§3 Excel 上传与字段识别

§3 Excel 上传是智能数据分析 (§1) 的数据入口，支持 .xlsx/.xls/.csv 文件拖拽上传。系统自动识别表头字段（日期/门店/菜品/营收/成本等），完成字段映射后即可进行 AI Query 分析。是中台财务和运营人员日常数据导入的核心操作。支持 POS 导出文件、线下汇总表、各平台对账单等多种来源格式。

§3.1 进入路径

进入 Excel 上传有两条路径：

  1. 菜单导航路径（推荐）：登录系统后，点击左侧导航栏"智能 BI"分组，再点击"数据集管理"，进入列表页后点击右上角"上传数据集"按钮。
  2. AI Query 快捷入口：在 AI Query 页面（§1）顶部工具栏，点击"上传 Excel"图标按钮，直接弹出上传对话框，上传完成后可立即选择该数据集进行提问。
新员工提示：上传前请确认你的账号角色有"数据上传"权限。若"上传数据集"按钮显示为灰色，请联系门店管理员开通权限。

§3.2 主界面 layout

上传页面由三个主要区块组成：

区块位置功能说明
拖拽上传区页面中央大区域支持拖拽文件或点击"选择文件"按钮；显示支持格式提示（.xlsx/.xls/.csv，最大 300MB）
字段映射区上传后展开，位于上传区下方展示系统自动识别的字段列表及识别类型（文本/数字/日期/门店/金额）；可点击下拉手动调整每个字段的类型
数据预览区字段映射区下方展示前 10 行原始数据，供核查字段识别是否正确；确认无误后点击"确认上传"完成导入

§3.3 常用操作步骤

完整上传流程共 7 步：

  1. 准备 Excel 文件：确保第一行是列标题，列名使用中文或英文（建议中文，识别率更高）；数字列不含合并单元格或公式。
  2. 进入"数据集管理"页面，点击右上角"上传数据集"按钮。
  3. 拖拽文件到上传区，或点击"选择文件"在文件浏览器中选择目标文件（支持 .xlsx/.xls/.csv，最大 300MB）。
  4. 等待解析（通常 2–10 秒），进度条完成后系统自动跳转到字段映射区。
  5. 检查字段映射：重点确认日期列、金额列、门店列的识别类型是否正确；若系统将"营业额"识别为"文本"则需手动改为"金额"。
  6. 手动调整（如需）：点击字段名旁的类型下拉框，选择正确类型后保存。
  7. 点击"确认上传"，等待完成提示后即可进入 AI Query，在数据集选择器中选择刚上传的文件开始提问。
示例数据下载：可下载 demo_restaurant_sales.csv 体验完整上传流程。包含 3 家门店、10 天、30 行脱敏化销售数据，字段含日期/门店/菜品/营收/成本等。

§3.4 常见错误处理

错误提示原因解决方法
"文件格式不支持"文件扩展名不在白名单内（如 .xls 老格式在部分环境下不支持）在 Excel 中另存为 .xlsx 格式后重新上传
"编码乱码（中文显示为问号）"CSV 文件使用 GBK/GB2312 编码而非 UTF-8用记事本或 Excel 重新保存，选择"UTF-8 编码"；Mac 用户注意去掉 BOM

"数据预览缺失（行数为 0）"文件前几行是说明性文字或有隐藏行，第一行不是真正表头删除说明行，确保第一行是列标题行，再重传
"上传超时"文件过大（通常 >50MB 时解析时间较长）按月份拆分为多个文件，每次上传一个月的数据

§3.5 关键指标速查

上传完成后，数据集详情页会展示以下元信息，是判断数据质量的核心指标：

行数（样本量）：数据集总记录数。<100 行的数据集 AI 趋势分析可靠性较低，建议使用至少覆盖 2 周的数据。
字段数/列数：可分析维度数量。推荐至少包含"日期 + 门店 + 金额"3 个核心字段，字段越丰富 AI 分析维度越多。
日期范围：数据覆盖时间段。AI 对超过 3 个月的趋势分析更准确；单日数据只能做结构分析，无法做趋势。
识别字段类型：系统识别的字段类型（日期/金额/门店/文本）。类型识别错误会导致聚合计算错误（如将金额列当文本则无法求和）。
数据完整度：各字段缺失值比例。超过 20% 缺失的字段建议清洗后再上传；关键字段（如门店名、日期）不建议有缺失。

§3.6 业务判断框架

遇到字段误识别时，按以下路径判断和处理：

常见误识别场景

误识别情况根因处理方法
金额列被识别为"文本"列中含"¥"符号、千分位逗号（1,234.56）或括号表示负数在 Excel 中将该列格式改为"数值"，删除特殊字符后重传

Pivot 表（多级表头）处理

系统对 pivot 表支持有限，建议上传前展平：

  1. 在 Excel 中全选数据（Ctrl+A）→ 复制（Ctrl+C）
  2. 新建 Sheet → 右键"选择性粘贴"→ 选"值"（去除公式和格式）
  3. 确认第一行是列标题（单行，无合并）→ 另存为新文件 → 上传
Pivot 格式的收入管理报表（多级表头、分段标题行）上传后 AI 可能无法正确识别门店和时间段，建议展平后再上传以获得最佳分析效果。

§3.7 跨章节联动

  • §1 AI Query：上传完成后立即进入 AI Query，在数据集选择器中选择刚上传的文件提问，是最直接的联动路径。
  • §2 财务 PBI 看板：看板数据来自系统数据库（Java 后端的业务数据），而非上传的 Excel 文件，两者独立互不影响。
  • §13 多门店对比：上传包含多门店数据的 Excel（含门店名列）后，可在 AI Query 直接进行门店对比分析，无需额外配置。
  • §11 菜品/配方管理：上传含菜品名称和成本字段的 Excel 后，可在 AI Query 分析单品成本率，作为配方成本管理的补充数据来源。

§3.8 常见决策场景

场景 A：历史数据迁移（上传过去一年的 POS 数据）

目标：将线下 POS 系统的历史销售数据导入系统，用于趋势分析和同比对比。

  1. 按月份拆分 Excel（每月一个文件），避免单文件过大超时。
  2. 统一各月份的列名（确保"日期"列名在每个文件中一致）。
  3. 依次上传每月文件 → 在 AI Query 选择对应月份文件提问，或合并后上传做全年分析。
  4. 在 AI Query 追问："对比 2026 年 1 月和 2026 年 4 月的营业额变化趋势"。

场景 B：多门店合并分析（不同门店 Excel 格式不同）

目标：将来自不同门店、格式略有差异的 Excel 合并为一份数据集进行对比分析。

  1. 打开各门店 Excel，用"查找替换"（Ctrl+H）统一字段名（如将"店名"统一改为"门店名称"）。
  2. 将各门店数据粘贴到同一 Sheet，确保列顺序一致、第一行为共用表头。
  3. 上传合并文件 → 在 AI Query 提问："各门店本月营业额排名如何？"

场景 C：POS 系统导出的 Pivot 格式（多级表头）

目标：将 POS 导出的交叉透视表展平为一维表后上传。

  1. 用 Excel 打开 POS 导出文件 → 全选 → 复制 → 新 Sheet → 选择性粘贴（仅值）。
  2. 删除合并单元格行和小计行（选中 → 右键删除行）。
  3. 确认第一行是列标题（单行，无嵌套） → 另存为 .xlsx → 上传。

FAQ

Q：上传的 Excel 数据会永久保存吗？

A：默认保留，可在"数据集管理"页面手动删除。建议只保留有效时间范围内的数据集，过时数据集会干扰 AI Query 的数据集自动选择（系统倾向推荐最近上传的数据集）。

Q：支持多个 Sheet 的 Excel 吗？

A：目前只读取第一个 Sheet（Sheet1）。如有多 Sheet 数据，请先在 Excel 中将所有数据合并到 Sheet1，或分别上传为多个数据集。

Q：上传后 AI 说"未找到对应数据"怎么办？

A：检查以下两点：①AI Query 顶部工具栏的数据集选择器是否已选中刚上传的文件（名称应与文件名一致）；②提问中的字段名是否与数据集列名一致（如数据集列名是"营业额"，提问中说"收入"可能无法匹配，可改为"营业额"）。

Q：每次上传会覆盖旧数据吗？

A：不会。每次上传创建新的独立数据集版本，旧版本完整保留。可在"数据集管理"页面查看所有历史版本并按需删除。

§4 登录 + 工厂/门店切换

白垩纪 SaaS 通过账号密码登录，支持多工厂/多门店切换。不同角色权限不同：老板级账号可查看旗下所有门店数据，店长账号仅限本店。首次使用需由管理员创建账号并分配角色，登录后可在顶部下拉切换当前工作门店。

入门 / 怎么用

  1. 浏览器打开系统 URL（由管理员提供），进入登录页面。
  2. 输入管理员分配的账号（通常是手机号）和初始密码，点击"登录"。
  3. 首次登录系统会提示修改密码，完成后进入 Dashboard 首页。
  4. 若账号绑定多个门店，页面顶部导航栏会显示当前门店名称下拉菜单，点击即可切换到其他门店。
  5. 确认右上角或顶部状态栏显示正确的门店名称，确保操作的是目标门店数据。

常见错误: "密码错误"提示 → 联系管理员在设置页面重置密码，系统无自助找回功能；"无权限访问该门店"提示 → 确认管理员已为账号分配对应门店角色，未分配的门店不会出现在切换列表中。

管理 / 怎么解读

  • 在线用户数: 反映系统当前活跃使用人数，管理员可在设置 → 用户管理中查看各账号最后登录时间。
  • 角色分布: 每个账号对应唯一角色（老板 / 店长 / 财务 / 前台），角色决定可见菜单和可操作数据范围。
  • 门店切换记录: 系统记录账号切换门店的操作，审计日志可追溯跨门店操作。

判断场景: 新员工入职时需由管理员在§7设置中创建账号并分配角色，新账号即刻生效无需重启系统；员工离职后管理员应当日在设置中停用账号，避免数据泄露风险。

FAQ

Q: 忘记密码怎么办？

A: 系统当前无自助找回功能。请联系门店管理员或老板级账号在"系统设置 → 用户管理"中重置你的密码，重置后用新密码登录并立即修改为自己的密码。

Q: 同一账号可以在多台设备上同时登录吗？

A: 支持多设备登录，但同一账号在不同设备同时活跃时，后登录的设备会使前一设备的 Token 失效（互踢机制）。建议每台设备使用专属账号以避免相互干扰。

Q: 切换门店后数据会混用吗？

A: 不会。系统严格按照当前选中门店隔离数据，切换门店后所有报表、AI Query 分析均基于新门店数据，操作记录也归属新门店。

§5 Dashboard 首页

登录后默认进入 Dashboard 首页，集中展示门店当日实时关键指标：今日营收、客流量、翻台率和待处理事项。一屏掌握门店运营状态，支持点击卡片下钻到对应功能模块，是店长和老板每日开工前必看页面。

入门 / 怎么用

  1. 完成登录后系统自动跳转到 Dashboard 首页，也可随时点击左侧导航栏顶部的"首页"图标返回。
  2. 查看顶部"今日营收"卡片，数字显示从今日 0 点到当前时刻的累计营业额，括号内展示与昨日同期对比百分比。
  3. 查看"客流量"和"翻台率"卡片，了解今日到店人数和餐桌使用效率。
  4. 查看右侧或底部"待处理"提醒区域，红色数字表示需要当日处理的事项（如待审批单据、设备告警）。
  5. 点击任意指标卡片可下钻：点击"今日营收"进入财务 PBI 详情，点击"待处理告警"进入告警列表，点击"快捷分析"按钮直接跳转 AI Query 并预填问题。

常见错误: "今日营收显示 0" → 确认当日 POS 或收银数据是否已同步，若刚开店可等待 15 分钟后数据刷新；"数据显示昨日" → 检查浏览器是否有缓存，按 F5 或 Ctrl+Shift+R 强制刷新页面。

管理 / 怎么解读

  • 今日营收 (环比): 与昨日同期对比，环比下跌超过 10% 需关注，建议立即进入§1 AI Query 分析原因（天气、促销、竞争等）。
  • 翻台率: 今日翻台次数与昨日/同期基准对比，低于基准值提示服务效率或客单价存在问题。
  • 待处理告警数: 超过 5 条需在当日内逐一处理，长期积压的告警反映系统或业务存在持续性问题。

判断场景: 营收卡片环比下跌超 10% 时立即点击下钻进入§1 AI Query 分析"今日营收下跌原因"；待处理告警超过 5 条时优先处理红色高优先级告警，再处理黄色普通告警，绿色信息类可批量关闭。

§6 报表中心 + 数据导出

报表中心提供预设格式的标准化报表（日报/周报/月报/自定义区间），支持 Excel、CSV 和 PDF 三种格式导出。适用于定期财务汇报、总部数据归档、月度对账等场景，是将系统数据交付外部的主要通道。

入门 / 怎么用

  1. 点击左侧导航栏"报表中心"进入报表列表页，可见营收、成本、库存、人效等多类预设报表。
  2. 选择所需报表类型（如"月度营收报表"），在右侧配置面板设置时间范围（开始日期/结束日期）和目标门店。
  3. 点击"生成报表"按钮，系统后台计算后在页面内渲染预览（通常需 5-30 秒，数据量大时较慢）。
  4. 在预览区核对数据无误后，点击右上角"下载"按钮，在弹出菜单中选择导出格式（Excel / CSV / PDF）。
  5. 文件下载到本地后，可直接发送给财务或总部存档，或上传到§3 Excel 上传做进一步 AI 分析。

常见错误: "报表生成超时"提示 → 时间范围过长（超过 3 个月）时运算量大，建议拆分为月度报表分批导出；"导出数据与 PBI 看板数字不一致" → 检查筛选条件是否相同，特别是门店范围和时间区间是否完全对应。

管理 / 怎么解读

  • 本月营收 vs 上月: 标准月度报表自带同环比列，红色为下降，绿色为上升，差异超过 15% 建议用 AI Query 追因。
  • 成本占比: 食材成本占营收的比例，餐饮行业健康区间通常为 25%-35%，超出范围需检查采购价格或损耗。
  • 库存周转率: 库存报表中的关键指标，周转率低意味着食材积压风险，需关注临期品处理。

判断场景: 每月月初导出上月财务报表发送给财务存档，使用 PDF 格式便于留档签批；总部需要多门店汇总数据时，先在顶部切换"所有门店"模式再生成报表，导出 Excel 供总部系统导入。

§7 设置 (用户/角色/通知)

系统设置模块集中管理用户账号、角色权限和通知推送配置，仅管理员和老板级账号可访问。涵盖新增/停用账号、角色分配、企微/短信告警推送设置和系统级参数调整，是保障系统安全和通知及时到达的核心后台入口。

入门 / 怎么用

  1. 点击页面右上角头像或下拉箭头，在菜单中选择"系统设置"进入设置主页。
  2. 在"用户管理"标签页点击"新增用户"，填写姓名、手机号（作为登录账号）、初始密码和绑定门店，选择角色后保存。
  3. 在"角色管理"标签页查看各角色（老板/店长/财务/前台）的权限列表，确认新账号角色匹配实际岗位职责。
  4. 在"通知设置"标签页配置告警推送渠道：填入企微机器人 Webhook 地址或短信手机号，选择推送事件类型（库存预警/设备告警/审批通知等）。
  5. 点击"测试发送"验证通知渠道是否畅通，收到测试消息后点"保存"使配置生效。

常见错误: "新增用户保存失败"提示手机号已存在 → 先在用户列表搜索该手机号，若账号已存在则直接编辑分配门店和角色，不需重新创建；"企微通知收不到" → 检查 Webhook 地址是否已过期（企微机器人 Webhook 有效期为一年），若过期需在企微后台重新生成并更新到设置中。

管理 / 怎么解读

  • 活跃用户数: 近 30 天有登录记录的账号数量，与实际在职员工数对比，差距大则提示存在闲置账号需清理。
  • 角色分布: 各角色账号数量分布，老板角色建议不超过 3 人，前台角色账号建议与排班人数匹配。

判断场景: 建议每季度审查用户列表一次，将"最后登录"超过 90 天的账号停用，保留但不删除（历史操作记录关联账号 ID）；发现异常登录（如凌晨操作或非正常 IP）时立即在设置中停用该账号并修改密码。

§8 移动端 RN app 使用

白垩纪移动端 App（基于 React Native，支持 iOS 和 Android）提供精简版 Dashboard 查看、消息通知和简单审批功能。适合店长和老板在移动场景下随时查看门店数据和处理紧急审批，复杂数据录入和深度分析仍建议在 PC 端进行。

入门 / 怎么用

  1. 通过管理员提供的下载链接或扫描二维码安装 App（iOS 通过 TestFlight / App Store，Android 通过直接安装 APK 或应用商店）。
  2. 打开 App，在登录页面输入与 PC 端相同的账号（手机号）和密码，点击"登录"。
  3. 登录后进入移动端 Dashboard，查看当日营收摘要、客流和翻台率等核心卡片数据。
  4. 点击底部导航栏"消息"图标进入消息中心，查看待处理通知（库存预警、审批请求、告警提醒等）。
  5. 针对审批类通知（如员工请假、报工审批），可在 App 内直接点击"通过"或"驳回"完成审批，无需切换到 PC 端。

常见错误: "App 白屏/无法加载" → 在手机设置中清除 App 缓存后重启；若问题持续，卸载重装以获取最新版本；"登录失败 / 服务器连接超时" → 确认手机网络可正常访问互联网，企业内网用户需确认 VPN 或代理设置不拦截 App 流量。

管理 / 怎么解读

  • App 日活用户数: 在§7 设置的用户管理中可查看各账号的移动端最后登录时间，日活率低提示通知推送或 App 安装可能存在问题。
  • 推送通知响应率: 告警/审批通知发出到实际处理的时间差，响应慢（超过 2 小时）说明移动端通知推送需要排查权限设置。

判断场景: 店长下班后用 App 查看当日营收是否达标，若距关店 1 小时还有差距可安排推促活动；老板出差期间用 App 处理紧急审批事项，避免因不在场导致流程卡顿，非紧急的复杂决策等回到 PC 端后再处理。
