3 个不能覆盖的例子 — 为什么

❌ 不能新增状态
Java enum SalesOrderStatus 有 9 个值。

Canvas 能: 禁用 FINANCE_REJECTED 状态
Canvas 不能: 新增 "QUALITY_HOLD" 状态

原因: enum 是编译期类型, 运行时不能加值。新增状态需要改 Java + 部署。

解决: 把 enum 改为 String + DB 查找表 (额外重构工作)
❌ 不能改 Service 内部序列
createSalesOrder() 方法:
1. 验证客户 → 2. 生成编号 → 3. 创建实体 → 4. 设字段 → 5. 保存 → 6. 处理行项目

Canvas 能: 改步骤4的默认值, 改步骤1的校验规则
Canvas 不能: 跳过步骤3, 在步骤5前插入新步骤

原因: 方法内部逻辑是 Java 代码, 不是可编排的步骤

解决: 不需要 — 这是原子操作, 不该被拆分
❌ 不能改 SmartBI 分析逻辑
FinanceAnalysisService 有 33 个 BigDecimal 常量用于基准对比。

Canvas 能: 改阈值 (如 "毛利率警戒线 30%")
Canvas 不能: 改分析维度 / 改计算公式结构

原因: 分析逻辑涉及多表 JOIN + 聚合 + 同比环比, 无法用简单公式表达

解决: SmartBI 有自己的 knowledge base + LLM 管道, 用行业知识库配置

最终结论

V3 方案覆盖率: ~70% (2,150/3,050)
对于"不同工厂有不同配置"这个目标, 70% 覆盖率已经足够:
• 所有校验规则 ✅ (工厂A不校验重复产品, 工厂B校验)
• 所有触发链 ✅ (工厂A自动排产, 工厂B手动)
• 所有工具/技能 ✅ (工厂A有AI排程, 工厂B没有)
• 所有定时任务 ✅ (工厂A凌晨2点, 工厂B早上8点)
• 所有字段/流程/权限 ✅ (Phase 1 已验证)

剩下 30% 中:
• 16% 可以通过逐个 service 重构解决 (Phase 3+ 持续迁移)
• 14% 是不应该配置化的 (系统安全/代码质量)
