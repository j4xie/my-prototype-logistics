## 1. 目标与边界

### 1.1 目标

用户问任何业务问题, 系统**自动**:

1. 拆解问题 (LLM-augmented planner)
2. 决定从哪些 fact/agg 表取数据
3. 通过 entity_id auto-join 多表
4. 调用 C 的 ProvenanceValue 算综合 confidence
5. 返回结果 + Trust Indicator

**前后对比**:

```
v1 (现状): 模板编写者写 SQL
@template
def dish_sales_top_n(schema):
    return f"SELECT product, SUM(amount) FROM agg_product 
            WHERE factory_id='{factory_id}' GROUP BY product ORDER BY 2 DESC LIMIT 20"

v2 (D 后): 模板编写者声明意图, 引擎生成 SQL
@template
class DishSalesTopN(Template):
    requires = ["product_name", "revenue"]
    grain = "product"
    aggregate = "sum(revenue)"
    top_n = 20
    # 引擎自动选 agg_product_period (有此 field), 写 SQL, 算 confidence
```

### 1.2 在 Data Fabric 体系中的角色

```
B 完成 (entity_id 稳定)
       ↓
C 完成 (field_provenance + confidence)
       ↓
[D] Query Planner (LLM-augmented)            ← 本 spec
       ↓
[D] Logical → Physical SQL Generator         ← 本 spec
       ↓
[D] Auto-join via entity_id                  ← 本 spec
       ↓
[D] Confidence Cascade (从 C 取 + 多源融合)   ← 本 spec
       ↓
[D] Template DSL + 高频模板迁移              ← 本 spec
       ↓
A 的 capability gate 控制可见性
```

### 1.3 in-scope vs out-of-scope

**In Scope**:
- ✅ Query Planner (LLM-augmented, 默认 qwen-plus, qwen-max 仅复杂 case)
- ✅ Logical Query Plan 数据结构 + 校验
- ✅ Logical → Physical SQL Generator (含 auto-join, time-axis 对齐, agg 表优先回退 fact)
- ✅ Confidence Cascade (从 C 的 ProvenanceValue 综合)
- ✅ Template DSL (现有 44 模板高频前 20 迁移)
- ✅ NL 问答 / smartRecommendChart 入口集成
- ✅ Cache 层 (复用现有 NarrativeCache + 加 query_plan_cache)

**Out of Scope**:
- ❌ Cross-tenant query (后期)
- ❌ Streaming / realtime (现状 batch 足够)
- ❌ Query optimizer (PG planner 自带, D 不重做)
- ❌ 全部 44 模板迁移 (高频 20 个先, 低频后期)
- ❌ Federated query 跨 DB (只在 PG 内 join)

## 2. Query Planner 架构

### 2.1 输入 / 输出

```python
# backend/python/smartbi/federated/types.py
from dataclasses import dataclass
from typing import List, Optional, Literal

@dataclass(frozen=True)
class QueryRequest:
    """用户输入."""
    factory_id: str
    question: str                         # 自然语言问题
    date_range: Optional[tuple[date, date]]
    template_hint: Optional[str] = None   # 客户选了某模板时跳过 LLM

@dataclass(frozen=True)
class LogicalQueryPlan:
    """planner 输出: 逻辑查询计划 (待编译为 SQL)."""
    measures: List["MeasureSpec"]         # 度量 (sum revenue / count bills)
    dimensions: List["DimSpec"]           # 维度 (product / store / month)
    filters: List["FilterSpec"]           # 过滤 (date, store_id, etc.)
    time_grain: Optional[Literal["day", "week", "month", "quarter", "year"]]
    sort: Optional["SortSpec"] = None
    limit: Optional[int] = None
    confidence_required: float = 0.0      # 客户要求最低 confidence
    
@dataclass(frozen=True)
class MeasureSpec:
    canonical_field: str                  # 'revenue' / 'qty_sold' / 'rating'
    aggregation: Literal["sum", "avg", "count", "max", "min", "count_distinct"]
    alias: str                            # 输出列名
    
@dataclass(frozen=True)
class DimSpec:
    canonical_field: str                  # 'product_name' / 'store_name'
    entity_type: Optional[str] = None     # auto-join 时用 (product / store / staff)
    
@dataclass(frozen=True)
class FilterSpec:
    canonical_field: str
    op: Literal["=", "!=", ">", "<", ">=", "<=", "IN", "BETWEEN", "LIKE"]
    value: Any
    
@dataclass(frozen=True)
class QueryResult:
    """最终输出."""
    columns: List[str]
    rows: List[dict]
    confidence: float                     # 综合 confidence (来自 C provenance)
    sources: List[str]                    # 数据来源 (用于 Trust UI)
    sql_executed: str                     # 透明可审计
    elapsed_ms: int
    plan: LogicalQueryPlan                # 给前端展示用
```

### 2.2 Planner 决策流程

```
QueryRequest
    ↓
[1] Template Cache 命中? (复用 Apr 25 5/5 hit pattern)
    ├─ Yes (80% 估计) → 直接返结果, 0 LLM call
    └─ No (20%)
        ↓
[2] template_hint 提供? 
    ├─ Yes → 直接用模板生成 plan, 0 LLM call
    └─ No
        ↓
[3] Rule-based intent classifier (现有 BERT 分类器)
    ├─ 高置信度 → 模板匹配
    └─ 低置信度
        ↓
[4] LLM Query Planner (qwen-plus 默认, qwen-max 仅 cross-5+ tables)
    ├─ 输入: 问题 + factory available_fields (来自 A) + template registry
    └─ 输出: LogicalQueryPlan
        ↓
[5] Plan validation (字段都在 capability 里? entity_type 都能 join?)
    ├─ Pass → 编译 SQL
    └─ Fail → 返友好错误 + 建议
```

### 2.3 LLM Planner Prompt 设计

```python
# backend/python/smartbi/federated/llm_planner.py
PLANNER_SYSTEM_PROMPT = """
你是数据查询计划专家. 把用户问题翻译成结构化查询计划.

可用字段 (factory 上传过的): {available_fields}
可用模板 (高频): {template_registry}
当前日期: {today}

输出格式 (JSON):
{
  "measures": [{"canonical_field": "...", "aggregation": "sum|avg|count|...", "alias": "..."}],
  "dimensions": [{"canonical_field": "...", "entity_type": "product|store|staff"}],
  "filters": [{"canonical_field": "...", "op": "=|>|...", "value": "..."}],
  "time_grain": "day|week|month|year|null",
  "sort": {"by": "...", "direction": "asc|desc"},
  "limit": <int 或 null>
}

注意:
- canonical_field 必须在 available_fields 里, 否则 plan 失败
- entity_type 用于 auto-join, 加上才能跨表
- time_grain 仅当 dimensions 含 'date' 时有效
- 不能用的字段或操作请明确返 {"error": "..."}
"""

async def llm_plan(request: QueryRequest, capability: Set[str], pool) -> LogicalQueryPlan:
    """调 LLM 生成 plan. 复用 Week 5 narrative_cache 缓存."""
    cache_key = sha256(f"{request.factory_id}|{request.question}|{request.date_range}".encode()).hexdigest()
    
    # 1. 缓存命中
    cached_plan = await NarrativeCache(pool).get(cache_key)
    if cached_plan:
        return LogicalQueryPlan(**cached_plan)
    
    # 2. 调 LLM (qwen-plus 默认)
    settings = get_settings()
    model = "qwen-plus"  # 仅 cross-5+ tables 才升 qwen-max (D §2.5)
    
    template_registry = await _load_template_registry(pool)
    
    response = await llm_client.chat(
        system=PLANNER_SYSTEM_PROMPT.format(
            available_fields=sorted(capability),
            template_registry=template_registry,
            today=date.today(),
        ),
        user=request.question,
        model=model,
        max_tokens=800,
    )
    
    plan_json = json.loads(response)
    if "error" in plan_json:
        raise PlannerError(plan_json["error"])
    
    plan = LogicalQueryPlan(**plan_json)
    
    # 3. validate
    _validate_plan(plan, capability)
    
    # 4. cache 24h
    await NarrativeCache(pool).set(cache_key, asdict(plan), ttl_hours=24)
    
    # 5. 计入 budget (D feature_breakdown 加 'query_planner')
    await budget_tracker.consume_with_feature(
        request.factory_id, response.tokens, "query_planner"
    )
    
    return plan
```

### 2.4 Plan validation

```python
def _validate_plan(plan: LogicalQueryPlan, capability: Set[str]):
    """plan 字段必须在 capability 里 (来自 A v1.4 contract)."""
    used_fields = set()
    for m in plan.measures:
        used_fields.add(m.canonical_field)
    for d in plan.dimensions:
        used_fields.add(d.canonical_field)
    for f in plan.filters:
        used_fields.add(f.canonical_field)
    
    missing = used_fields - capability
    if missing:
        raise PlannerError(
            f"Plan 引用 capability 未提供的字段: {missing}. "
            f"客户上传含这些字段的数据可解锁此查询."
        )
    
    # entity_type 必须在已知 dim 表
    KNOWN_ENTITIES = {"product", "store", "staff", "ingredient", "subject"}
    for d in plan.dimensions:
        if d.entity_type and d.entity_type not in KNOWN_ENTITIES:
            raise PlannerError(f"未知 entity_type: {d.entity_type}")
```

### 2.5 qwen-plus 默认, qwen-max 仅复杂 case

```python
def _select_planner_model(question: str, capability: Set[str]) -> str:
    """复杂查询用 qwen-max, 否则 qwen-plus.
    
    复杂判定:
    - 字段引用 ≥ 5 个
    - 含 cross-fact join 词 (含成本/毛利/评分 综合的)
    - 含时间序列 + 同环比 双轴
    """
    complex_keywords = ["毛利", "评分", "同比", "环比", "对比", "占比"]
    if any(kw in question for kw in complex_keywords):
        return "qwen-max"
    if len(question) > 100:  # 长问题倾向复杂
        return "qwen-max"
    return "qwen-plus"
```

成本影响 (与 roadmap §9.2 v1.2 对齐):
- 80% 走缓存 0¥
- 16% 走 qwen-plus ~¥0.04/call
- 4% 走 qwen-max ~¥0.30/call

## 3. Logical → Physical SQL Generator

### 3.1 表选择策略 (粗 agg 优先, 缺时回退 fact)

```python
# backend/python/smartbi/federated/sql_generator.py
TABLE_PRIORITY = {
    # field → [(table, grain, where_clause)]  按粒度从粗到细排序
    "revenue": [
        ("agg_product_period", "month", ""),       # 最粗 (product × period)
        ("agg_daily", "day", ""),                  # 中等 (date)
        ("fact_pos_item", "row", "WHERE qty > 0"), # 最细 (per item)
    ],
    "qty_sold": [
        ("agg_product_period", "month", ""),
        ("fact_pos_item", "row", ""),
    ],
    "rating": [
        ("dim_review_summary", "month", ""),
        ("fact_review_event", "row", ""),
    ],
    "stock_qty": [
        ("fact_inventory_snapshot", "day", ""),
    ],
    "voucher_amount": [
        ("fact_finance_voucher", "day", ""),
    ],
}

def choose_source_table(plan: LogicalQueryPlan) -> str:
    """根据 measures + grain 选最优表.
    
    规则:
    - 优先用粒度最粗的 agg 表 (省扫描)
    - 如果 grain 比 agg 表的 grain 粗, 也行 (PG GROUP BY 升级)
    - 如果 grain 比 agg 表细 (e.g. 要 day 但 agg 是 month), 必须回退 fact
    """
    primary_measure = plan.measures[0]
    candidates = TABLE_PRIORITY.get(primary_measure.canonical_field, [])
    if not candidates:
        raise PlannerError(f"无 source table for {primary_measure.canonical_field}")
    
    requested_grain = plan.time_grain or "month"
    GRAIN_ORDER = {"row": 0, "day": 1, "week": 2, "month": 3, "quarter": 4, "year": 5}
    
    for table, table_grain, where in candidates:
        if GRAIN_ORDER[table_grain] <= GRAIN_ORDER[requested_grain]:
            return table  # 此表 grain 比 requested 细, GROUP BY 升级即可
    
    return candidates[-1][0]  # 用最细的 fact
```

### 3.2 Auto-join via entity_id

```python
def auto_join(primary_table: str, dimensions: List[DimSpec]) -> str:
    """根据 dimensions 中的 entity_type 加 LEFT JOIN.
    
    Returns SQL fragment: ' LEFT JOIN dim_product p ON p.product_id = primary.product_id ...'
    """
    joins = []
    aliases = {}
    
    for d in dimensions:
        if not d.entity_type:
            continue
        dim_table = f"dim_{d.entity_type}"
        alias = d.entity_type[0]  # 'p' for product, 's' for store
        aliases[d.entity_type] = alias
        joins.append(
            f" LEFT JOIN {dim_table} {alias} "
            f"ON {alias}.{d.entity_type}_id = primary.{d.entity_type}_id"
        )
    
    return "".join(joins), aliases
```

### 3.3 Time-axis 自动对齐

```python
def time_grain_clause(grain: str, date_field: str = "date") -> str:
    """生成 GROUP BY 时间表达式."""
    if grain == "day":
        return date_field
    elif grain == "week":
        return f"date_trunc('week', {date_field})"
    elif grain == "month":
        return f"date_trunc('month', {date_field})"
    elif grain == "quarter":
        return f"date_trunc('quarter', {date_field})"
    elif grain == "year":
        return f"date_trunc('year', {date_field})"
    raise ValueError(f"Unknown grain: {grain}")
```

### 3.4 完整 SQL 生成

```python
def generate_sql(plan: LogicalQueryPlan, factory_id: str) -> tuple[str, list]:
    """生成 SQL + 参数列表 (asyncpg 风格 $1, $2, ...).
    
    Returns: (sql_string, params)
    """
    # 1. 选表
    primary_table = choose_source_table(plan)
    
    # 2. SELECT
    select_parts = []
    for d in plan.dimensions:
        if d.entity_type:
            alias = d.entity_type[0]
            select_parts.append(f"{alias}.name AS {d.canonical_field}")
        elif d.canonical_field == "date":
            grain_expr = time_grain_clause(plan.time_grain or "day", "primary.date")
            select_parts.append(f"{grain_expr} AS time_period")
        else:
            select_parts.append(f"primary.{d.canonical_field}")
    
    for m in plan.measures:
        select_parts.append(
            f"{m.aggregation.upper()}(primary.{m.canonical_field}) AS {m.alias}"
        )
    
    # 3. JOIN
    joins, aliases = auto_join(primary_table, plan.dimensions)
    
    # 4. WHERE (filters + factory_id RLS auto-applied via app.factory_id)
    params = []
    where_parts = ["primary.factory_id = current_setting('app.factory_id')"]
    for f in plan.filters:
        params.append(f.value)
        where_parts.append(f"primary.{f.canonical_field} {f.op} ${len(params)}")
    
    if plan.date_range:
        params.extend(plan.date_range)
        where_parts.append(f"primary.date BETWEEN ${len(params)-1} AND ${len(params)}")
    
    # 5. GROUP BY
    group_by = ", ".join(
        s.split(" AS ")[0] for s in select_parts if "(" not in s.split(" AS ")[0]
    )
    
    # 6. ORDER BY
    order_clause = ""
    if plan.sort:
        order_clause = f" ORDER BY {plan.sort.by} {plan.sort.direction.upper()}"
    
    # 7. LIMIT
    limit_clause = f" LIMIT {plan.limit}" if plan.limit else ""
    
    sql = f"""
        SELECT {', '.join(select_parts)}
          FROM {primary_table} primary
          {''.join(joins)}
         WHERE {' AND '.join(where_parts)}
         GROUP BY {group_by}
         {order_clause}
         {limit_clause}
    """
    return sql, params
```

## 4. Confidence Cascade

### 4.1 多源 confidence 综合

```python
async def compute_query_confidence(
    plan: LogicalQueryPlan, factory_id: str, conn
) -> tuple[float, List[str]]:
    """Query 的 confidence = 所有依赖字段 confidence 的最弱一环.
    
    Returns: (confidence, sources)
    """
    field_confidences = []
    sources = set()
    
    for m in plan.measures + [d for d in plan.dimensions if not d.entity_type]:
        # 抽样取 10 个 entity 算平均 confidence (太多算太慢)
        sample = await conn.fetch("""
            SELECT confidence, source_type FROM field_provenance
             WHERE factory_id = $1 AND field_name = $2
               AND superseded_by_id IS NULL
             ORDER BY created_at DESC LIMIT 10
        """, factory_id, m.canonical_field)
        
        if sample:
            avg_conf = sum(float(r["confidence"]) for r in sample) / len(sample)
            field_confidences.append(avg_conf)
            sources.update(r["source_type"] for r in sample)
        else:
            # 字段没有 provenance 记录 (例如直接来自 fact 表的字段)
            field_confidences.append(0.95)  # fact 表数据假定 95%
    
    # 综合: 木桶理论, 取最低
    overall = min(field_confidences) if field_confidences else 0.0
    return overall, sorted(sources)
```

### 4.2 输出到 Trust UI

```python
async def execute_query(plan: LogicalQueryPlan, factory_id: str, pool) -> QueryResult:
    sql, params = generate_sql(plan, factory_id)
    
    async with pool.acquire() as conn:
        async with conn.transaction():
            await conn.execute("SELECT set_config('app.factory_id', $1, true)", factory_id)
            
            t0 = time.time()
            rows = await conn.fetch(sql, *params)
            elapsed_ms = int((time.time() - t0) * 1000)
            
            # confidence cascade
            confidence, sources = await compute_query_confidence(plan, factory_id, conn)
    
    return QueryResult(
        columns=[c.canonical_field if hasattr(c, 'canonical_field') else c.alias 
                 for c in plan.dimensions + plan.measures],
        rows=[dict(r) for r in rows],
        confidence=confidence,
        sources=sources,
        sql_executed=sql,
        elapsed_ms=elapsed_ms,
        plan=plan,
    )
```

## 10. 风险与未决问题

### 10.1 风险

| # | 风险 | 缓解 |
|---|---|---|
| D1 | LLM Planner 生成无效 plan (字段名错 / 操作不支持) | _validate_plan + 返友好错误 + 让用户改问法 |
| D2 | LLM 成本超 §9.2 估算 (¥9,631/月) | feature_breakdown cap 防失控 + 缓存命中率监控 |
| D3 | Auto-join 性能差 (多表 LEFT JOIN 慢) | EXPLAIN ANALYZE 验证 + 索引检查 + agg 表优先 |
| D4 | DSL 表达力不够覆盖 44 模板 | 高频 20 个先, 低频留 hardcoded |
| D5 | confidence cascade 取最低过严 | 调权重 (e.g. 主 measure 权重高) 或改加权平均 |
| D6 | C 的 ProvenanceValue API 变更 | D 通过 ProvenanceValue dataclass (C v1.2 §2.1.1) 解耦 |
| D7 | 时间窗 UNKNOWN (来自 B Sheet Merger) | _validate 跳过 PERIOD_UNKNOWN 上传, 提示客户补时间 |

### 10.2 未决问题 (送审用户)

1. **LLM Planner 模型选择策略**: qwen-plus 默认 vs 全部 qwen-max?
2. **DSL 高频迁移范围**: 20 个 vs 44 个全迁?
3. **confidence cascade 算法**: min vs 加权平均 vs 几何平均?
4. **Plan cache TTL**: 24h vs 7d vs 永久 (LRU evict)?
5. **NL 问答失败时**: 返错误 vs 推荐相近模板 vs 让 LLM 重试?
