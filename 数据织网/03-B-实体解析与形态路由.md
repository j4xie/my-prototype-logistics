## 1. 目标与边界

### 1.1 目标

让客户上传**任何形态**的餐饮业务文件 (账单流水 / 商品汇总 / 评论 / 财务 / 库存 / 排班 / 会员) 系统自动:

1. **识别形态** (LLM-driven Shape Detector)
2. **路由到对应 Silver 写入路径** (Shape Router → 4-5 种 writer)
3. **跨文件用 AI 识别同一店/菜/人** (Multi-Agent RAG 渐进策略)
4. **多 sheet 智能时间合并** (Sheet Merger, A v1.4 §11 移交需求)

```
Bronze 层 (raw row_data JSONB)

       ↓
[B] Silver Writer (4-5 种 per shape)      ← 本 spec
       ↓
[B] Multi-Agent Entity Resolution         ← 本 spec
       ↓ stable entity_id
[B] Sheet Merger (merge_status)           ← 本 spec
       ↓
Silver 层 (fact_pos_* / dim_* / 新增 4 张)
```

## 2. Multi-Agent RAG 实体解析

### 2.1 渐进策略 (从 A v1.4 §4.2 继承)

```
阶段 B1 (MVP, 1.5-2 周): baseline 2-agent
  ├── DeterministicAgent (升级 alias_normalizer.py)
  └── EmbeddingAgent (Qwen text-embedding-v3 + 余弦)
       ↓
跑标记数据集 holdout (§4.2.1, B1 末尾)
   - 店名 ≥ 88% / 菜名 ≥ 88% / 人名 ≥ 80% → ✅ ship B1, 跳过 B2
   - 任一 < 88% / < 80% → 进 B2
   - 任一 < 75% → 急停, 重新设计 baseline (e.g., 改 embedding 模型)

阶段 B2 (条件触发, 1-1.5 周): 升级到 5-agent
  ├── DeterministicAgent (B1 已有)
  ├── EmbeddingAgent (B1 已有)
  ├── ContextualAgent (新: 店名+城市+区, 菜名+品类+店 上下文 embedding)
  ├── TransitiveAgent (新: A=B, B=C → A=C 闭包)
  └── LLMArbitrator (新: 仅低置信度上 qwen-plus, 不是 qwen-max)
       ↓
B2 holdout: 店名 ≥ 92% / 菜名 ≥ 92% / 人名 ≥ 85% 才 ship
```

**为什么不一开始就 5 agent**:
1. 工作量翻倍 (3-4 周 → 6-8 周), 不一定值得
2. 单 LLM 在简单 case 浪费钱 (99% 实体匹配应该走便宜 deterministic + embedding)
3. 量化阈值让决策可证伪, 不是 vibes

### 2.2 EntityResolutionOrchestrator 接口 (v1.1 修复 C-1/C-2/S-7)

```python
# backend/python/smartbi/canonical/entity_resolution/orchestrator.py
from dataclasses import dataclass, field
from enum import Enum
from typing import List, Optional, Dict, Any

class EntityType(Enum):
    STORE = "store"
    PRODUCT = "product"
    STAFF = "staff"
    # 后期: BILL, TABLE, INGREDIENT, CUSTOMER

@dataclass
class ResolutionInput:
    """输入: 一个待解析实体名 + 上下文.
    
    v1.1 修复 C-1: 不 frozen, 允许 orchestrator 在 agent 间传递状态.
    """
    raw_name: str
    entity_type: EntityType
    factory_id: str
    context: Dict[str, Any] = field(default_factory=dict)

@dataclass
class OrchestrationContext:
    """v1.1 新增 (修 C-1): 跨 agent 传递的可变状态. 不在 ResolutionInput 内.
    
    Agent 之间共享: top_k 候选 / 已尝试的 entity_id / debug trace
    """
    top_k_candidates: List[Dict] = field(default_factory=list)
    tried_entity_ids: set = field(default_factory=set)
    agent_outputs: Dict[str, "AgentResult"] = field(default_factory=dict)

@dataclass(frozen=True)
class AgentResult:
    matched_entity_id: Optional[int]
    confidence: float
    reasoning: str
    candidates: List[Dict] = field(default_factory=list)  # v1.1 加: agent 提供给后续 agent 的候选

@dataclass(frozen=True)
class ResolutionOutput:
    matched_entity_id: Optional[int]
    confidence: float
    decided_by_agent: str
    reasoning: str
    fallback_chain: List[str]
    is_tentative: bool = False  # v1.1 修 S-7: 标识是否走了二次低阈值通道

class EntityResolutionOrchestrator:
    """协调多个 agent, 按规则聚合."""
    
    def __init__(self, pool, agents: List["BaseAgent"]):
        self._pool = pool
        self._agents = agents
        # v1.1 修 S-7: 二次低阈值兜底, 避免 0.85-0.90 之间也进 admin 队列
        self._tentative_threshold = 0.80
    
    async def resolve(self, input: ResolutionInput) -> ResolutionOutput:
        """按 agent 顺序跑, 第一个 ≥ 高置信度阈值 的胜出.
        
        v1.1 修复 C-1: orchestrator 维护 OrchestrationContext, agent 间共享 top_k.
        v1.1 修复 C-2: 决策后写 entity_resolution_history (供 TransitiveAgent + 审计用).
        v1.1 修复 S-7: 全部 agent < ship 时, 取 max-confidence 若 ≥ 0.80 标 tentative.
        """
        ctx = OrchestrationContext()
        chain = []
        best: Optional[tuple[str, AgentResult]] = None  # 用于 second-pass
        
        for agent in self._agents:
            # 把上一 agent 的 candidates 写入 input.context, agent 可读
            input.context["top_k_candidates"] = ctx.top_k_candidates
            input.context["tried_entity_ids"] = list(ctx.tried_entity_ids)
            
            result = await agent.resolve(input, self._pool)
            chain.append(agent.name)
            ctx.agent_outputs[agent.name] = result
            
            # 把 agent 输出的 candidates 加进 ctx 供下一个 agent
            if result.candidates:
                ctx.top_k_candidates = result.candidates[:5]  # 仅留 top 5
            if result.matched_entity_id is not None:
                ctx.tried_entity_ids.add(result.matched_entity_id)
            
            if result.confidence >= agent.ship_threshold:
                output = ResolutionOutput(
                    matched_entity_id=result.matched_entity_id,
                    confidence=result.confidence,
                    decided_by_agent=agent.name,
                    reasoning=result.reasoning,
                    fallback_chain=chain,
                    is_tentative=False,
                )
                # v1.1 修 C-2: 写 history
                await self._record_history(input, output)
                return output
            
            # 跟踪 best 用于 second-pass
            if best is None or result.confidence > best[1].confidence:
                best = (agent.name, result)
        
        # v1.1 修 S-7: second-pass 0.80 兜底
        if best and best[1].confidence >= self._tentative_threshold:
            output = ResolutionOutput(
                matched_entity_id=best[1].matched_entity_id,
                confidence=best[1].confidence,
                decided_by_agent=best[0],
                reasoning=f"[tentative] {best[1].reasoning}",
                fallback_chain=chain,
                is_tentative=True,
            )
            await self._record_history(input, output)
            # tentative 同时进 admin 队列 (低优先级), 不阻塞业务
            await self._queue_for_admin(input, output, priority="low")
            return output
        
        # 全部低置信度 → 进 admin 队列, 临时返新建
        output = ResolutionOutput(
            matched_entity_id=None,
            confidence=0.0,
            decided_by_agent="admin_queue",
            reasoning="所有 agent 置信度均不足, 进入人工审核",
            fallback_chain=chain,
        )
        await self._queue_for_admin(input, output, priority="high")
        return output
    
    async def _record_history(self, input: ResolutionInput, output: ResolutionOutput) -> None:
        """v1.1 修 C-2: 写 entity_resolution_history 供 TransitiveAgent + 审计."""
        if output.matched_entity_id is None:
            return
        async with self._pool.acquire() as conn:
            await conn.execute("""
                INSERT INTO entity_resolution_history
                  (factory_id, entity_type, a_name, b_name, b_entity_id, sim, decided_by_agent)
                VALUES ($1, $2, $3, $3, $4, $5, $6)
                ON CONFLICT DO NOTHING
            """, input.factory_id, input.entity_type.value,
                normalize(input.raw_name), output.matched_entity_id,
                output.confidence, output.decided_by_agent)
    
    async def _queue_for_admin(
        self, input: ResolutionInput, output: ResolutionOutput, priority: str
    ) -> None:
        """v1.1 新增 (S-2): 写 entity_resolution_admin_queue (§5.4.2 表)."""
        async with self._pool.acquire() as conn:
            await conn.execute("""
                INSERT INTO entity_resolution_admin_queue
                  (factory_id, entity_type, raw_name, candidate_entity_id, confidence, 
                   decided_by_agent, reasoning, priority, status)
                VALUES ($1, $2, $3, $4, $5, $6, $7, $8, 'PENDING')
            """, input.factory_id, input.entity_type.value, input.raw_name,
                output.matched_entity_id, output.confidence,
                output.decided_by_agent, output.reasoning, priority)
```

**关键变化 (v1.1)**:
- `ResolutionInput` 不再 frozen, agent 间可填 context
- 加 `OrchestrationContext` 维护 top_k_candidates / tried_entity_ids
- `AgentResult.candidates` 字段让 EmbeddingAgent 把 top 5 输出, LLMArbitrator 读到
- 决策后 `_record_history` 写表, TransitiveAgent 后续可读
- second-pass 0.80 阈值: agent 全部 < ship 但 best ≥ 0.80 → tentative 走业务路径同时进 admin 队列复审 (双轨)

#### 2.3.1 DeterministicAgent (B1)

**职责**: 简繁/空白/标点归一化 + 完全相等匹配. 99% 简单 case 走这.

```python
# backend/python/smartbi/canonical/entity_resolution/agents/deterministic.py
class DeterministicAgent(BaseAgent):
    name = "deterministic"
    ship_threshold = 0.95
    
    async def resolve(self, input: ResolutionInput, pool) -> AgentResult:
        # 1. 用 alias_normalizer 归一化 (复用现有 smartbi/canonical/alias_normalizer.py)
        normalized = normalize_for_dim(input.raw_name)  # 简繁/空白/标点
        
        # 2. 在 dim_{entity_type} 表查 normalized_name 完全相等
        async with pool.acquire() as conn:
            row = await conn.fetchrow(f"""
                SELECT {input.entity_type.value}_id 
                  FROM dim_{input.entity_type.value}
                 WHERE factory_id = $1 AND normalized_name = $2
            """, input.factory_id, normalized)
        
        if row:
            return AgentResult(
                matched_entity_id=row[0],
                confidence=1.0,  # 完全相等
                reasoning=f"normalized 完全匹配: '{input.raw_name}' → '{normalized}'",
            )
        return AgentResult(matched_entity_id=None, confidence=0.0, reasoning="无完全匹配")
```

**真实案例**:
- "唏嘛香 金虹桥店" / "唏嘛香金虹桥店" / "唏嘛香  金虹桥店" → 同一 normalized "唏嘛香金虹桥店" → 命中
- "招牌青花椒鱼（一吃）" / "招牌青花椒鱼(一吃)" → 半角 / 全角统一 → 命中

#### 2.3.2 EmbeddingAgent (B1)

**职责**: 名字向量化 + 余弦相似度. 处理同义/拼写错误.

```python
# backend/python/smartbi/canonical/entity_resolution/agents/embedding.py
class EmbeddingAgent(BaseAgent):
    name = "embedding"
    ship_threshold = 0.90
    
    def __init__(self, dashscope_client):
        self._client = dashscope_client
        # v1.1 修 S-1: LRU + 大小上限, 防 100 factories × 5000 dishes = 2GB 内存爆炸
        # 50K 条 × 1024 dim × 4 bytes (float32) = 200MB 上限
        from functools import lru_cache  # 概念用法; 实际 OrderedDict 可控制
        self._embedding_cache: OrderedDict[tuple[str, str], list[float]] = OrderedDict()
        self._cache_max_size = 50_000
    
    def _cache_get(self, key):
        if key in self._embedding_cache:
            self._embedding_cache.move_to_end(key)  # LRU
            return self._embedding_cache[key]
        return None
    
    def _cache_put(self, key, value):
        if key in self._embedding_cache:
            self._embedding_cache.move_to_end(key)
        else:
            self._embedding_cache[key] = value
            if len(self._embedding_cache) > self._cache_max_size:
                self._embedding_cache.popitem(last=False)  # 删最旧
    
    async def resolve(self, input: ResolutionInput, pool) -> AgentResult:
        # 1. 算 raw_name 的 embedding (qwen text-embedding-v3, 1024 dim)
        query_emb = await self._embed(input.raw_name)
        
        # 2. 查 dim_{entity_type} 所有候选 (同 factory)
        async with pool.acquire() as conn:
            rows = await conn.fetch(f"""
                SELECT {input.entity_type.value}_id, name, normalized_name
                  FROM dim_{input.entity_type.value}
                 WHERE factory_id = $1
                 LIMIT 1000  -- 防止 factory 实体爆炸 (一般 < 200)
            """, input.factory_id)
        
        if not rows:
            return AgentResult(matched_entity_id=None, confidence=0.0, reasoning="dim 表为空")
        
        # 3. 算每个候选的 embedding (缓存) + 余弦相似度
        best_id, best_sim = None, 0.0
        for row in rows:
            cand_emb = await self._embed(row["normalized_name"], cache_key=(input.factory_id, row["normalized_name"]))
            sim = cosine_similarity(query_emb, cand_emb)
            if sim > best_sim:
                best_sim, best_id = sim, row[0]
        
        # 4. 输出
        return AgentResult(
            matched_entity_id=best_id if best_sim > 0.7 else None,
            confidence=best_sim,
            reasoning=f"cosine sim={best_sim:.3f} 最高匹配 entity_id={best_id}",
        )
    
    async def _embed(self, text: str, cache_key=None) -> list[float]:
        if cache_key and cache_key in self._embedding_cache:
            return self._embedding_cache[cache_key]
        # 调 DashScope
        result = await self._client.embed(text, model="text-embedding-v3")
        if cache_key:
            self._embedding_cache[cache_key] = result
        return result
```

**Embedding 缓存策略**:
- 内存缓存 (per-process, 重启清)
- key = `(factory_id, normalized_name)`
- TTL: 不限 (因为 normalized_name 不变, model 不升级时不会失效)
- 模型升级 → 整个 cache 清

**成本估算**: 100 tenants × ~200 distinct entities/tenant × ~50 tokens × ¥0.0007/1K = ~¥0.7/月. 微小.

#### 2.3.3 ContextualAgent (B2, 条件触发)

**职责**: 加上下文 (店名+城市+区+品牌, 菜名+品类+店) 重新 embed, 提高准确率.

```python
class ContextualAgent(BaseAgent):
    name = "contextual"
    ship_threshold = 0.85
    
    async def resolve(self, input: ResolutionInput, pool) -> AgentResult:
        # 1. 构造 context 字符串
        if input.entity_type == EntityType.STORE:
            context_str = f"{input.raw_name} {input.context.get('city', '')} {input.context.get('district', '')}"
        elif input.entity_type == EntityType.PRODUCT:
            context_str = f"{input.raw_name} {input.context.get('category', '')} 店:{input.context.get('store_name', '')}"
        elif input.entity_type == EntityType.STAFF:
            context_str = f"{input.raw_name} 店:{input.context.get('store_name', '')} 岗位:{input.context.get('role', '')}"
        else:
            return AgentResult(matched_entity_id=None, confidence=0.0, reasoning="不支持的实体类型")
        
        # 2. 跟 EmbeddingAgent 类似, 但 embed context_str 而非 raw_name
        query_emb = await self._embed(context_str)
        
        # 3. 查候选, 各自构造同样格式的 context_str, embed, 比相似度
        # ... (同 EmbeddingAgent 但用 context_str)
        
        return AgentResult(
            matched_entity_id=best_id,
            confidence=best_sim,
            reasoning=f"contextual sim={best_sim:.3f}, ctx={context_str!r}",
        )
```

**真实案例**:
- "金虹桥店" 单独可能匹配多个店 → 加 city="上海" + district="长宁" → 唯一
- "招牌青花椒鱼" 单独可能歧义 (川菜店和粤菜店都有) → 加 store="桂满陇" → 准确

#### 2.3.4 TransitiveAgent (B2)

**职责**: 处理传递性闭包. A=B, B=C → A=C.

```python
class TransitiveAgent(BaseAgent):
    name = "transitive"
    ship_threshold = 0.80
    
    async def resolve(self, input: ResolutionInput, pool) -> AgentResult:
        """读 entity_resolution_history 表 (新建), 找 'A=B, B=C → A=C' 链.
        
        先决条件: 之前的 EmbeddingAgent / DeterministicAgent 已经决策过的 (raw_name → entity_id)
        都记录在 history 里, TransitiveAgent 用这些建立 union-find 找连通分量.
        """
        async with pool.acquire() as conn:
            # 1. 找跟 raw_name 历史 sim > 0.85 的 (a candidates)
            candidates = await conn.fetch("""
                SELECT b_name, b_entity_id, sim
                  FROM entity_resolution_history
                 WHERE factory_id = $1 
                   AND a_name = $2 
                   AND sim > 0.85
                 ORDER BY sim DESC LIMIT 5
            """, input.factory_id, normalize(input.raw_name))
            
            # 2. 对每个 b, 看 b 是不是又跟其他 c 高 sim 配对过
            for cand in candidates:
                next_hop = await conn.fetch("""
                    SELECT b_name, b_entity_id, sim FROM entity_resolution_history
                     WHERE factory_id = $1 AND a_name = $2 AND sim > 0.85
                """, input.factory_id, cand["b_name"])
                if next_hop and next_hop[0]["b_entity_id"] == cand["b_entity_id"]:
                    # 连通: input → cand → next_hop, 都同一个 entity
                    return AgentResult(
                        matched_entity_id=cand["b_entity_id"],
                        confidence=min(cand["sim"], next_hop[0]["sim"]) * 0.95,  # 闭包稍打折
                        reasoning=f"传递性: '{input.raw_name}' → '{cand['b_name']}' → entity_id={cand['b_entity_id']}",
                    )
        
        return AgentResult(matched_entity_id=None, confidence=0.0, reasoning="无传递性闭包")
```

### 2.4.0 STAFF 实体特例处理 (v1.1 修 C-5, 用户拍 半自动)

**背景**: prod `dim_staff` = 0 行. 不做特殊处理 → DeterministicAgent / EmbeddingAgent / TransitiveAgent 全部空表 → 100% 进 admin 队列, 第一天上线就爆.

**用户决策 (选项 C, 半自动)**:
- 同 `store_id` 内**第一次出现的员工名** → 自动 INSERT `dim_staff`, mapper_method='auto_new'
- 跨 store 重名员工 → 进 admin 队列 (因为可能是同人/可能不是)

```python
# backend/python/smartbi/canonical/entity_resolution/staff_handler.py
async def resolve_staff_with_autoCreate(
    raw_name: str, factory_id: str, store_id: int, conn
) -> tuple[int, bool]:
    """v1.1 C-5 半自动: 同 store 第一次见 → 自动创建; 跨 store 重名 → admin 队列.
    
    Returns: (staff_id, was_auto_created)
    """
    normalized = normalize_for_dim(raw_name)
    
    # 1. 同 store 内有同名员工?
    existing = await conn.fetchrow("""
        SELECT staff_id FROM dim_staff
         WHERE factory_id = $1 AND store_id = $2 AND normalized_name = $3
    """, factory_id, store_id, normalized)
    if existing:
        return existing["staff_id"], False
    
    # 2. 跨 store 有同名? → admin 队列
    cross_store = await conn.fetch("""
        SELECT staff_id, store_id FROM dim_staff
         WHERE factory_id = $1 AND store_id != $2 AND normalized_name = $3
    """, factory_id, store_id, normalized)
    if cross_store:
        # 进 admin 队列, 先临时创建一个新 staff_id (后期可被 admin 合并)
        new_id = await _create_staff(conn, factory_id, raw_name, normalized, store_id, mapper_method='cross_store_pending')
        await _queue_admin_staff_dedup(conn, new_id, [r["staff_id"] for r in cross_store])
        return new_id, True
    
    # 3. 完全新员工 → 自动创建
    new_id = await _create_staff(conn, factory_id, raw_name, normalized, store_id, mapper_method='auto_new')
    return new_id, True

async def _create_staff(conn, factory_id, raw_name, normalized, store_id, mapper_method) -> int:
    row = await conn.fetchrow("""
        INSERT INTO dim_staff (factory_id, name, normalized_name, store_id, mapper_method, created_at)
        VALUES ($1, $2, $3, $4, $5, NOW())
        ON CONFLICT (factory_id, name, store_id) DO UPDATE SET updated_at = NOW()
        RETURNING staff_id
    """, factory_id, raw_name, normalized, store_id, mapper_method)
    return row["staff_id"]

async def _queue_admin_staff_dedup(conn, new_staff_id, candidate_ids) -> None:
    """跨 store 重名 → admin 看一眼是不是同人"""
    await conn.execute("""
        INSERT INTO entity_resolution_admin_queue
          (factory_id, entity_type, raw_name, candidate_entity_id, confidence,
           decided_by_agent, reasoning, priority, status, extra)
        VALUES (
          (SELECT factory_id FROM dim_staff WHERE staff_id = $1),
          'staff', 
          (SELECT name FROM dim_staff WHERE staff_id = $1),
          $1, 0.5, 'cross_store_heuristic',
          '同 factory 跨 store 出现同名, 可能是同一人 (例如调店), 也可能不是',
          'medium', 'PENDING',
          jsonb_build_object('candidate_staff_ids', $2::int[])
        )
    """, new_staff_id, candidate_ids)
```

**特殊路径**: STAFF 实体不走通用 EntityResolutionOrchestrator, 而走 `resolve_staff_with_autoCreate`. 其它实体 (STORE / PRODUCT) 仍走 orchestrator.

**为什么不走 orchestrator**: 
- 通用 orchestrator 假设 dim 表有数据可查, staff 没有, 无法 fail open
- 半自动需要 store_id 上下文, ResolutionInput.context 不够直接
- staff 跨上传不需要 5-agent 决策, 简单"同店第一次见就建"足够

```python
async def consume_with_feature(
    self, factory_id: str, tokens: int, feature: str, today=None
) -> BudgetCheckResult:
    """加 feature 维度. 在功能 cap 内 OR 总 cap 内才放行."""
    today = today or _utc_today()
    feature_caps = {
        "shape_detector": 5_000,
        "entity_resolution_arbitrator": 30_000,
        "agent_insights": 200_000,
    }
    
    async with self._pool.acquire() as conn:
        async with conn.transaction():
            row = await conn.fetchrow("""
                SELECT tokens_used, tokens_cap, feature_breakdown
                  FROM agent_budget_daily
                 WHERE factory_id = $1 AND date = $2
                 FOR UPDATE
            """, factory_id, today)
            
            breakdown = row["feature_breakdown"] or {}
            feature_used = breakdown.get(feature, {}).get("used", 0)
            feature_cap = feature_caps.get(feature, 50_000)
            
            if feature_used + tokens > feature_cap:
                return BudgetCheckResult(blocked=True, ...)
            if row["tokens_used"] + tokens > row["tokens_cap"]:
                return BudgetCheckResult(blocked=True, ...)
            
            # 写入
            breakdown[feature] = {"used": feature_used + tokens, "cap": feature_cap}
            await conn.execute("""
                UPDATE agent_budget_daily
                   SET tokens_used = tokens_used + $1,
                       feature_breakdown = $2
                 WHERE factory_id = $3 AND date = $4
            """, tokens, breakdown, factory_id, today)
    
    return BudgetCheckResult(blocked=False, ...)
```

### 3.2 Shape Detector (LLM-driven)

```python
# backend/python/smartbi/canonical/shape_detector.py
from enum import Enum
from typing import List, Optional
import json

class FileShape(Enum):
    BILL_FLOW = "bill_flow"
    PRODUCT_SUMMARY = "product_summary"
    REVIEW = "review"
    FINANCE = "finance"
    INVENTORY = "inventory"
    SCHEDULE = "schedule"
    MEMBER = "member"
    UNKNOWN = "unknown"

@dataclass
class DetectionResult:
    shape: FileShape
    confidence: float
    reasoning: str

class ShapeDetector:
    """LLM-driven shape 识别. 第一遍跑 rule-based 快路径,
    rule 不确定时 fallback to qwen-plus."""
    
    async def detect(self, sample_rows: List[dict], column_names: List[str]) -> DetectionResult:
        # Step 1: rule-based 快路径
        rule_result = self._rule_detect(column_names)
        if rule_result.confidence > 0.85:
            return rule_result
        
        # Step 2: LLM fallback
        return await self._llm_detect(sample_rows, column_names)
    
    def _rule_detect(self, column_names: List[str]) -> DetectionResult:
        """硬编码规则, 覆盖 70% 常见 case."""
        col_set = set(column_names)
        
        # bill_flow 特征
        if any(c in col_set for c in ["账单号", "结账号", "订单号"]) and \
           any(c in col_set for c in ["营业日期", "日期", "transaction_date"]) and \
           any(c in col_set for c in ["商品信息", "菜品明细"]):
            return DetectionResult(FileShape.BILL_FLOW, 0.95, "rule: 账单+日期+商品 三件套")
        
        # product_summary 特征
        if any(c in col_set for c in ["商品名称", "菜品名称"]) and \
           not any(c in col_set for c in ["账单号", "订单号"]) and \
           any(c in col_set for c in ["销售金额", "营业额"]):
            return DetectionResult(FileShape.PRODUCT_SUMMARY, 0.90, "rule: 商品+金额 + 缺账单")
        
        # review 特征
        if any(c in col_set for c in ["评分", "星级", "rating"]) and \
           any(c in col_set for c in ["评论", "评价", "review_text"]):
            return DetectionResult(FileShape.REVIEW, 0.92, "rule: 评分+评论文本")
        
        # finance 特征
        if any(c in col_set for c in ["凭证号", "voucher_no"]) and \
           any(c in col_set for c in ["科目", "subject"]):
            return DetectionResult(FileShape.FINANCE, 0.88, "rule: 凭证+科目")
        
        # inventory 特征
        if any(c in col_set for c in ["库存量", "盘点量", "stock_qty"]) and \
           any(c in col_set for c in ["食材", "原材料", "ingredient"]):
            return DetectionResult(FileShape.INVENTORY, 0.85, "rule: 库存+食材")
        
        # 不确定
        return DetectionResult(FileShape.UNKNOWN, 0.50, "rule: 无明显特征, 需 LLM")
    
    async def _llm_detect(self, sample_rows, column_names) -> DetectionResult:
        """用 qwen-plus 看前 5 行 + 列名."""
        prompt = f"""
你是餐饮数据形态识别专家. 给定 Excel/CSV 列名 + 前 5 行样本, 判断它是哪种形态:

支持的形态:
1. bill_flow (账单流水): 每行=一笔顾客订单, 含账单号+日期+菜品组合
2. product_summary (商品销售汇总): 每行=一道菜在某段时间的总销售
3. review (评论): 含评分+评论文本
4. finance (财务凭证): 含凭证号+科目+收支
5. inventory (库存盘点): 含食材+库存量
6. schedule (排班): 含员工+班次+日期
7. member (会员): 含会员 ID+储值
8. unknown: 都不是

列名: {column_names}
前 5 行样本: {sample_rows[:5]}

返回 JSON: {{"shape": "<one of above>", "confidence": <0-1>, "reasoning": "<简要原因>"}}
"""
        response = await self._llm_client.chat(prompt, model="qwen-plus")
        result = json.loads(response)
        return DetectionResult(
            shape=FileShape(result["shape"]),
            confidence=result["confidence"],
            reasoning=f"LLM: {result['reasoning']}",
        )
```

**置信度阈值**:
- ≥ 0.85: 自动路由
- 0.50-0.85: 进 admin 审核队列, 客户/内部确认
- < 0.50: 标 UNKNOWN, 用户必须手工选

```python
            raw_name=raw_name,
            entity_type=EntityType.PRODUCT,
            factory_id=factory_id,
            context=context,  # {category, store_id, store_name}
        ))
```

```python
                upload_id
            )
            # 2. 取 period (Sheet Merger 推断的, 可能 NULL)
            period = await self._fetch_period(upload_id, conn)
            
            # 3. 批量解析实体 + 累积 records
            orchestrator = self._build_orchestrator(pool)
            records = []
            new_entity_count = 0
            admin_queue_count = 0
            
            for row_pg in rows:
                row = row_pg["row_data"]
                store_name = row.get("门店名称") or row.get("store_name")
                product_name = row.get("商品名称") or row.get("product_name")
                
                store_id = await self._resolve_store(
                    store_name, factory_id,
                    context={"brand": row.get("品牌")},
                    orchestrator=orchestrator,
                )
                product_id = await self._resolve_product(
                    product_name, factory_id,
                    context={"category": row.get("商品分类"), "store_name": store_name},
                    orchestrator=orchestrator,
                )
                
                if store_id is None or product_id is None:
                    admin_queue_count += 1
                    continue  # 跳过 (admin 队列已记录)
                
                qty = float(row.get("单卖数量") or 0)
                revenue = float(row.get("销售金额") or 0)
                records.append((
                    factory_id, upload_id, product_id, store_id,
                    period.start, period.end, qty, revenue, revenue / qty if qty else 0,
                ))
            
            # 4. 批量 INSERT (v1.1 修 S-4: 5000/批)
            for i in range(0, len(records), self.BATCH_SIZE):
                batch = records[i:i + self.BATCH_SIZE]
                await conn.executemany("""
                    INSERT INTO agg_product_period 
                      (factory_id, upload_id, product_id, store_id,
                       period_start, period_end, qty_sold, revenue, avg_unit_price)
                    VALUES ($1, $2, $3, $4, $5, $6, $7, $8, $9)
                    ON CONFLICT (factory_id, upload_id, product_id, store_id, period_start) DO UPDATE SET
                      qty_sold = EXCLUDED.qty_sold,
                      revenue = EXCLUDED.revenue
                """, batch)
        
        return WriteSummary(
            rows_written=len(records),
            rows_skipped=admin_queue_count,
            new_entity_count=new_entity_count,
            admin_queue_count=admin_queue_count,
            elapsed_ms=int((time.time() - t0) * 1000),
        )
```

**性能估算**: 1.3M 行 / 5000 batch = 260 批; 假设每批 50ms (网络 + commit) = ~13 秒. 远低于"几小时". 集成测试可过.

#### 5.4.1 compare_periods 完整定义

```python
# backend/python/smartbi/canonical/sheet_merger.py
from enum import Enum
from datetime import date
from typing import Optional, Tuple

class PeriodRelation(Enum):
    EQUAL = "equal"           # A 完全等于 B
    SUBSET = "subset"         # A 是 B 的子集 (A ⊂ B)
    SUPERSET = "superset"     # A 是 B 的超集 (A ⊃ B)
    DISJOINT = "disjoint"     # 完全不相交
    OVERLAP = "overlap"       # 部分重叠 (不是 subset/superset/equal)
    UNKNOWN = "unknown"       # v1.1 加: 至少一边为 NULL, 不可比较

def compare_periods(
    a: Tuple[Optional[date], Optional[date]],
    b: Tuple[Optional[date], Optional[date]],
) -> PeriodRelation:
    """v1.1 完整定义.
    
    任一边 None → UNKNOWN (调用方负责跳过 merge).
    """
    a_start, a_end = a
    b_start, b_end = b
    if any(x is None for x in (a_start, a_end, b_start, b_end)):
        return PeriodRelation.UNKNOWN
    
    if a_start == b_start and a_end == b_end:
        return PeriodRelation.EQUAL
    if a_end < b_start or b_end < a_start:
        return PeriodRelation.DISJOINT
    if a_start <= b_start and a_end >= b_end:
        return PeriodRelation.SUPERSET
    if b_start <= a_start and b_end >= a_end:
        return PeriodRelation.SUBSET
    return PeriodRelation.OVERLAP
```

#### 5.4.2 decide_merge (v1.1 完整版)

```python
async def decide_merge(new_upload, factory_id: str, conn) -> dict:
    """对新 upload 跟同 factory 同 shape 的其它 upload 比较.
    
    v1.1 修复:
    - C-6/S-8: 时间推断失败 (period 含 NULL) → 跳过, 标 PERIOD_UNKNOWN
    - S-2: compare_periods + queue helpers 现已显式定义
    - 增加 SUBSET 处理 (新 upload 比旧的更窄, 怎么办)
    """
    summary = {"superseded_count": 0, "merged_count": 0, "queued_count": 0, "skipped_count": 0}
    
    # v1.1 修 C-6/S-8: 推断失败 → 标 PERIOD_UNKNOWN, 不参与 merge
    if new_upload.merge_inferred_period_start is None or new_upload.merge_inferred_period_end is None:
        await conn.execute(
            "UPDATE smart_bi_pg_excel_uploads SET merge_status = 'PERIOD_UNKNOWN' WHERE id = $1",
            new_upload.id
        )
        summary["skipped_count"] = 1
        return summary
    
    new_period = (new_upload.merge_inferred_period_start, new_upload.merge_inferred_period_end)
    
    others = await conn.fetch("""
        SELECT id, merge_inferred_period_start AS p_start,
               merge_inferred_period_end AS p_end, created_at
          FROM smart_bi_pg_excel_uploads
         WHERE factory_id = $1
           AND id != $2
           AND merge_status IS NULL
           AND detected_table_type = $3
    """, factory_id, new_upload.id, new_upload.detected_table_type)
    
    for other in others:
        relation = compare_periods(new_period, (other["p_start"], other["p_end"]))
        
        if relation == PeriodRelation.UNKNOWN:
            continue  # 对方推断失败, 跳过
        
        if relation in (PeriodRelation.EQUAL, PeriodRelation.SUPERSET):
            # 新版完全覆盖或包含旧版
            await conn.execute(
                "UPDATE smart_bi_pg_excel_uploads SET merge_status = 'SUPERSEDED' WHERE id = $1",
                other["id"]
            )
            summary["superseded_count"] += 1
        elif relation == PeriodRelation.SUBSET:
            # v1.1 加: 新 upload 比旧的窄 (e.g. 新=2025-01, 旧=2025 全年)
            # 不 SUPERSED 旧的 (旧的覆盖更广), 但标 'NESTED_IN_<id>' 让客户裁决
            await conn.execute("""
                UPDATE smart_bi_pg_excel_uploads
                SET merge_status = $1, merge_target_id = $2 WHERE id = $3
            """, f'NESTED_IN_{other["id"]}', other["id"], new_upload.id)
            await _queue_for_admin_review(
                conn, factory_id, new_upload.id, other["id"], "PERIOD_NESTED"
            )
            summary["queued_count"] += 1
            break  # 新 upload 已被 nest, 跳出
        elif relation == PeriodRelation.OVERLAP:
            # 部分重叠 → admin 裁决
            await conn.execute("""
                UPDATE smart_bi_pg_excel_uploads
                SET merge_status = $1, merge_target_id = $2 WHERE id = $3
            """, f'MERGED_INTO_{new_upload.id}', new_upload.id, other["id"])
            await _queue_for_admin_review(
                conn, factory_id, other["id"], new_upload.id, "PERIOD_OVERLAP"
            )
            summary["merged_count"] += 1

    return summary
```

## 7. 并发模型 (advisory_xact_lock + asyncio.Lock + cache 失效)

(从 A v1.4 §4.2.2 继承)

### 7.1 三层防御

```python
# backend/python/smartbi/canonical/concurrency.py
import asyncio
import hashlib
from collections import defaultdict

_factory_locks: dict[str, asyncio.Lock] = defaultdict(asyncio.Lock)

async def with_factory_serialization(factory_id: str, conn, work):
    """三层防御: asyncio.Lock + pg_advisory_xact_lock + cache invalidation.
    
    Layer 1 (asyncio.Lock): Python 进程内, 防 同 factory 任务并发跑同步函数
    Layer 2 (pg_advisory_xact_lock): Postgres 层, 防 multi-worker 并发
    Layer 3 (cache invalidate): 清 dim_resolver 内存缓存, 防 stale entity_id
    """
    async with _factory_locks[factory_id]:           # Layer 1
        lock_key = int(hashlib.md5(factory_id.encode()).hexdigest()[:8], 16) % (2**31)
        async with conn.transaction():
            await conn.execute("SELECT pg_advisory_xact_lock($1)", lock_key)  # Layer 2
            result = await work(conn)
        # Layer 3: 清 in-memory cache (现有 dim_resolver 有 cache 不线程安全)
        from smartbi.canonical.dim_resolver import clear_cache
        clear_cache(factory_id)
        return result
```
