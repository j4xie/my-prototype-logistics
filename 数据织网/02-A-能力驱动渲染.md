# Sub-Project A: 能力驱动渲染契约层 (Capability Contract Layer)

**所属**: 数据织网 (Data Fabric) 4 个 Sub-Project 之 A
**版本**: v1.0
**日期**: 2026-04-25
**关联**: `01-总览路线图.md` v1.2
**工作量**: 1.5-2 周 (单工)
**关键依赖**: 无 (可与 B 并行启动)
**关键产出**: A 是 B/C/D 的契约层, 后三者完成新功能时**必须**填 A 的 metadata

---

## 1. 目标与边界

### 1.1 目标

客户上传任何 CSV/xlsx 后, Dashboard / 模板 / KPI 卡片**只渲染当前数据能算的内容**, 不显示空 0 / 误导, 缺数据时友好引导客户补充.

### 1.2 在 Data Fabric 体系中的角色

A 是**契约层 (Contract Layer)**, 不是下游消费层. 即:
- A 定义全系统统一的 `requires: [field_list]` 元数据格式
- A 提供 `CapabilityCalculator(factory_id) → set[canonical_fields]` 接口
- B/C/D 在做新功能 (新 fact 表 / 新 template) 时**必须填 requires 元数据**
- A 的渲染层 pre-filter 自动决定每张卡片 / 模板是否显示

```
Bronze 层 (已 Production)
       ↓
A: Capability Contract Layer  ← 本 spec, week 1-2
   - requires: metadata schema
   - CapabilityCalculator
   - FE pre-filter + CTA
       ↓
B/C/D 完成新功能 → 自动填 A 的契约 → A 的渲染自动解锁
```

### 1.3 in-scope vs out-of-scope

**In Scope**:
- ✅ `requires:` YAML 格式定义
- ✅ Python `CapabilityCalculator` 类
- ✅ FastAPI 端点 `GET /api/smartbi/capability/{factory_id}`
- ✅ Vue composable `useCapability()` + `<CapabilityGate>` 组件
- ✅ "解锁更多分析" CTA 组件
- ✅ 现有 44 个 template + ~30 个 Dashboard 卡片打 metadata
- ✅ Admin 审计页 (列出所有 `requires` 元数据 + 当前 factory 的可用字段)

**Out of Scope (留给 B/C/D)**:
- ❌ 新 Silver writer (B)
- ❌ 实体解析 (B)
- ❌ 字段血统 (C)
- ❌ Federated Query (D)
- ❌ Java 后端 capability gate (Java 是 CRUD, 不做 UI 渲染决策)

### 2.2 metadata 在哪里存

3 种声明位置, 各有用途:

#### 2.2.1 Python template (现有 44 个 + B 新增)

加在 template class 作为 ClassVar:

```python
# backend/python/smartbi/services/materialized_analytics/templates/dish_sales_top_n.py
from smartbi.capability.contract import RequiresSpec

class DishSalesTopN(AnalysisTemplate):
    code = "dish_sales_top_n"
    
    # v1.0 新增: capability metadata
    requires: ClassVar[RequiresSpec] = RequiresSpec(
        all=["store_name", "combo_string"],
        any=[],  # 不需要 OR 关系
        description="按菜品销量 / 销售额排行 (Top 20)",
    )
    
    sample_queries: ClassVar[List[str]] = ["菜品销量排名", "卖得最多的菜"]
    
    def applies(self, schema: DataSchema) -> bool:
        # 现有 applies() 保留, A 不替换
        return "商品信息" in schema.field_names_set or "combo_string" in schema.canonical_fields
    
    def compute(self, backend, schema): ...
```

**与 `applies()` 的关系**:
- `applies(schema)` = 模板内部"基于本次上传的 schema 是否适用"
- `requires` = "本卡片要在 factory 视图层显示, 需要 factory 至少上传过哪些字段"
- 二者**互补不互斥**: applies() 决定是否对单次上传产生 result; requires 决定 result 是否在 UI 显示

### 2.3 RequiresSpec 类型定义

```python
# backend/python/smartbi/capability/contract.py
from dataclasses import dataclass, field
from typing import List, Optional

@dataclass(frozen=True)
class RequiresSpec:
    """声明一个卡片/模板需要哪些 canonical 字段才能渲染."""
    
    all: List[str] = field(default_factory=list)
    """所有字段必须在 factory 可用集合中. 任一缺失则隐藏."""
    
    any: List[str] = field(default_factory=list)
    """至少一个字段在 factory 可用集合中. 全缺则隐藏. 默认空表示无 OR 约束."""
    
    description: Optional[str] = None
    """人类可读说明 (用于 admin 审计页 + CTA tooltip)"""
    
    def is_satisfied_by(self, available: set[str]) -> bool:
        """判断 factory 当前可用字段集合是否满足此 spec."""
        all_ok = all(f in available for f in self.all)
        any_ok = (not self.any) or any(f in available for f in self.any)
        return all_ok and any_ok
    
    def missing_fields(self, available: set[str]) -> List[str]:
        """列出缺失字段 (用于 CTA 提示)."""
        return [f for f in self.all if f not in available]
```

```typescript
// web-admin/src/types/capability.ts
export interface RequiresSpec {
  all: string[];
  any?: string[];
  description?: string;
}
```

## 3. CapabilityCalculator 设计

### 3.1 接口

```python
# backend/python/smartbi/capability/calculator.py
class CapabilityCalculator:
    """聚合 factory 所有 upload 的 field_definitions, 返回 canonical 字段集合."""
    
    def __init__(self, pool: asyncpg.Pool):
        self._pool = pool
        self._cache: dict[str, tuple[set[str], float]] = {}  # factory_id → (fields, ts)
        self._cache_ttl = 300  # 5 分钟 TTL (上传不频繁)
    
    async def get_capabilities(self, factory_id: str) -> set[str]:
        """返回 factory 当前可用的 canonical 字段集合.
        
        逻辑:
        1. SELECT DISTINCT original_name FROM smart_bi_pg_field_definitions
           WHERE upload_id IN (SELECT id FROM smart_bi_pg_excel_uploads
                               WHERE factory_id = $1 AND upload_status = 'COMPLETED')
        2. 用 _ALIAS_TO_ATTR 把每个 original_name 映射到 canonical
        3. 返回去重后的 canonical 集合
        4. 5 分钟 TTL 缓存
        """
        cached = self._cache.get(factory_id)
        if cached and time.time() - cached[1] < self._cache_ttl:
            return cached[0]
        
        async with self._pool.acquire() as conn:
            await conn.execute("SELECT set_config('app.factory_id', $1, false)", factory_id)
            rows = await conn.fetch("""
                SELECT DISTINCT fd.original_name
                  FROM smart_bi_pg_field_definitions fd
                  JOIN smart_bi_pg_excel_uploads u ON fd.upload_id = u.id
                 WHERE u.factory_id = $1
                   AND u.upload_status = 'COMPLETED'
            """, factory_id)
        
        from scripts.backfill_silver import _ALIAS_TO_ATTR
        canonical_fields: set[str] = set()
        for row in rows:
            original = row["original_name"]
            canonical = _ALIAS_TO_ATTR.get(original)
            if canonical:
                canonical_fields.add(canonical)
        
        self._cache[factory_id] = (canonical_fields, time.time())
        return canonical_fields
    
    def invalidate(self, factory_id: str) -> None:
        """上传完成后调用, 失效缓存."""
        self._cache.pop(factory_id, None)
```

### 3.2 缓存失效时机

| 时机 | 调用 | 文件 |
|---|---|---|
| 新上传完成 (status → COMPLETED) | `calculator.invalidate(factory_id)` | `excel_async.py` `_finalize_upload()` |
| 上传删除 | 同上 | `excel_async.py` `delete_upload()` |
| 手动 admin 操作 | API: `POST /api/smartbi/capability/{factory_id}/invalidate` | 新建 `capability/api.py` |
| field_definitions 编辑 (admin 修映射) | 同 invalidate | 现有 admin 端点加 hook |

### 3.3 RLS 兼容性

`smart_bi_pg_field_definitions` 表当前**没有 factory_id 列** (FK 到 upload). RLS 要靠 join `smart_bi_pg_excel_uploads`. 上面 SQL 已正确处理.

**注意**: pool 的 `setup` callback (现有 `set_pg_connection_tenant`) 会自动设 `app.factory_id`, 但本调用是从背景任务发起 (HTTP 请求中), 需确保 tenant context 已设置. 检查方式:

```python
from smartbi.tenant_ctx import get_factory_id

async def get_capabilities(self, factory_id: str) -> set[str]:
    # Defensive: 上下文里的 factory_id 必须 == 参数
    ctx_fid = get_factory_id()
    if ctx_fid and ctx_fid != factory_id:
        raise ValueError(f"factory_id mismatch: ctx={ctx_fid}, arg={factory_id}")
    ...
```

## 4. FastAPI 端点设计

### 4.1 路由

```python
# backend/python/smartbi/capability/api.py
from fastapi import APIRouter, Depends, HTTPException
from smartbi.capability.calculator import CapabilityCalculator

router = APIRouter(prefix="/api/smartbi/capability", tags=["Capability"])

@router.get("/{factory_id}")
async def get_capability(
    factory_id: str,
    calc: CapabilityCalculator = Depends(get_calculator),
    user_factory_id: str = Depends(verify_jwt_factory_id),
):
    """返回 factory 当前可用的 canonical 字段 + 模板/卡片解锁状态."""
    if user_factory_id != factory_id:
        raise HTTPException(403, "Cross-tenant access denied")
    
    available = await calc.get_capabilities(factory_id)
    
    # 收集所有已知的 requires (来自 templates + manifest)
    template_status = await _check_template_capability(available)
    card_status = await _check_card_capability(available)
    
    return {
        "factory_id": factory_id,
        "available_fields": sorted(available),
        "template_status": template_status,    # {template_code: {satisfied, missing}}
        "card_status": card_status,            # {card_id: {satisfied, missing}}
        "unlock_suggestions": _suggest_unlocks(available, template_status, card_status),
    }

@router.post("/{factory_id}/invalidate")
async def invalidate_cache(
    factory_id: str,
    calc: CapabilityCalculator = Depends(get_calculator),
    user_factory_id: str = Depends(verify_jwt_factory_id),
):
    if user_factory_id != factory_id:
        raise HTTPException(403)
    calc.invalidate(factory_id)
    return {"status": "ok"}
```

## 5. Vue 前端集成

### 5.1 Composable

```typescript
// web-admin/src/composables/useCapability.ts
import { ref, computed, onMounted } from 'vue';
import { useAuthStore } from '@/store/auth';
import apiClient from '@/services/apiClient';

interface CapabilityResponse {
  available_fields: string[];
  template_status: Record<string, { satisfied: boolean; missing: string[] }>;
  card_status: Record<string, { satisfied: boolean; missing: string[] }>;
  unlock_suggestions: Array<{
    missing_field: string;
    unlocks_count: number;
    unlocks_examples: string[];
    cta: string;
  }>;
}

const _capabilityCache = ref<CapabilityResponse | null>(null);
const _loading = ref(false);

export function useCapability() {
  const authStore = useAuthStore();
  
  async function fetchCapability(force = false) {
    if (_capabilityCache.value && !force) return _capabilityCache.value;
    _loading.value = true;
    try {
      const factoryId = authStore.factoryId;
      const res = await apiClient.get(`/api/smartbi/capability/${factoryId}`);
      _capabilityCache.value = res.data;
      return res.data;
    } finally {
      _loading.value = false;
    }
  }
  
  const available = computed(() => 
    new Set(_capabilityCache.value?.available_fields ?? [])
  );
  
  function hasAll(requires: string[]): boolean {
    return requires.every(f => available.value.has(f));
  }
  
  function missingOf(requires: string[]): string[] {
    return requires.filter(f => !available.value.has(f));
  }
  
  return {
    fetchCapability,
    available,
    hasAll,
    missingOf,
    loading: _loading,
    suggestions: computed(() => _capabilityCache.value?.unlock_suggestions ?? []),
  };
}
```

### 5.2 CapabilityGate 组件

```vue
<!-- web-admin/src/components/CapabilityGate.vue -->
<script setup lang="ts">
import { computed } from 'vue';
import { useCapability } from '@/composables/useCapability';

const props = defineProps<{
  requires: string[];
  cardId: string;
  fallback?: 'hide' | 'placeholder';   // hide (默认) 完全隐藏; placeholder 显示占位 + 解锁提示
}>();

const { hasAll, missingOf } = useCapability();

const satisfied = computed(() => hasAll(props.requires));
const missing = computed(() => missingOf(props.requires));
const fallbackMode = computed(() => props.fallback ?? 'hide');
</script>

<template>
  <slot v-if="satisfied" />
  <div v-else-if="fallbackMode === 'placeholder'" class="capability-placeholder">
    <el-empty :description="`此分析需上传含 ${missing.join('/')} 的数据`" :image-size="60" />
  </div>
  <!-- fallbackMode === 'hide': 渲染空 -->
</template>
```

**默认 hide** = 缺数据时整个卡片消失 (Dashboard 看起来天然只有这么多). 不显示空白卡片误导客户.

**placeholder 模式**用于关键卡 (例如 Dashboard 的"客单价"), 即使没数据也显示占位帮客户理解"这里本应有客单价".

## 10. 风险与未决问题

### 10.1 风险

| # | 风险 | 缓解 |
|---|---|---|
| A1 | `_ALIAS_TO_ATTR` 现存中文别名不全 (qhj 版 vs 客如云版 vs 银豹版可能用不同列名) | 上 prod 前用 12 个 factories 真实 field_definitions 跑一遍, 命中率 < 80% 时扩 ALIAS 表 |

| A4 | Vue 组件 build-time manifest 收集 (vite plugin 写起来繁琐) | v1.0 不强制 vite plugin, manifest YAML 手工维护; v1.1 再自动化 |

### 10.2 未决问题 (送审用户)

5. **Java 后端是否需要 capability gate**: 当前 spec 不做, 未来如果 Java 暴露 dashboard 数据接口才考虑. 是否同意?
