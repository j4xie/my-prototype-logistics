## 1. 目标与边界

### 1.1 目标

客户上传任何 CSV/xlsx 后, Dashboard / 模板 / KPI 卡片**只渲染当前数据能算的内容**, 不显示空 0 / 误导, 缺数据时友好引导客户补充.

### 1.2 在 Data Fabric 体系中的角色

A 是**契约层 (Contract Layer)**, 不是下游消费层. 即:
- A 定义全系统统一的 `requires: [field_list]` 元数据格式
- A 提供 `CapabilityCalculator(factory_id) → set[canonical_fields]` 接口
- B/C/D 在做新功能 (新 fact 表 / 新 template) 时**必须填 requires 元数据**
- A 的渲染层 pre-filter 自动决定每张卡片 / 模板是否显示

```
Bronze 层 (已 Production)
       ↓
A: Capability Contract Layer  ← 本 spec, week 1-2
   - requires: metadata schema
   - CapabilityCalculator
   - FE pre-filter + CTA
       ↓
B/C/D 完成新功能 → 自动填 A 的契约 → A 的渲染自动解锁
```

### 1.3 in-scope vs out-of-scope

**In Scope**:
- ✅ `requires:` YAML 格式定义
- ✅ Python `CapabilityCalculator` 类
- ✅ FastAPI 端点 `GET /api/smartbi/capability/{factory_id}`
- ✅ Vue composable `useCapability()` + `<CapabilityGate>` 组件
- ✅ "解锁更多分析" CTA 组件
- ✅ 现有 44 个 template + ~30 个 Dashboard 卡片打 metadata
- ✅ Admin 审计页 (列出所有 `requires` 元数据 + 当前 factory 的可用字段)

**Out of Scope (留给 B/C/D)**:
- ❌ 新 Silver writer (B)
- ❌ 实体解析 (B)
- ❌ 字段血统 (C)
- ❌ Federated Query (D)
- ❌ Java 后端 capability gate (Java 是 CRUD, 不做 UI 渲染决策)

### 2.2 metadata 在哪里存

3 种声明位置, 各有用途:

#### 2.2.1 Python template (现有 44 个 + B 新增)

加在 template class 作为 ClassVar:

```python
# backend/python/smartbi/services/materialized_analytics/templates/dish_sales_top_n.py
from smartbi.capability.contract import RequiresSpec

class DishSalesTopN(AnalysisTemplate):
    code = "dish_sales_top_n"
    
    # v1.0 新增: capability metadata
    requires: ClassVar[RequiresSpec] = RequiresSpec(
        all=["store_name", "combo_string"],
        any=[],  # 不需要 OR 关系
        description="按菜品销量 / 销售额排行 (Top 20)",
    )
    
    sample_queries: ClassVar[List[str]] = ["菜品销量排名", "卖得最多的菜"]
    
    def applies(self, schema: DataSchema) -> bool:
        # 现有 applies() 保留, A 不替换
        return "商品信息" in schema.field_names_set or "combo_string" in schema.canonical_fields
    
    def compute(self, backend, schema): ...
```

**与 `applies()` 的关系**:
- `applies(schema)` = 模板内部"基于本次上传的 schema 是否适用"
- `requires` = "本卡片要在 factory 视图层显示, 需要 factory 至少上传过哪些字段"
- 二者**互补不互斥**: applies() 决定是否对单次上传产生 result; requires 决定 result 是否在 UI 显示

#### 2.2.2 Vue Dashboard 卡片

每张卡 component 加 `data().requires` 字段:


#### 2.2.3 Card manifest 在 FE 维护 (v1.1 修正 C1)

**v1.0 设计漏洞**: 把卡片 manifest 写到 YAML 让 Python 计算 `card_status`, 但 YAML 在 `web-admin/` 下, **永远不会 ship 到 Python**. 后端无数据可算.

**v1.1 修法**: **`card_status` 改在 FE 计算**. 后端只返 `available_fields` + `template_status` (templates 在 Python 代码里, 后端能算). FE 用本地 manifest TS 文件 + `available_fields` 自己算 card_status.

```python
from dataclasses import dataclass, field
from typing import List, Optional

@dataclass(frozen=True)
class RequiresSpec:
    """声明一个卡片/模板需要哪些 canonical 字段才能渲染."""
    
    all: List[str] = field(default_factory=list)
    """所有字段必须在 factory 可用集合中. 任一缺失则隐藏."""
    
    any: List[str] = field(default_factory=list)
    """至少一个字段在 factory 可用集合中. 全缺则隐藏. 默认空表示无 OR 约束."""
    
    description: Optional[str] = None
    """人类可读说明 (用于 admin 审计页 + CTA tooltip)"""
    
    def is_satisfied_by(self, available: set[str]) -> bool:
        """判断 factory 当前可用字段集合是否满足此 spec."""
        all_ok = all(f in available for f in self.all)
        any_ok = (not self.any) or any(f in available for f in self.any)
        return all_ok and any_ok
    
    def missing_fields(self, available: set[str]) -> List[str]:
        """列出缺失字段 (用于 CTA 提示)."""
        return [f for f in self.all if f not in available]
```

### 3.1 接口 (v1.1 修复 C4 RLS + C5 import)

```python
# backend/python/smartbi/capability/calculator.py
import asyncio
import time
from typing import Optional
import asyncpg
from fastapi import HTTPException
from smartbi.canonical.aliases import to_canonical
from smartbi.tenant_ctx import get_factory_id

class CapabilityCalculator:
    """聚合 factory 所有 upload 的 field_definitions, 返回 canonical 字段集合.
    
    Concurrency model:
    - Per-process in-memory dict cache (current prod uvicorn worker=1, OK)
    - 5 分钟 TTL + event-driven invalidate
    - Inflight Promise dedup 防 stampede
    
    多 worker scale 时切 Redis (见 §3.4).
    """
    
    def __init__(self, pool: asyncpg.Pool):
        self._pool = pool
        self._cache: dict[str, tuple[set[str], float]] = {}
        self._cache_ttl = 300  # 5 分钟
        self._inflight: dict[str, asyncio.Future] = {}  # 防 stampede
        # v1.4 修复 O5: invalidation generation token, 防 inflight 完成后写入已 invalidate 的旧结果
        self._invalidation_gen: dict[str, int] = {}
        # v1.4 修复 S-v3-1: merge_status column 存在性 lazy memo (一次性, 不在 hot path)
        self._has_merge_status: Optional[bool] = None
    
    async def _check_merge_status_column(self) -> bool:
        """检测 merge_status 列是否存在 (B 上线后存在). lazy memo 一次. v1.4 S-v3-1."""
        if self._has_merge_status is not None:
            return self._has_merge_status
        async with self._pool.acquire() as conn:
            self._has_merge_status = await conn.fetchval("""
                SELECT EXISTS (
                    SELECT 1 FROM information_schema.columns
                    WHERE table_name = 'smart_bi_pg_excel_uploads'
                      AND column_name = 'merge_status'
                )
            """)
        return self._has_merge_status
    
    async def get_capabilities(self, factory_id: str) -> set[str]:
        """返回 factory 当前可用的 canonical 字段集合."""
        # Defensive: 上下文 factory_id 必须匹配 (防 IDOR)
        ctx_fid = get_factory_id()
        if ctx_fid and ctx_fid != factory_id:
            raise HTTPException(status_code=403, detail="Cross-tenant access denied")
        
        # 缓存命中
        cached = self._cache.get(factory_id)
        if cached and time.time() - cached[1] < self._cache_ttl:
            return cached[0]
        
        # Inflight dedup: 多个并发请求同一 factory 时只跑一次 query
        if factory_id in self._inflight:
            return await self._inflight[factory_id]
        
        # v1.4 修复 O5: 记录开始时的 generation, 完成后只在 generation 未变时写入 cache
        gen_at_start = self._invalidation_gen.get(factory_id, 0)
        future: asyncio.Future = asyncio.Future()
        self._inflight[factory_id] = future
        try:
            result = await self._fetch_capabilities(factory_id)
            # v1.4: 只有 generation 没变 (期间未发生 invalidate) 才写入 cache
            if self._invalidation_gen.get(factory_id, 0) == gen_at_start:
                self._cache[factory_id] = (result, time.time())
            future.set_result(result)
            return result
        except Exception as e:
            future.set_exception(e)
            raise
        finally:
            self._inflight.pop(factory_id, None)
    
    async def _fetch_capabilities(self, factory_id: str) -> set[str]:
        """v1.1 修复 C4: transaction-scoped set_config + 显式 transaction 包裹.
        v1.3 修复 S-v2-2 + v1.4 修复 C-v3-1 + S-v3-1: merge_status 过滤改 NOT LIKE 模式 (匹配动态 id), column 存在性 memo 不在 hot path.
        """
        # v1.4: 一次性 lazy memo, 不在事务内 (避免事务跨多个操作)
        has_merge_status = await self._check_merge_status_column()
        
        # v1.4 修复 C-v3-1: NOT LIKE 'MERGED_INTO_%' 匹配动态 id 模式
        # (§11.1 定义 merge_status='MERGED_INTO_<id>', literal 'MERGED_INTO_OTHER' 永远不匹配)
        merge_filter = (
            "AND (u.merge_status IS NULL OR (u.merge_status != 'SUPERSEDED' AND u.merge_status NOT LIKE 'MERGED_INTO_%'))"
            if has_merge_status
            else ""
        )
        
        async with self._pool.acquire() as conn:
            async with conn.transaction():
                await conn.execute(
                    "SELECT set_config('app.factory_id', $1, true)",
                    factory_id
                )
                rows = await conn.fetch(f"""
                    SELECT DISTINCT fd.original_name
                      FROM smart_bi_pg_field_definitions fd
                      JOIN smart_bi_pg_excel_uploads u ON fd.upload_id = u.id
                     WHERE u.factory_id = $1
                       AND u.upload_status = 'COMPLETED'
                       {merge_filter}
                """, factory_id)
        
        canonical_fields: set[str] = set()
        for row in rows:
            canonical = to_canonical(row["original_name"])
            if canonical:
                canonical_fields.add(canonical)
        return canonical_fields
    
    def invalidate(self, factory_id: str) -> None:
        """上传完成后调用, 失效缓存.
        
        v1.4 修复 O5: 同时 bump generation token. 任何此刻仍 inflight 的 query
        完成后会比对 generation, 不再覆盖新数据 (防 race: invalidate 跑时
        旧 inflight 还没结束, 旧结果会写入 cache 当作 fresh).
        """
        self._cache.pop(factory_id, None)
        self._invalidation_gen[factory_id] = self._invalidation_gen.get(factory_id, 0) + 1
```

### 3.3 RLS 兼容性 (v1.1)

`smart_bi_pg_field_definitions` 表**没有 factory_id 列** (FK 到 upload). RLS 要靠 join `smart_bi_pg_excel_uploads`. SQL 已正确处理.

**v1.1 修复 C4 关键变化**: 用 `set_config(..., true)` (transaction-scoped) + 显式 `async with conn.transaction():` 包裹. 事务结束 GUC 自动清, **不会**泄露到 pool 下一个 acquirer.

如果用 `set_config(..., false)` (session-scoped) 会**留在连接上**, 下一个借连接的 tenant 看到 factory_id=A 的 RLS context, 错读 A 的数据. 这是 v1.0 的 bug.

`tenant_ctx.set_pg_connection_tenant` 是 pool setup callback, 在每次 acquire 时自动设. 但本 calculator 走显式事务, 不依赖 setup callback (二者并存不冲突).

### 3.4 多 worker scale 注意 (v1.1 新增)

**当前 prod uvicorn worker = 1** (查 `/etc/systemd/system/cretas-python.service` ExecStart 无 `--workers` 参数), per-process dict cache 安全.

**未来 scale 到 worker > 1 时**, 各 worker 的 cache 不同步, `invalidate(factory_id)` 在 worker 1 跑, worker 2-N 仍 5min 内返旧数据. 解决方案:

| 方案 | 工作量 | 何时切 |
|---|---|---|
| Redis (port 6379 已有 systemd 跑着) | 1-2 天 | scale > 1 worker 前 |
| Pub/Sub invalidate (Postgres LISTEN/NOTIFY) | 0.5 天 | 同上 |
| 缩 TTL 到 30s + 吞两次查询 | 0 天 | 临时方案 |
| 干脆不缓存 (12 factories 直接查很快) | 0 天 | 测一下查询耗时, 若 < 50ms 直接拿掉缓存 |

**推荐**: A v1.1 不上 Redis, 但 **Day 2 单测加 SLO**: cold cache 查询 p95 < 50ms; 若达标, 后期可直接拿掉缓存 (简化代码).

### 4.2 `_suggest_unlocks` 算法 (v1.1 修复 S3)

```python
# backend/python/smartbi/capability/template_status.py
from typing import Iterable
from smartbi.services.materialized_analytics.registry import all_templates

def compute_template_status(
    available: set[str]
) -> dict[str, dict]:
    """对每个已注册 template 算 (satisfied, missing) 状态."""
    status = {}
    for tpl in all_templates():
        if tpl.requires is None:
            # v1.1 修复 S2: (待定) templates 显式标 None, audit 页特殊处理
            status[tpl.code] = {"satisfied": None, "missing": [], "deferred": True}
            continue
        spec = tpl.requires
        sat = spec.is_satisfied_by(available)
        missing = spec.missing_fields(available)
        status[tpl.code] = {"satisfied": sat, "missing": missing}
    return status

def suggest_unlocks(
    available: set[str],
    template_status: dict[str, dict],
) -> list[dict]:
    """对每个未满足的 template, 按缺失字段聚合, 返回 top 5 建议.
    
    算法:
    1. 收集所有未满足 template 的 missing 字段
    2. groupby missing field → 列出能解锁的 templates
    3. 按 unlocks_count 降序排
    4. 返回 top 5, 每条带 CTA 文案 + 例子
    """
    from collections import defaultdict
    field_to_templates: dict[str, list] = defaultdict(list)
    
    for code, st in template_status.items():
        if st.get("deferred") or st.get("satisfied"):
            continue
        for missing_field in st["missing"]:
            field_to_templates[missing_field].append(code)
    
    suggestions = []
    for missing_field, template_codes in field_to_templates.items():
        if not template_codes:
            continue
        # 取头 3 个 template 当例子
        examples = template_codes[:3]
        cta = _generate_cta(missing_field, len(template_codes))
        suggestions.append({
            "missing_field": missing_field,
            "unlocks_count": len(template_codes),
            "unlocks_examples": examples,
            "cta": cta,
        })
    
    # 按 unlocks_count 降序
    suggestions.sort(key=lambda x: -x["unlocks_count"])
    return suggestions[:5]  # top 5

def _generate_cta(missing_field: str, count: int) -> str:
    """生成人类可读 CTA. v1.3 修复 L-4: 12 个 canonical 字段全覆盖."""
    field_to_hint = {
        # 时间 / 账单
        "date": "上传账单流水或交易日报",
        "source_bill_no": "上传账单流水",
        # 门店 / 员工
        "store_name": "上传带'门店名称'列的数据",
        "staff_name": "上传带'收银员/服务员'列的数据",
        # 金额
        "gross_amount": "上传含'应收金额/营业额'的订单数据",
        "discount_amount": "上传带'优惠金额'列的订单数据",
        "net_amount": "上传含'实收金额'的订单数据",
        "actual_receive": "上传带'收款金额'列的数据",
        # 订单详情
        "customer_count": "上传含'就餐人数'的数据",
        "table_no": "上传带'桌号'列的订单数据",
        "order_type": "上传带'订单类型'列的数据",
        "channel_origin": "上传带'订单来源'列的数据",
        "combo_string": "上传含'商品信息/订单明细'的订单数据",
    }
    hint = field_to_hint.get(missing_field)
    if hint is None:
        # B 阶段引入新字段时兜底, 中文 fallback 而非 raw English
        hint = f"上传含 '{missing_field}' 字段的数据 (待补充字段中文别名)"
    return f"{hint} 即可解锁 {count} 个分析"
```

```typescript
    cta: string;
  }>;
  /** v1.4 修复 S-v3-3: factory 当前 Silver 数据覆盖的时间窗 list.
   * A v1.0 阶段后端返 null (字段预留, 不计算).
   * B 阶段 Sheet Merger 上线后 backfill 真实数据, 例: [["2025-01-01", "2025-12-31"]].
   * FE 当前不消费此字段, 但接口已声明, 后期 B 上线无需改 FE schema. */
  time_coverage: string[][] | null;
}

// 单例 module-level state
const _capabilityCache = ref<CapabilityResponse | null>(null);
const _loading = ref(false);
const _error = ref<Error | null>(null);   // v1.1 修复 S7
let _inflight: Promise<CapabilityResponse | null> | null = null;  // v1.1 修复 S5

export function useCapability() {
  const authStore = useAuthStore();
  
  /**
   * Fetch capability. Dedups concurrent calls via _inflight.
   * Fail-open: 错误时返 null, hasAll/missingOf 用 fail-open 兜底.
   */
  async function fetchCapability(force = false): Promise<CapabilityResponse | null> {
    if (_capabilityCache.value && !force) return _capabilityCache.value;
    
    // v1.1 修复 S5: inflight dedup
    if (_inflight) return _inflight;
    
    // v1.1 修复 S8: auth-ready guard
    const factoryId = authStore.factoryId;
    if (!factoryId) {
      console.warn('[capability] auth not ready, skipping fetch');
      return null;
    }
    
    _loading.value = true;
    _error.value = null;
    
    _inflight = (async () => {
      try {
        const res = await apiClient.get(`/api/smartbi/capability/${factoryId}`);
        _capabilityCache.value = res.data;
        return res.data;
      } catch (e) {
        _error.value = e as Error;
        console.error('[capability] fetch failed, falling back to fail-open mode:', e);
        return null;  // fail-open
      } finally {
        _loading.value = false;
        _inflight = null;
      }
    })();
    
    return _inflight;
  }
  
  /**
   * v1.1 修复 S7 fail-open semantics:
   * - 缓存有数据 → 正常判断
   * - 缓存空 + loading → 假定满足 (避免初始 flash 隐藏)
   * - 缓存空 + error → fail-open, 假定满足 (好过整个 dashboard 空白)
   */
  const available = computed(() => {
    if (!_capabilityCache.value) return null;  // 表示"尚未确定"
    return new Set(_capabilityCache.value.available_fields);
  });
  
  function hasAll(requires: string[]): boolean {
    if (available.value === null) {
      // 加载中或错误 → fail-open
      return true;
    }
    return requires.every(f => available.value!.has(f));
  }
  
  function missingOf(requires: string[]): string[] {
    if (available.value === null) return [];
    return requires.filter(f => !available.value!.has(f));
  }
  
  /**
   * v1.1 新增: card_status 在 FE 算 (§2.2.3 修法).
   */
  const cardStatus = computed(() => {
    const status: Record<string, { satisfied: boolean; missing: string[] }> = {};
    for (const card of CARD_MANIFEST) {
      status[card.id] = {
        satisfied: hasAll(card.requires),
        missing: missingOf(card.requires),
      };
    }
    return status;
  });
  
  return {
    fetchCapability,
    available,
    hasAll,
    missingOf,
    cardStatus,
    loading: _loading,
    error: _error,
    suggestions: computed(() => _capabilityCache.value?.unlock_suggestions ?? []),
  };
}
```

**关键变化总结**:
| 修复 | v1.0 | v1.1 |
|---|---|---|
| S5 dedup | 无 | `_inflight` Promise singleton |
| S6 loading | `available={}`, hasAll 返 false → 闪空 | `available=null` 时 `hasAll` 返 **true** (fail-open) |
| S7 error | `_capabilityCache` 留 null → 全 false → 全空 | catch + log + return null + fail-open 兜底 |
| S8 auth race | `factoryId` 可能 null → API 调 `/null` | guard 检查 + log + skip |

### 11.1 多 sheet xlsx 智能时间合并 (用户需求)

**v1.2 用户拍板**: 当前"每 sheet 独立 upload, capability 自动 union" 不够好. **B 必须**实现以时间为主轴的智能合并:

**场景分析**:

| Sheet 关系 | 例子 | 期望行为 |
|---|---|---|
| 不同时间段, 同形态 | sheet1=2025-01 销售明细, sheet2=2025-02 销售明细 | **集成** (累加为 2 个月覆盖) |
| 同时间段, 同形态, 后版本 | sheet1=2025-01 销售明细 (上传 4-15), sheet2=2025-01 销售明细 (上传 4-25 修正版) | **覆盖** (后者作为权威, 前者标 superseded) |

### 11.2 时间推断详细规则 (v1.3 修正 C-v2-3)

**关键前提**: 此函数在 **field_definitions detection 完成之后**调用, 不是 raw Bronze 阶段. ALIAS lookup 用 raw column name (中文/英文原始值), 不是 canonical_fields.

```python
from smartbi.canonical.aliases import to_canonical

def infer_sheet_time_window(upload_id: int, conn) -> tuple[date, date] | None:
    """推断单一 upload (sheet) 的时间窗.
    
    必须在 field_definitions detection 后调用.
    """
    # Priority 1: 行内日期列
    # 找 field_definitions 中映射到 canonical 'date' 的 original_name
    rows = await conn.fetch("""
        SELECT original_name FROM smart_bi_pg_field_definitions
        WHERE upload_id = $1
    """, upload_id)
    
    date_col = None
    for r in rows:
        if to_canonical(r["original_name"]) == "date":
            date_col = r["original_name"]
            break
    
    if date_col:
        # 用 row_data JSONB 查 min/max 该列
        result = await conn.fetchrow(f"""
            SELECT 
              MIN((row_data->>$1)::date) AS min_date,
              MAX((row_data->>$1)::date) AS max_date
            FROM smart_bi_dynamic_data
            WHERE upload_id = $2
        """, date_col, upload_id)
        if result and result["min_date"]:
            return (result["min_date"], result["max_date"])
    
    # Priority 2: sheet 名解析
    upload = await conn.fetchrow(
        "SELECT sheet_name, file_name, created_at FROM smart_bi_pg_excel_uploads WHERE id = $1",
        upload_id
    )
    if upload:
        for name in [upload["sheet_name"], upload["file_name"]]:
            if not name:
                continue
            match = re.search(r"(\d{4})[年_\-/]?(\d{1,2})", name)
            if match:
                year, month = int(match.group(1)), int(match.group(2))
                first = date(year, month, 1)
                last = date(year, month, calendar.monthrange(year, month)[1])
                return (first, last)
    
    # Priority 3: 文件 metadata (兜底, 不准)
    if upload and upload["created_at"]:
        d = upload["created_at"].date()
        return (d, d)  # 单日窗
    
    return None
```

**用户教育 (UI)**: 上传后 admin 能看到"系统识别了 X sheet, 时间窗推断为 Y, 与 sheet Z 时间重叠 → 自动覆盖". 客户裁决: 同意/手动调整/拒绝合并 (各 sheet 独立).
