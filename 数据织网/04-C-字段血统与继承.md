## 1. 目标与边界

### 1.1 目标

多个文件给同一字段不同值时, 系统**自动选最优值**, 派生 KPI 标注**置信度 + 来源**, 客户审计可追溯.

3 个层次:

1. **Cell-level Provenance**: 每个 entity 的每个字段记录 "来源 + 时间 + 置信度", 不再是表级 upload_id
2. **冲突解决规则**: 多源同字段不同值时, 按优先级 + 时间窗 + 客户裁决决定权威值
3. **继承 Cascade**: 长期属性 (配方成本) 自动应用到动态记录 (销售) 派生指标 (毛利)

### 1.2 在 Data Fabric 体系中的角色

```
B 完成 (entity_id 稳定, merge_status 简单)
       ↓
[C] field_provenance 表 (cell-level)        ← 本 spec
       ↓
[C] 冲突解决规则 + 优先级                    ← 本 spec  
       ↓
[C] 继承 Cascade (配方→销售→毛利)            ← 本 spec
       ↓
[C] Trust Indicator UI                       ← 本 spec
       ↓
[C] B 的 merge_status → field_provenance 升级 ← 本 spec
       ↓
D Federated Query 消费 confidence cascade
```

### 1.3 in-scope vs out-of-scope

**In Scope**:
- ✅ `field_provenance` 表 schema + 写入路径 (B 各 writer 在 commit 时同时写 provenance)
- ✅ 冲突解决规则引擎 (优先级表 + 时间窗 + 30% 差异阈值)
- ✅ 继承 Cascade (配方→销售毛利, 评分→产品标签, 等)
- ✅ Trust Indicator UI 组件 (KPI 卡显示来源 + 置信度)
- ✅ Provenance 审计页 (任意 cell 的 lineage)
- ✅ B 的 `merge_status` 升级为 cell-level provenance 兼容 path
- ✅ §11.5 现有 12 factories / 1.31M 行回填策略 (来自 roadmap)

**Out of Scope (留给 D)**:
- ❌ Federated Query 引擎本身 (D)
- ❌ Cross-tenant benchmark (后期产品化)
- ❌ Automated provenance ML (新数据源自动学习权威性, 后期)

### 2.2 polymorphic field_value 设计

`JSONB` 装任意类型, 上层 reader 按 field_name 解读:

```python
# 字段类型推断 (从 ALIAS_TO_ATTR 元数据扩展)
FIELD_TYPE_MAP = {
    "store_name": "string",
    "date": "date_string",
    "gross_amount": "decimal",
    "customer_count": "int",
    "rating": "decimal",
    "top_keywords": "string_array",
    # ...
}

def read_field_value(provenance_row) -> Any:
    raw = provenance_row["field_value"]  # JSONB
    field_type = FIELD_TYPE_MAP.get(provenance_row["field_name"])
    if field_type == "decimal":
        return Decimal(raw["v"])  # JSONB stored as {"v": "12.34"}
    elif field_type == "date_string":
        return date.fromisoformat(raw["v"])
    # ...
```

JSONB 让我们**不需要按类型分多张表**, 同时保持 SQL-queryable.

## 3. 冲突解决规则

### 3.1 优先级表

`source_priority` 取值 (低数字 = 高优先级):

| Priority | source_type | 含义 | 例子 |
|---|---|---|---|
| 1 | `manual` | 客户手动确认/修改 | admin UI 改 product.cost = 60 |
| 2 | `bill_flow` | 官方 POS 账单流水 | 现成 backfill_silver.py |
| 3 | `product_summary` | 商品销售汇总 | xmx 报表 |
| 4 | `review` / `external_platform` | 第三方平台 | 大众点评导出 |
| 5 | `inferred` | AI 推断 | LLM 抽 keyword |
| 6 | `industry_default` | 行业默认值 | 川菜成本率 0.35 |

### 3.2 解决算法 (v1.2 修 C-6 运行时 priority + S-13 cache)

**关键变化 (C-6)**: source_priority 不再持久化, 查询时**计算**:
1. 全局默认: `GLOBAL_PRIORITY_TABLE[source_type]`
2. Factory override: `factory_provenance_config.priority_overrides[source_type]`
3. 后者优先

这样客户在 admin UI 改优先级 → 立即对**所有已存数据生效** (不需 backfill).

```python
# backend/python/smartbi/canonical/provenance/resolver.py
import time

# v1.2 修 S-13: factory_provenance_config 缓存, 5 min TTL (复用 A v1.4 模式)
_factory_config_cache: dict[str, tuple[dict, float]] = {}
_CACHE_TTL = 300

async def _get_factory_config(factory_id: str, conn) -> dict:
    """读 factory_provenance_config, 5 min TTL 缓存."""
    cached = _factory_config_cache.get(factory_id)
    if cached and time.time() - cached[1] < _CACHE_TTL:
        return cached[0]
    
    row = await conn.fetchrow(
        "SELECT diff_threshold, priority_overrides, industry_default_overrides "
        "FROM factory_provenance_config WHERE factory_id = $1",
        factory_id
    )
    config = dict(row) if row else {
        "diff_threshold": 0.30,
        "priority_overrides": None,
        "industry_default_overrides": None,
    }
    _factory_config_cache[factory_id] = (config, time.time())
    return config

def invalidate_factory_config_cache(factory_id: str):
    """admin 改 config 后调用."""
    _factory_config_cache.pop(factory_id, None)

GLOBAL_PRIORITY_TABLE = {
    "manual": 1, "bill_flow": 2, "product_summary": 3,
    "review": 4, "external_platform": 4, "inferred": 5,
    "industry_default": 6,
}

def _compute_priority(source_type: str, factory_config: dict) -> int:
    """运行时算 priority: factory override 优先, 否则全局默认 (C-6)."""
    overrides = factory_config.get("priority_overrides")
    if overrides and source_type in overrides:
        return int(overrides[source_type])
    return GLOBAL_PRIORITY_TABLE.get(source_type, 5)

async def get_authoritative_value(
    factory_id: str, entity_type: str, entity_id: int, 
    field_name: str, as_of_date: Optional[date], conn
) -> Optional[ProvenanceValue]:
    """取某 entity 某 field 在指定日期的权威值. v1.2 改用运行时 priority."""
    target_date = as_of_date or date.today()
    factory_config = await _get_factory_config(factory_id, conn)
    
    # 拉所有候选行. v1.3 修 NC-2: NULLIF 投影 sentinel '-infinity'/'infinity' 为 None
    rows = await conn.fetch("""
        SELECT id, factory_id, entity_type, entity_id, field_name, field_value,
               source_type, confidence, source_upload_id,
               NULLIF(valid_from, '-infinity'::date) AS valid_from,
               NULLIF(valid_to, 'infinity'::date) AS valid_to,
               superseded_by_id, superseded_reason, created_at, created_by
          FROM field_provenance
         WHERE factory_id = $1
           AND entity_type = $2
           AND entity_id = $3
           AND field_name = $4
           AND superseded_by_id IS NULL
           AND valid_from <= $5
           AND valid_to >= $5
         ORDER BY confidence DESC, created_at DESC
    """, factory_id, entity_type, entity_id, field_name, target_date)
    
    if not rows:
        return None
    
    # 应用层算 priority + 排序 (v1.2 C-6)
    candidates = [
        (row, _compute_priority(row["source_type"], factory_config))
        for row in rows
    ]
    candidates.sort(key=lambda c: (c[1], -float(c[0]["confidence"]), -c[0]["created_at"].timestamp()))
    
    best_row, best_priority = candidates[0]
    return ProvenanceValue.from_row(best_row, source_priority=best_priority)
```

**性能**: 候选行数小 (< 10 通常), 应用层排序 O(N log N) 微秒级. JOIN factory_config 命中缓存 0 DB IO.

### 3.3 30% 差异自动弹审 (v1.2 修 C-3 advisory_lock + C-7 safe diff)

**v1.2 修复**:
- **C-3 race**: 加 `pg_advisory_xact_lock(hashtext(factory||entity_type||entity_id||field_name))` 同字段写串行
- **C-7 safe diff**: current.value=0 + 字符串/数组 分别处理, 不再静默覆盖

```python
import hashlib

async def write_field_provenance_with_conflict_check(
    factory_id: str, entity_type: str, entity_id: int, field_name: str,
    new_value, source_type: str, confidence: float,
    source_upload_id: int = 0,  # 0 = sentinel (非 upload 来源)
    valid_from: Optional[date] = None, valid_to: Optional[date] = None,
    pool=None,
) -> dict:
    """写 provenance, 含冲突检查 + race-safe.
    
    Returns: {"action": "written" | "queued" | "no_change", "id": <new_id 或 None>}
    """
    # v1.2 C-1: NULL → sentinel
    valid_from = valid_from or date.min  # PG '-infinity'
    valid_to = valid_to or date.max      # PG 'infinity'
    
    async with pool.acquire() as conn:
        async with conn.transaction():
            # v1.2 C-3 / v1.3 NS-3: advisory_xact_lock 用 2-arg form 避免与 B 的 lock 冲突
            # B 用 1-arg form (md5 of factory_id) 在 sub_project=1 namespace
            # C 用 2-arg form, 第一参数 namespace=99 专给 C 字段冲突使用
            CFIELD_LOCK_NAMESPACE = 99
            lock_key = int(hashlib.sha256(
                f"{factory_id}|{entity_type}|{entity_id}|{field_name}".encode()
            ).hexdigest()[:8], 16) % (2**31)
            await conn.execute(
                "SELECT pg_advisory_xact_lock($1::int, $2::int)",
                CFIELD_LOCK_NAMESPACE, lock_key
            )
            
            # 1. 读 factory config + 现有权威值
            factory_config = await _get_factory_config(factory_id, conn)
            diff_threshold = float(factory_config["diff_threshold"])
            new_source_priority = _compute_priority(source_type, factory_config)
            
            current = await get_authoritative_value(
                factory_id, entity_type, entity_id, field_name, None, conn
            )
            
            if current is None:
                # 没现有, 直接写
                new_id = await _insert_provenance(
                    conn, factory_id, entity_type, entity_id, field_name,
                    new_value, source_type, confidence, source_upload_id,
                    valid_from, valid_to,
                )
                return {"action": "written", "id": new_id}
            
            # 2. v1.2 C-7: 安全差异检查
            field_type = FIELD_TYPE_MAP.get(field_name, "string")
            should_queue = False
            
            if field_type in ("decimal", "int"):
                # 数值字段 (修 current=0 case)
                if current.value == 0 and new_value != 0:
                    # 0 → 非 0 是大变化, 直接进 queue
                    should_queue = (new_source_priority >= current.source_priority)
                elif current.value != 0:
                    diff_ratio = abs(new_value - current.value) / abs(current.value)
                    if diff_ratio > diff_threshold and new_source_priority >= current.source_priority:
                        should_queue = True
            elif field_type == "string":
                # 字符串字段: 同优先级且不同值 → queue, 高优先级直接覆盖
                if current.value != new_value and new_source_priority >= current.source_priority:
                    should_queue = True
            elif field_type in ("string_array", "json"):
                # 数组/对象: 集合差异 > 50% 也 queue
                from json import dumps
                if dumps(current.value, sort_keys=True) != dumps(new_value, sort_keys=True):
                    if new_source_priority >= current.source_priority:
                        should_queue = True
            
            if should_queue:
                await _queue_for_admin_field_conflict(
                    conn, factory_id, entity_type, entity_id, field_name,
                    current_value=current.value, new_value=new_value,
                    current_priority=current.source_priority,
                    new_priority=new_source_priority,
                )
                return {"action": "queued", "id": None}
            
            # 3. 正常写入 + supersede 旧值 (高优先级)
            new_id = await _insert_provenance(
                conn, factory_id, entity_type, entity_id, field_name,
                new_value, source_type, confidence, source_upload_id,
                valid_from, valid_to,
            )
            if new_source_priority < current.source_priority:
                await conn.execute(
                    "UPDATE field_provenance SET superseded_by_id = $1, "
                    "superseded_reason = 'higher_priority' WHERE id = $2",
                    new_id, current.id
                )
            return {"action": "written", "id": new_id}
```

```python
# backend/python/smartbi/canonical/provenance/cascade.py
async def compute_dish_margin(
    factory_id: str, product_id: int, date_range: tuple[date, date], pool
) -> dict:
    """计算菜品毛利, 自动 cascade 配方成本.
    
    Steps:
    1. 取 product_id 的 cost_per_unit (from field_provenance, 时间窗匹配)
    2. 取 product_id 在 date_range 的销售 (from agg_product_period 或 fact_pos_item)
    3. 算毛利 = revenue - cost * qty
    4. 返回带 confidence (cost 的 confidence + sales 的 confidence)
    """
    async with pool.acquire() as conn:
        # 1. cost (v1.2 C-9: cost_prov 可能为 None)
        cost_prov = await get_authoritative_value(
            factory_id, "product", product_id, "cost_per_unit",
            as_of_date=date_range[1], conn=conn
        )
        if cost_prov is None:
            cost_prov = await _get_industry_default_cost(factory_id, product_id, conn)
        
        if cost_prov is None:
            # v1.2 C-9: 真无法算, 返 unavailable 状态而不是误导 0
            return {
                "product_id": product_id,
                "status": "unavailable",
                "reason": "无配方且从未销售, 无法估算成本",
                "confidence": 0.0,
            }
        
        # 2. sales (从 fact 表取, sales 来自上传, 也有自己的 confidence)
        sales = await conn.fetchrow("""
            SELECT SUM(revenue) AS total_rev, SUM(qty_sold) AS total_qty,
                   COUNT(DISTINCT upload_id) AS upload_count
              FROM agg_product_period
             WHERE factory_id = $1 AND product_id = $2
               AND period_start >= $3 AND period_end <= $4
        """, factory_id, product_id, date_range[0], date_range[1])
        
        revenue = float(sales["total_rev"] or 0)
        qty = float(sales["total_qty"] or 0)
        cost_per_unit = float(cost_prov.value)
        margin = revenue - (cost_per_unit * qty)
        margin_rate = margin / revenue if revenue else 0
        
        # v1.2 修 S-14: 用 min(cost_conf, sales_conf), 不假定 sales=100%
        # sales_conf 简化估算: 上传数越多越可信, 上限 0.95
        sales_confidence = min(0.95, 0.5 + 0.1 * (sales["upload_count"] or 0))
        result_confidence = min(cost_prov.confidence, sales_confidence)
        
        return {
            "product_id": product_id,
            "status": "ok",
            "revenue": revenue,
            "cost": cost_per_unit * qty,
            "margin": margin,
            "margin_rate": margin_rate,
            "confidence": result_confidence,
            "cost_source": cost_prov.source_type,
            "cost_confidence": cost_prov.confidence,
            "sales_confidence": sales_confidence,
        }
```

```python
async def infer_product_summary_period(
    factory_id: str, product_summary_upload_id: int, conn
) -> Optional[tuple[date, date]]:
    """商品汇总没日期, 但同 factory 同时段有账单流水 → 借用账单时间窗.
    
    Steps:
    1. 取 product_summary upload 的 created_at (上传时间)
    2. 找同 factory 同 ±7 天上传的 bill_flow upload
    3. 取它们的 merge_inferred_period (来自 B Sheet Merger)
    4. 求并集作为推断时间窗
    """
    upload_date = await conn.fetchval(
        "SELECT created_at::date FROM smart_bi_pg_excel_uploads WHERE id = $1",
        product_summary_upload_id
    )
    
    # v1.3 修 S-15: ±N 天读 factory_provenance_config.time_inheritance_window_days
    factory_config = await _get_factory_config(factory_id, conn)
    window_days = factory_config.get("time_inheritance_window_days", 7)
    
    bill_uploads = await conn.fetch(f"""
        SELECT merge_inferred_period_start AS p_start,
               merge_inferred_period_end AS p_end
          FROM smart_bi_pg_excel_uploads
         WHERE factory_id = $1
           AND detected_table_type = 'bill_flow'
           AND created_at::date BETWEEN $2::date - INTERVAL '{int(window_days)} days'
                                    AND $2::date + INTERVAL '{int(window_days)} days'
           AND merge_inferred_period_start IS NOT NULL
    """, factory_id, upload_date)
    
    if not bill_uploads:
        return None  # 没邻近账单, 时间继承失败
    
    # 求并集
    return (
        min(b["p_start"] for b in bill_uploads),
        max(b["p_end"] for b in bill_uploads),
    )
```

### 9.2.1 backfill_progress 表 (v1.2 修 C-4 idempotent)

```sql
CREATE TABLE backfill_progress (
    table_name VARCHAR(50) PRIMARY KEY,
    last_id BIGINT NOT NULL DEFAULT 0,         -- 已处理到的 source row id
    rows_processed BIGINT NOT NULL DEFAULT 0,
    rows_inserted BIGINT NOT NULL DEFAULT 0,
    rows_skipped BIGINT NOT NULL DEFAULT 0,    -- 已存在的 (UNIQUE 命中)
```

```python
# backend/python/scripts/backfill_provenance.py (新建)
async def backfill_table(table_name: str, batch_size: int = 5000):
    """从 backfill_progress.last_id 续跑 (crash 后可 resume).
    
    每批:
    1. SELECT 5000 行 WHERE id > last_id ORDER BY id LIMIT 5000
    2. INSERT INTO field_provenance ON CONFLICT DO NOTHING (依赖修好的 UNIQUE)
    3. UPDATE backfill_progress.last_id = MAX(processed.id)
    4. sleep 200ms
    """
    async with pool.acquire() as conn:
        progress = await conn.fetchrow(
            "SELECT last_id FROM backfill_progress WHERE table_name = $1",
            table_name
        )
        last_id = progress["last_id"] if progress else 0
        
        while True:
            rows = await conn.fetch(
                f"SELECT * FROM {table_name} WHERE id > $1 ORDER BY id LIMIT $2",
                last_id, batch_size
            )
            if not rows:
                break
            
            # INSERT to field_provenance (idempotent via UNIQUE)
            inserted = 0
            for row in rows:
                # 详细映射逻辑 per table_name (省略)
                result = await _insert_provenance_from_legacy_row(conn, table_name, row)
                if result:
                    inserted += 1
            
            last_id = rows[-1]["id"]
            await conn.execute("""
                INSERT INTO backfill_progress (table_name, last_id, rows_processed, rows_inserted)
                VALUES ($1, $2, $3, $4)
                ON CONFLICT (table_name) DO UPDATE SET
                  last_id = EXCLUDED.last_id,
                  rows_processed = backfill_progress.rows_processed + EXCLUDED.rows_processed,
                  rows_inserted = backfill_progress.rows_inserted + EXCLUDED.rows_inserted
            """, table_name, last_id, len(rows), inserted)
            
            await asyncio.sleep(0.2)
        
        await conn.execute(
            "UPDATE backfill_progress SET completed_at = NOW() WHERE table_name = $1",
            table_name
        )
```

### 9.3 Rollback (v1.2 修 S-20: 显式 cutover 前/后两套)

**Cutover 前 (BF4 之前)**:
- `DROP TABLE field_provenance` + 删迁移记录
- 现有数据在 fact 表里, 不影响业务
- 双写代码可降级 (feature flag)

**Cutover 后 (BF4 之后)**:
- 不能简单 DROP, 因为 D 的 query planner 已读 provenance, 删了 D 失败
- 需要 D 同时 rollback (回退到 SQL 模板)
- 极端情况: pg_restore 从 BF1 前的 backup 恢复 (可能丢双写期数据 ~14 天)
- **建议**: BF4 后 14 天内观察, 有问题立即回退; 14 天后基本不可逆

### 9.4 BF2 风险控制

- **rollback**: 见 §9.3 (cutover 前/后两套)
- **Prod 跑前**: `pg_dump` 备份 `fact_pos_*` + `dim_*` (~600MB) + `field_provenance` (空也备一份)
- **监控指标 (v1.2 修 S-21)**:
  - `pg_stat_activity` lock_waits (单 batch 期间应 < 5 个 wait)
  - `pg_stat_user_tables.n_dead_tup` (autovacuum 工作量, 涨太快说明回填速度过快)
  - `pg_stat_user_tables.n_live_tup` (provenance 表行数增长, 与预期 3.2M 比对)
  - 磁盘: provenance 表预计 +500MB, 检查可用空间
