## ⚠️ 必读陷阱 (下次 session 遇到 100% 会卡)

### 1. Vite proxy 本地坏
- 症状: `fetch /api/mobile/...` 500 in Playwright, 明明后端是 good 的
- 原因: web-admin dev server 的 vite proxy 配置在本地环境炸
- **修法**: 每个 spec 的 `beforeEach` 必须:
  ```typescript
  await context.route('**/api/mobile/**', async (route) => {
    const url = route.request().url().replace(
      /http:\/\/localhost:\d+\//, 'http://localhost:10010/');
    const response = await route.fetch({ url });
    await route.fulfill({ response });
  });
  ```
- `tests/v1-e2e/helpers/auth-cache.ts` 里有 `installApiProxy()` 封装, 用它.

### 2. Backend 429 rate limit — 登录 5/min 窗口
- 症状: 10 个测试里前 5 个 pass, 后 5 个 "登录请求过于频繁"
- 原因: `/api/mobile/auth/unified-login` 有 rate limit, 每分钟 5 次
- **修法**: multi-test spec 必须用 `auth-cache` pattern:
  - `beforeAll` 登录一次, `context.storageState({ path: authFile })` 存 cookies+localStorage
  - `beforeEach` 读 `authFile`, `context.addCookies(state.cookies)` + `page.evaluate` 还原 localStorage
- 参考 Task 9 `g1-invoice.spec.ts` + Task 10 `g2-sales-chain.spec.ts` 实现.

### 3. 登录 endpoint 是 `/api/mobile/auth/unified-login`
- 不是 `/api/mobile/auth/login`, 不是 `/auth/login`
- `tests/v1-e2e/helpers/login.ts` 里已经对了

### 4. `warehouse_worker` 是 MOBILE_ONLY_ROLES
- `web-admin/src/router/guards.ts` 有 `MOBILE_ONLY_ROLES` 常量
- 包含 `warehouse_worker` + 其他仅 RN 使用的 role
- 后果: Web E2E 测试不能用 warehouse_worker 作为 warehouse phase 的登录 — 会 /403
- **解决**: 用 `super_admin` 或 `procurement_manager` fallback. Task 10 里用的就是 purchase_mgr 做 phase 4 入库.

### 5. tax_rate 是整数百分比
- SalesOrderItem.java:73 Javadoc: `/** 税率 (%) */`
- 后端公式: `amount × taxRate / 100` — 假设 `taxRate` 是 9, 13, 不是 0.09, 0.13
- **seed SQL 里写 9/13/0**, 不是 0.09/0.13/0.00

### 6. 真实 schema 表名 (v1 plan 常写错)
| Plan 说 | 实际 schema |
|---|---|
| `customer` | `customers` |
| `supplier` | `suppliers` |
| `material_type` | `raw_material_types` |
| `product_type` | `product_types` |
| `bom` | `boms` |
| `bom_item` | `bom_items` |
| `factory_warehouse` | `factory_warehouses` |
| `sales_order.order_code` | `sales_orders.order_number` |
| `sales_order.order_status` | `sales_orders.status` |
| `invoices` / `invoice_items` | `invoice_records` (no separate items) |
| `internal_transfer.factory_id` | `source_factory_id` / `target_factory_id` |

- `customers` 表**没有 tax_rate** 列. 税率在 `sales_order_items.tax_rate` + `bom_items.tax_rate`.
- `customers` / `suppliers` 都要两个字段: `code` AND `customer_code` / `supplier_code` (历史冗余)

### 7. Subagent 可能切换到 main
- 偶尔某个 subagent 在 run 中途 `git checkout main` 然后回来. 我的 `git status` 突然显示在 main. 本 session 至少发生 2 次.
- **防御**: 每次重要操作前 `git branch --show-current`, 确认在 `e2e/v1-framework`. 发现偏差用 `git checkout e2e/v1-framework` 切回.

### 8. Pre-commit hook 会 auto-stage 并行 session 的文件
- `husky/lint-staged` 在 `git commit` 时会 auto-stage 某些类型的文件, 把其他 Claude session 正在改的文件一起带进我的 commit
- **防御**: 每次 commit 后 `git status --short` 核对已 commit 的文件. 发现多余文件:
  ```bash
  git reset --soft HEAD~1  # 回退 commit, 保留 staged
  git restore --staged <不想要的文件>  # 去除 scope
  git commit -m "..."  # 重提
  ```
- `soft reset` 不是 destructive, 不会丢工作.

### 9. 20+ 并行 worktree-agent 分支
- 仓库里有 `worktree-agent-*` 分支群, 每个做一块 P0 工作. 但大部分已经在 main 里了 (那些 worktree 是基于更早的 main fork, 230+ commits behind).
- **不要** 去 merge 这些 worktree 进我们的 e2e 分支 — 会带进 200+ commits 的 unrelated churn.
- **要查** 某个 worktree 改了什么: `git diff main..worktree-agent-XXX --stat`, 看 head commit: `git show worktree-agent-XXX`

### 10. F_E2E_TEST seed 需要先跑一次

- 跑法: `bash tests/v1-e2e/scripts/seed-and-reset.sh`
