## 二、根因分析

### 为什么已经有 E2E 测试还是漏掉了这些问题？

**1. 现有测试只覆盖 App，Web-Admin 零自动化测试**
- 50 个 Maestro 测试全部针对 React Native App
- Web-Admin (Vue) 没有任何自动化 E2E 测试
- 这次的 18 个 bug 全部来自 Web-Admin

**2. 现有测试只验证"页面能打开"，不验证"功能能用"**
- Maestro 测试模式: 打开页面 → 看到元素 → 通过
- 缺少: 填表单 → 提交 → 验证创建成功 → 验证在列表中出现
- 更缺少: 模块A创建 → 模块B能看到（跨模块数据流）

**3. 没有"用户操作链路"测试**
- 真实用户操作: 新建原料 → BOM里选到 → 采购订单里选到 → 入库时不报错
- 我们的测试: 各模块独立验证，不测跨模块

**4. 开发节奏问题: 功能做了但没走完整流程验证**
- Claude Code 生成代码时通常验证"编译通过+单元测试通过"
- 但不验证"实际用浏览器点一遍完整流程"
- 前端表单的必填字段、后端 API 的必填参数不匹配是最常见的问题

### 四大根因模式的深层原因

| 模式 | 深层原因 | 预防手段 |
|------|---------|---------|
| A: 缺参数 | 前后端接口契约不明确，前端不知道后端要什么 | E2E 提交测试 + API 契约测试 |
| B: 数据不同步 | 多个模块从不同表/API取下拉数据 | 跨模块数据流测试 |
| C: UI缺失 | 需求→实现有gap，开发只做了"能用"没做"好用" | UI 完整性检查清单 |
| D: 功能缺失 | 业务流程理解不完整，只做了单点没做链路 | 业务流程链路测试 |

## 四、E2E 测试 Skill 方案

### 设计理念

**不测"页面能打开"，测"用户能完成任务"。**

每个测试 = 一个完整的**业务操作链路**：
```
登录 → 导航到模块 → 填表单 → 提交 → 验证成功 → 验证在列表/其他模块可见
```

### 测试分层

```
Layer 1: 基础可用性 (每个模块能打开且不报错)
Layer 2: CRUD 操作 (创建/读取/更新/删除 实际执行并验证)
Layer 3: 跨模块数据流 (A模块创建 → B模块能看到)
Layer 4: 完整业务链路 (从头到尾走完一个业务场景)
```

### Layer 1: 基础可用性（自动扫描所有页面）

```
对每个侧边栏菜单项:
  1. 点击菜单
  2. 等待页面加载
  3. 检查: 无 error toast, 无 401, 无 500, 无白屏
  4. 记录结果
```

### Layer 2: CRUD 操作测试

| 模块 | 创建测试 | 读取测试 | 更新测试 | 删除测试 |
|------|---------|---------|---------|---------|
| 用户管理 | 添加用户+重置密码 | 查看用户 | 编辑用户 | 禁用用户 |
| 销售订单 | 选客户+选产品+下拉业务员+提交 | 查看详情 | 编辑未确认订单 | 取消订单 |
| 采购订单 | 选供应商+选原料+填价格+提交 | 查看详情 | - | 取消 |
| 生产批次 | 选产品+填数量+提交 | 查看详情 | - | - |
| 生产计划 | 选产品+自动填客户+选工序+提交 | 查看 | 转批次 | 取消(需reason) |
| 原材料入库 | 选原料+填数量+自动算总重+提交 | 查看 | 编辑 | - |
| BOM配方 | 添加原辅料+填配比 | 查看配方 | 编辑 | 删除物料行 |
| 研发样品 | 填全字段+上传照片+追踪记录 | 查看详情 | 修改状态 | - |

### Layer 3: 跨模块数据流测试

| 测试名 | 链路 | 验证 |
|--------|------|------|
| 原料→BOM→采购 | 新建原料类型 → BOM配方能选到 → 采购订单能选到 | 下拉列表一致 |
| 产品→销售→发货 | 创建产品 → 新建销售订单能选到 → 确认后能发货 | 流程不断裂 |
| 客户→销售→财务 | 新建客户 → 创建订单 → 确认 → 开票 → 收款 | 财务状态正确 |
| 销售→采购关联 | 创建销售订单 → 创建关联采购订单 | 关联关系正确 |
| 产品→生产计划→调拨 | 创建有BOM的产品 → 生产计划 → 生成调拨单 | 不报"无BOM" |
| 采购→入库 | 创建采购订单 → 采购入库 → 库存增加 | 库存数量正确 |

### Layer 4: 完整业务链路测试

**链路 1: 销售到发货全流程**
```
1. 确保有客户、有产品、有成品库存
2. 创建销售订单 (选客户、选业务员下拉、添加商品+表头)
3. 确认订单
4. 查看详情 → 创建发货单
5. 验证发货单创建成功
6. 验证出货记录出现
```

**链路 2: 采购到入库全流程**
```
1. 确保有供应商、有原料类型
2. 创建采购订单 (选供应商、选原料、填价格+表头)
3. 确认采购订单
4. 采购入库 (选采购单、确认数量)
5. 验证原材料批次库存增加
```

**链路 3: 生产全流程**
```
1. 确保有产品+BOM配方
2. 创建生产计划 (选产品、自动填客户、选工序)
3. 生成调拨单
4. 转为批次
5. 开始生产
6. 报工
7. 完成生产
```

**链路 4: 研发追踪全流程**
```
1. 创建研发需求
2. 分配样品
3. 填写追踪表(全字段+照片)
4. 添加追踪记录
5. 修改状态
```

## 五、E2E Skill 技术方案

### 工具选择
- **Web-Admin**: Playwright (headless Chrome, Node.js)
- **执行方式**: Claude Code Skill (`/e2e-web-admin`)

### Skill 结构
```
.claude/skills/e2e-web-admin/
├── SKILL.md                  # Skill 定义 + 触发条件
├── config.ts                 # 测试配置 (URL, 账号, 超时)
├── helpers/
│   ├── auth.ts               # 登录/登出
│   ├── navigation.ts         # 侧边栏导航
│   ├── form.ts               # 表单操作 (填写/提交/验证)
│   └── assertions.ts         # 通用断言 (无error/无401/有数据)
├── tests/
│   ├── layer1-accessibility.ts   # 所有页面可访问性
│   ├── layer2-crud/
│   │   ├── users.ts
│   │   ├── sales-orders.ts
│   │   ├── purchase-orders.ts
│   │   ├── production-batches.ts
│   │   ├── production-plans.ts
│   │   ├── materials.ts
│   │   ├── bom.ts
│   │   └── rd-samples.ts
│   ├── layer3-cross-module/
│   │   ├── material-sync.ts
│   │   ├── product-sales-flow.ts
│   │   └── purchase-receipt.ts
│   └── layer4-business-flows/
│       ├── sales-to-shipment.ts
│       ├── purchase-to-receipt.ts
│       ├── production-full.ts
│       └── rd-tracking.ts
└── run.ts                    # 主入口 (支持 --layer, --module 参数)
```

### 执行模式

```bash
# 快速检查 (Layer 1, ~2min)
/e2e-web-admin quick

# CRUD 测试 (Layer 1+2, ~10min)
/e2e-web-admin crud

# 完整测试 (Layer 1-4, ~30min)
/e2e-web-admin full

# 只测特定模块
/e2e-web-admin --module sales
/e2e-web-admin --module procurement
```

### 与开发流程的集成

**何时运行:**
1. 每次 web-admin 代码改动后，部署前
2. 每次后端 API 改动后
3. PR 创建前
4. 每周定期全量跑一次

**如何防止本次 bug 再发生:**

| 本次 Bug | 对应测试 | 测试逻辑 |
|---------|---------|---------|
| 重置密码缺 factoryId | Layer2/users | 点重置密码 → 验证成功 (非 error toast) |
| BOM 不显示新原料 | Layer3/material-sync | 创建原料 → 打开 BOM → 验证下拉有新原料 |
| 销售业务员是文本框 | Layer2/sales-orders | 验证业务员字段是 el-select (非 el-input) |
| 采购订单创建 500 | Layer2/purchase-orders | 填完所有字段 → 提交 → 验证成功 (非 error) |
| 生产计划取消缺 reason | Layer2/production-plans | 点取消 → 验证弹出 reason 输入框 |
| 发货单创建 500 | Layer4/sales-to-shipment | 完整走确认→发货流程 |
| 入库"原材料不存在" | Layer3/material-sync | 选了下拉原料 → 提交 → 验证成功 |
