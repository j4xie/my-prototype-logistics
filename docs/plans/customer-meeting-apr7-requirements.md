## 0. 背景说明

客户张权此前在永辉集团做过 ERP 系统设计，对工厂端数据流有完整经验。六扇门食品是**熟食加工非标品工厂**（猪肉精、带鱼段、白鹿鸡腿、梅酱小排、鸡胸肉等），主要特征：

- **非标品**: 每个 SKU 可能有 20-40 种原辅料，BOM 异常复杂
- **无固定产线**: 组长每天动态认领工序，不存在"A产线/B产线"概念
- **按工序报工**: 生产流程按工序（注射/焯水/卤制/装箱）拆分，每个小组长负责 1 个工序
- **双仓体系**: 物流仓（长期库存）+ 鲜棉仓（车间仓，当天清仓不留料）
- **主原料定点追踪**: 主原料贵，必须追踪"哪批原料用到哪个订单"
- **生产日期批次管理(PC)**: 每批货必须标记生产日期，客户要求先进先出

**客户现状**: 使用 aliwork 搭建的 ERP，字段冗余，希望白垩纪系统能简化并完整覆盖全链路。

### 2.2 BOM / 报模模块 (P0) — [17:00 - 28:00]

#### 2.2.1 核心诉求 — 原辅料拆分为 3 块

**当前问题**: 一个产品的所有物料（原料+辅料+包材）**堆在同一张表**里。
**客户原话**: *"我们这边最多的一个产品，涉及的包辅材将近 40 多种…全放在一起的话，原料续小明细、辅料续小明细…界面非常长，特别难看"*

**改造方案**: 物料明细拆分为 **3 个 tab / 3 个表格**：

1. **原料(主料)清单** — 主原料、次原料
2. **辅料清单** — 调味料、添加剂
3. **包材清单** — 袋、箱、真空袋、标签等

> 截图 `t022m10s_0076_i.jpg` 显示客户现有 BOM 物料表，10 种物料混杂了肉类、腌料、糖、调味料、真空袋 — 正是客户抱怨的"堆一起"的现状。

| 是否启用 | 布尔 | |
| BOM 类型 | 枚举 | 自制 / 委外 |

#### 2.2.6 BOM 追踪记录（痕迹追踪）

**关键需求**: BOM 下方留一个**追踪记录表**，记录原料变动痕迹。
**场景**: 主原料从 A 换成 B（比如供应商换了、质量变了），必须留记录。

字段: 日期 / 变更内容 / 变更前 / 变更后 / 操作人 / 附件

> 客户原话: *"主原料以前是用的 A 主原料，可能后面变成 B 主原料，然后我们可能要修改一下，就做一个痕迹追的追踪"*

#### 2.2.7 计算结果汇总

底部自动计算：
- 成品单价（总）
- 原料成本 / 辅料成本 / 包材成本（分块小计）
- 人工成本小计
- 均摊小计
- 总成本
- 毛利（= 出厂价 - 总成本）

### 2.3 基础数据 / 产品信息管理 (P1) — [28:00 - 31:00]

#### 2.3.1 产品大类必须拆分

**当前问题**: 产品大类是一个通用选项，选"原料"还是"成品"没有真正隔离。客户说"我选原料，但我的成品里面还是能看见"。

- 包材

#### 2.4.2 同一产品在同一订单中不允许重复 ⚠️

**当前问题**: 同一个产品（如"带鱼段精品"）在同一个销售订单里**可以加两次**（两行），会导致后续统计偏差。

**改造方案**:
- 在添加明细行时，已经选过的产品从下拉中**过滤掉**
- 或者：提交时校验，发现重复 → 合并或阻止提交

> 客户原话: *"同一个商品一个订单里面应该只能出现一次…因为你后面计算的话就可能有偏差嘛…就会有这种风险"*

> 客户原话: *"一旦有出库了，就要显示我们的那个出库金额，不然的话我们金额会对不上，因为出库金额跟订单金额有时候是不一样的"*

### 2.6 开票申请 (P1) — [52:00 - 55:00]

#### 2.6.1 流程

```
销售订单 → 开票申请 → 财务审批 → 财务开票 → 上传发票附件 → 销售下载
```

#### 2.6.2 申请单字段

| 字段 | 来源 |
|------|------|
| 订单号 | 自动带出 |

#### 2.7.2 批次选择逻辑（重要）

**场景**: "猪肉精"产品可能分 2 个批次生产（1月1日、1月2日），库存分属不同批次。出库时**可以同时选择多个批次**凑够出库量。

> 客户原话: *"我们销售产品还是不可以选择两个产品的，但是你出库可以选择，因为你批次不一样…库存不一样"*

### 2.10 工序报工 (P0) — [72:00 - 82:00]

#### 2.10.1 核心原则 — **按工序报工，不是按产品**

**重要逻辑**: 六扇门的生产组织是"**一个小组长 = 一个工序**"，不是"一个组长 = 一批产品"。

**现状 vs 改造**:
```
现状（指派逻辑）:
  排产时指派主管 → 主管看到任务 → 开始任务

改造（认领逻辑）:
  排产时不指派 → 所有小组长能看到任务池 → 早会口头分工 → 小组长主动认领某个工序
```

#### 2.10.2 工序拆分示例

参考客户群里发的排产表：
```
拉丁东威利:
  - 牛肉注射 (工序1)
  - 焯水 (工序2)

锐铲滚柔:
  - 腌制 (工序1)
  - 装箱 (工序2)
  - 500公斤 (工序3)
```

**每个工序由一个小组长带队**，他领走若干工人（靠扫码签到），完成后再扫工人下班（签退）。

#### 2.10.3 报工数据结构

**报工分两块**（重要区分）:

**A) 工时报工（签到签退机制）**
- 记录工人在某工序上的**上下班时间**
- 用于**工时统计**（工资、人效）
- 流程: 工序开始 → 扫码工人牌（签到） → 工序结束 / 工人提前走（签退） → 抓出工时

**B) 产量报工（累积爆料）**
- 记录该工序完成的**实际产量**
- ⚠️ **支持一个工序多次报工**（比如每小时报一次）
- 流程:
  - 进行中的工序 → 点"报工"
  - 填"产出数量 (kg)" 和 可选的"投入量 (kg)"
  - 提交 → 数据累加到该工序的完成量
  - 可以报好多次: 第1小时报一次、第3小时报一次、结束再报一次

> 客户原话: *"我可能不是说我生产结束才会报，可能是我生产了一个小时我可能就不好意思，然后第二个小时到第三个小时我开会再报一次…这样的话开始就累积爆料了"*

#### 2.10.4 报工界面（手机端）

参考已有 RN App 的报工界面（截图 `t077m30s_0267_i.jpg`），基本正确，需要调整：

- 顶部流程: **扫人 → 工序 → 报工** (3 步)
- 工序信息显示: 工序名 / 料名 / 料量（来自 BOM 推算）
- 产量区:
  - 产出数量 (kg) + 快捷按钮（480, 240 等）
  - 投入量 (kg, 选填)
  - 备注 (选填)
- 提交按钮

#### 2.10.5 扫码工序而非产品

**关键调整**: 扫码对象是**工序二维码**，不是产品二维码。

> 客户原话: *"我们这边的话做的话就是扫码，就是扫的话直接就扫工序，不是说扫了这个产品权限了然后再改出来"*

**建议**: 每个生产任务的工序生成独立的二维码（PC 端打印），小组长扫码进入该工序。

#### 2.10.6 数字大屏（P2）

基于报工数据做**车间数字大屏**，实时显示每个工序的完成进度。

> 客户原话: *"可以做一个数字打屏嘛…看到所有的商品工序生产的一个进度"*

### 2.11 仓库管理 (P1) — [82:00 - 85:00]

#### 2.11.1 双仓体系

| 仓库 | 用途 | 规则 |
|------|------|------|
| **物流仓** | 长期库存（原材料/辅料/包材/成品） | 常规进销存 |
| **鲜棉仓（车间仓）** | 当天生产用 | ⚠️ **当天领料，当天清仓**，不留原辅料 |

**车间仓规则**:
- 每天从物流仓调料到车间仓 → 生产 → 生产完把剩余料退回物流仓
- 车间仓**只能留**:
  - 半成品（当天没生产完的中间产品）
  - 成品（整批订单完成后一次性入物流仓，临时存放）
- **禁止**: 原辅料过夜

> 客户原话: *"鲜棉仓是不留库存的，留的话只会留那种…半产品库存和成品库存"*

#### 2.11.2 入库流程严格化

**当前问题**: 现在仓库可以自己新建入库单，客户说: *"这个是不行的，因为仓库正常来说是没有这个权限的"*

**改造方案**: 入库必须**先有发起单**，仓库只做扫码确认操作：

| 入库类型 | 发起方 | 仓库动作 |
|---------|-------|---------|
| **采购入库** | 采购部（采购订单） | 扫采购订单二维码 → 进入采购入库页面 |
| **销售退货入库** | 销售部 | 扫退货单 |
| **货赠入库** | 采购部 | 扫赠品单 |
| **盘点入库** | 仓库（盘点发起）| ✅ 仓库可自建 |

**核心原则**: 仓库只管"在不在、多少"，**不管价格**（价格属于商业机密）。

> 客户原话: *"正常仓库他只能管这个东西有没有在不在、多了少了，他没有跟价格他们是不说的，有很多观点的"*

#### 2.11.3 出库流程

| 出库类型 | 来源 |
|---------|------|
| 销售出库 | 销售订单发起 |
| 领用出库 | 其他部门发起（客户领用、试吃等） |
| 盘点出库 | 仓库自身 |

#### 2.11.4 PC 生产批次管理 (核心)

**核心字段**: 所有商品（原料+成品）**必须有 PC 字段 = 生产日期批次**。

**规则**:
- 同一物料可能有多个 PC（比如原料 10 号到一批、12 号到一批）
- 自产成品也按生产日期分 PC
- 销售出库单上，同一产品可能出现多个 PC（从不同批次凑货）
- **先进先出**: 系统建议优先出库早批次

**销售出库单示例**:
```
产品            数量    PC(生产日期)
猪肉精 500g    100包   2026-01-07
猪肉精 500g    50包    2026-01-08   ← 两个批次凑货
猪肉精 500g    20包    2026-01-09
```

**理由**: 客户需要在出库单上**清楚告知客户生产日期**，客户自己也要做先进先出。

### 2.12 周转耗材管理 (P2) — [57:00 插话]

**新需求**: 周转筐（rental crate）管理。

**业务背景**: 新业务中，配送给客户的"周转筐"是**卖租模式**（借出+押金），丢了要赔钱。需要做进销存管理。

**方案建议**: 把周转筐作为**一个特殊商品**，做独立的进销存：
- 销售订单里可以"借出"周转筐（记录借出数量）
- 出库时关联
- 客户退还时入库
- 每日统计在外数量

> 客户原话: *"我的想法是…要么就在销售订单里面就是看有没有什么新增的一个窗口，他就类似于框当一个商品，做一个经销存…不然的话你没法去管理，他每天都有进每天都有出的"*
