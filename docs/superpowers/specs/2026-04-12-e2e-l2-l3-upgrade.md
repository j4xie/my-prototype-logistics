# E2E L2/L3 CRUD Upgrade Spec

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this spec task-by-task.

**Goal:** Upgrade V1 E2E test suite from L1 page-navigation to L2 CRUD + L3 cross-module + P-check compliance per E2E skill hard rules.

**Trigger:** Audit found existing 11 specs are 40% compliant — most J-specs only verify page loads, not user task completion.

---

## 1. Hard Rules Compliance Target

Every CRUD test must produce this evidence structure:

```
filled: fieldA=value1, fieldB=value2
toast: "确切的toast文本"
list after: 数据在列表中可见 (刷新后)
validation: 前端必填标记与后端一致=YES/NO
```

Every L3 test must produce:
```
下拉列表: [实际看到的选项列表]
```

### 2.2 J5 Sales Full (+2 tests)

**现状**: 7 tests, test 2 做了 SO 创建.

**新增**:

### 2.3 J6 Purchase Full (重写 3 tests)

**现状**: 5 tests, test 3 用 API 创建 PO (违反 Hard Rule 1), test 4/5 只看页面.

- `test('P-2 双击锁: PO 创建不可重复提交')`: 同 J5 pattern

## 3. 不做的事项

- P-1 (contract shape drift): 需要 backend Controller 静态分析, 不适合 Playwright E2E, 由 unit test 覆盖
- P-4 (cross-tenant race): 需要多 factory 切换, E2E 种子只有 1 个 factory, 不可行
- P-6 (export/import round-trip): Canvas V3 功能, 不在六扇门 V1 scope
- P-7 (field type fallthrough): DDLExecutor 审计, 由 unit test 覆盖
- P-8 (reverse audit): CI 级工具, 不是 E2E spec

**理由**: P-1/4/6/7/8 是代码级审计 (适合 unit test / CI linting), 不是用户行为验证 (E2E 的领域). 把它们放进 Playwright 会产生脆弱的测试.
