# Canvas 配置编辑器 — 前端设计 Spec

> **基于**: Canvas V2 后端 (已部署 prod) + 14 个 Vue 组件 (Phase 2c)
> **版本**: 1.0.0
> **日期**: 2026-04-09

---

## 1. 设计目标

将已实现的 14 个 Vue 组件打磨为完整的用户体验，覆盖：
- 新工厂 Onboarding 引导流程
- 流程优先的配置编辑器
- 草稿 → 审核 → 发布的版本管理
- AI 全程陪伴（可直接执行配置）
- 可折叠的响应式 3 栏布局

**核心理念**: 先流程后细节 — 用户先定义业务怎么运转（工作流/触发链/校验），再配置界面长什么样（字段/权限/工具）。

## 3. Onboarding 引导流程

### 3.1 触发条件

- 首次打开 Canvas（工厂无 factory_configurations 记录）
- 用户点击"新建配置"按钮
- 用户点击侧边栏"重新引导"

### 3.2 四步流程

```
Step 1          Step 2          Step 3            Step 4
选择模板   →    调整模块   →    流程总览确认  →   审核 & 发布
(卡片选择)      (开关+拖拽)     (卡片确认页)      (检查+发布)
```

**Step 1: 选择行业模板**
- 4 张模板卡片 (食品加工 / 烘焙 / 餐饮 / 水产) + "空白配置"
- 每张卡片显示: 模板名 + 行业 + 描述 + 启用模块数
- 选中后 AI 面板说: "已选择烘焙模板，将启用 12 个模块，设置良率 90%，保质期默认 7 天。"
- AI 可直接被指令: "我是做熟食加工的，帮我选" → AI 自动选模板

**Step 2: 调整模块**
- 模板预选的模块已打勾，用户可增减
- 拖拽调整显示顺序
- 右侧 AI 面板: "建议: 六扇门不需要设备管理模块，要关闭吗？" + [关闭] 按钮
- AI 可执行: "把财务模块都关了" → AI 直接 toggle

**Step 3: 流程总览确认**
- 所有启用模块的流程概览卡片
- 每张卡片: 模块名 + 状态数 + 流程缩略图 + ✅就绪 / ⚠️需配置
- 模板已预设合理流程 → 默认全部 ✅
- 点击卡片进入该模块的流程编辑器
- AI 主动: "所有模块流程已由模板预设。如需调整可以点击具体模块，或告诉我你的需求。"
- 确认按钮: "流程确认，下一步"

**Step 4: 预览 & 提交发布**
- 配置摘要: X 个模块 / Y 个流程步骤 / Z 条校验规则
- 完整性检查:
  - 模块依赖 (有销售必须有客户)
  - 流程完整性 (每个状态有出路)
  - 字段必填完整性
- 检查通过 → "提交发布" 按钮 → 进入审核流程
- AI: "配置检查通过，无异常。建议先在测试环境验证后再发布。"

### 3.3 Onboarding 后续

- 完成后自动跳转到编辑器
- 编辑器 Header 显示 "📝 草稿 v1 · 待审核"
- 再次打开 Canvas 直接进编辑器（跳过引导）

## 4. Phase Tab 设计

### 4.1 Tab 排序 & 分组

水平 Tab 栏，用竖线分隔符分为两组:

```
🔄 流程设计 | 🔗 触发链 | 📐 校验规则 ┃ 📋 字段配置 | 🛡️ 权限矩阵 | 🔧 工具/技能
```

**Phase A (流程 & 结构)**: 流程设计、触发链、校验规则 — 决定"业务怎么运转"
**Phase B (细节 & 权限)**: 字段配置、权限矩阵、工具/技能 — 决定"界面长什么样"

默认打开: 🔄 流程设计

### 4.2 面包屑

Tab 栏下方显示: `📋 销售订单 › 🔄 流程设计 · 7 状态 · 9 转换`

切换模块或 Tab 时面包屑实时更新。

### 4.3 各 Tab 内容

**🔄 流程设计 (默认)**
- Vue Flow 画布，显示状态节点 + 转换箭头
- 拖拽节点移动位置
- 点击连线编辑转换条件
- 右键空白处添加新状态
- 右键节点删除/编辑状态属性
- 底部: 流程完整性指示器 (● 完整 / ⚠ 孤立状态)

**🔗 触发链**
- 按 event 分组的卡片列表
- 每张卡片: event 名 + 步骤列表 (可拖拽排序)
- 每步: Tool 选择下拉 + 条件输入 + 开关
- 新增步骤 / 新增链 按钮

**📐 校验规则**
- 表格: 规则代码 / 操作 / 条件(SpEL) / 错误消息 / 严重级别 / 开关
- 严重级别下拉: BLOCK / WARN / INFO
- 所有字段 inline 编辑
- 按模块筛选（选中模块自动过滤）

**📋 字段配置**
- 表格: 拖拽排序 + 字段代码 / 标签 / 类型 / 列表显示 / 表单显示 / 必填 / 只读
- 点击"编辑"打开 FieldPropertyDrawer (侧滑)
- Drawer 内: 类型选择 / 可见性开关 / 默认值 / 依赖字段 / 选项列表

**🛡️ 权限矩阵**
- 表格: 字段 × 角色 矩阵
- 每格下拉: 编辑 / 只读 / 隐藏

**🔧 工具/技能**
- 双 Tab: Tools | Skills
- Tools: 按领域分组 (sales_ / purchase_ / bom_ / ...) + 搜索 + 批量开关
- Skills: 列表 + 优先级 + 开关

## 5. 发布流程 (草稿 → 审核 → 发布)

### 5.1 四阶段

```
DRAFT (草稿)  →  PENDING_REVIEW (待审核)  →  APPROVED (已审核)  →  PUBLISHED (已发布)
                       ↓                         ↓
                 REJECTED (驳回) → DRAFT    等待发布窗口...
```

### 5.2 发布时间窗口

审核通过后，配置不会立即生效。管理员需设置**发布窗口** — 一天中允许自动应用配置变更的时间段：

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 发布窗口开始 | 22:00 | 每天这个时间后可以应用 |
| 发布窗口结束 | 06:00 | 这个时间前完成应用 |
| 立即发布 | 关闭 | super_admin 可跳过窗口立即发布 |

**行为:**
- 审核通过 → 状态变 APPROVED，等待下一个发布窗口
- 进入窗口时 (如 22:00) → DynamicScheduler 自动执行 publish，状态变 PUBLISHED
- 如果审核通过时正好在窗口内 → 立即发布
- super_admin 可以随时点 "立即发布" 强制跳过窗口（需二次确认）
- 发布窗口配置存在 factory_scheduler_configs 表 (task_code = 'CONFIG_PUBLISH_WINDOW')

**典型场景:**
- 白天编辑配置 → 下午提交审核 → 晚上审批通过 → 凌晨 22:00 自动发布 → 第二天早上工厂使用新配置
- 紧急修改 → 审批 → super_admin 点"立即发布" → 即时生效

### 5.3 操作权限

| 操作 | 谁可以做 |
|------|---------|
| 编辑草稿 | factory_admin, factory_super_admin |
| 提交审核 | factory_admin (编辑者) |
| 审批/驳回 | factory_super_admin (不能审批自己提交的) |
| 设置发布窗口 | factory_super_admin |
| 立即发布 (跳过窗口) | factory_super_admin (需二次确认) |
| 回滚 | factory_super_admin |

### 5.4 UI 交互

**编辑中 (DRAFT):**
- Header: "📝 草稿 v3 · 2 项未保存"
- 按钮: [保存草稿] [提交审核 →]

**待审核 (PENDING_REVIEW):**
- Header: "🔍 待审核 v3 · 提交者: admin1"
- 编辑器变为只读模式
- 审核人看到: [通过 ✅] [驳回 ❌]
- 驳回需填写原因

**已审核，等待发布窗口 (APPROVED):**
- Header: "⏰ 已审核 v3 · 将在 22:00 自动发布"
- 编辑器只读
- 按钮: [⚡ 立即发布 (需确认)] [取消发布 → 回到草稿]
- 倒计时显示: "距离发布窗口还有 3 小时 42 分"

**已发布 (PUBLISHED):**
- Header: "✅ 已发布 v3 · 2026-04-09 22:00 发布"
- 编辑器只读
- 按钮: [新建草稿 v4] [回滚到 v2]

### 5.5 版本对比

提交审核时自动生成 diff:
- 新增字段: 绿色高亮
- 删除字段: 红色高亮
- 修改: 黄色高亮 + before/after

审核人在 ConfigDiffViewer 中逐项查看。

## 6. AI 助手设计

### 6.1 三种模式

**🤖 Autopilot (全自动)**
- 用户描述需求 → AI 分析 → 直接执行配置变更
- 执行后显示: "已完成 3 项操作: ✅ 禁用设备模块 ✅ 关闭 3 个字段 ✅ 简化流程"
- 用户可以 undo

**📋 Plan (方案)**
- 用户描述需求 → AI 生成变更方案列表 → 用户逐项审核
- 每项显示: 变更类型 + 描述 + [应用] [跳过]
- 全部审核后: [应用选中项] 按钮

**⚡ Action (实时提示)**
- 用户在编辑器手动操作时，AI 实时分析影响
- 例: 用户关闭一个字段 → AI 提示 "该字段被 2 条校验规则引用"
- 纯提示，不主动执行

### 6.2 Onboarding 中的 AI

AI 面板在 Onboarding 4 步中始终显示:

| Step | AI 行为 |
|------|---------|
| 1 选模板 | 主动推荐: "根据你之前的描述，建议选烘焙模板"。可被指令: "帮我选" |
| 2 调模块 | 主动建议关闭不需要的模块。可执行: "关掉财务相关的" |
| 3 流程确认 | 主动说明模板预设了什么。可执行: "简化销售流程" |
| 4 发布 | 报告检查结果。无执行能力（发布需要人工确认） |

### 6.3 AI 后端集成

- Endpoint: `POST /api/mobile/{factoryId}/config/v2/ai/chat`
- 使用 DashScope Qwen chatFast (已部署)
- System prompt 包含当前模块上下文 + 可用 canvas tools
- 6 个 Canvas Tools 做实际执行: canvas_toggle_module / canvas_toggle_tool / canvas_toggle_skill / canvas_update_field / canvas_update_trigger_chain / canvas_apply_template

## 7. 拖拽交互

### 7.1 拖拽场景

| 场景 | 技术方案 | 反馈 |
|------|---------|------|
| 模块排序 (左侧) | HTML5 DnD | 拖拽时半透明 + 目标位置蓝线 |
| 字段排序 (表格行) | HTML5 DnD | 行高亮 + 放置指示线 |
| 工作流节点移动 | @vue-flow/core 内置 | 节点跟随鼠标 + 连线自动重绘 |
| 触发链步骤排序 | HTML5 DnD | 同字段排序 |

### 7.2 拖拽约束

- 禁用模块不可拖拽 (灰色，grip 不可点击)
- 工作流起始状态 (DRAFT) 不可删除
- 拖拽排序变更标记为 dirty，需保存

## 8. 响应式 & 极端情况

### 8.1 屏幕尺寸

| 宽度 | 行为 |
|------|------|
| ≥ 1440px | 3 栏全展开 |
| 1200-1439px | AI 面板默认折叠 |
| 1024-1199px | 左侧 + AI 都默认折叠 |
| < 1024px | 不支持（显示提示"请使用更宽的屏幕"） |

### 8.2 空状态

| 场景 | 显示 |
|------|------|
| 未选模块 | 中间区域显示 "请在左侧选择模块" + 模块列表缩略图 |
| 模块无流程 | 流程设计 Tab 显示 "该模块未配置工作流" + [从模板导入] 按钮 |
| 无校验规则 | 校验规则 Tab 显示 "暂无规则" + [导入全局默认规则] 按钮 |
| AI 不可用 | AI 面板显示 "AI 服务暂不可用" + 离线提示 |

## 9. 技术约束

- Vue 3 Composition API + `<script setup>` + TypeScript
- Element Plus 2.13 (el-tabs, el-table, el-drawer, el-dialog, el-segmented)
- @vue-flow/core 1.48.2 (工作流画布)
- Pinia (config store 已有，需扩展 write 方法)
- HTML5 原生拖拽 (不引入新 drag 库)
- 所有 API 调用走 canvasApi.ts (已有) + configApi.ts (已有)

---

## 10. 不在本期范围

- 多语言 (暂只支持中文)
- 深色/浅色主题切换 (暂只有深色)
- 移动端适配 (Canvas 编辑器是桌面工具)
- 实时协作 (多人同时编辑同一配置)
- Git-style 分支 (只有线性版本)
