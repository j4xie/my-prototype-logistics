# E2E CRUD 深度验证设计

## Context

当前94个E2E测试只覆盖了happy path的"能操作"层面。缺失：编辑结果核对、错误拦截、计算字段、状态流转按钮变化、跨模块级联影响。

## 每个CRUD操作的4维度覆盖

### 维度定义

| 维度 | 含义 | 验证方式 |
|------|------|---------|
| Happy Path | 正确填写→提交→成功 | toast+列表+详情每字段精确核对 |
| Error Path | 漏填/错填→被拦截→补填→成功 | 红色错误提示文字+补填后成功 |
| Result Verify | 操作后刷新→值精确匹配 | 编辑后刷新核对值变了；删除后核对消失 |
| Downstream | 操作后下游模块数据联动 | 入库后库存+N；确认后按钮变化 |

### 模块×操作矩阵

| 模块 | Create(4维) | Edit(Result) | Delete(级联) | 状态流转 | 计算字段 | Error Path |
|------|------------|-------------|-------------|---------|---------|-----------|
| 销售订单 | 全字段创建→详情逐字段核对 | 改数量→刷新核对 | 取消→按钮消失 | 草稿→确认→按钮变化 | 箱数=数量/系数, 小计=数量×单价 | 空客户/重复SKU |
| 采购订单 | 全字段创建→详情核对 | N/A(不可编辑) | 取消 | 草稿→提交→审批 | 小计=数量×单价 | 空供应商 |
| 客户 | 5必填+详情核对 | 改联系人→刷新核对 | 删除→列表消失 | N/A | N/A | 空名称/空电话 |
| 供应商 | 4必填+详情核对 | 改地址→刷新核对 | 删除→列表消失 | N/A | N/A | 空名称 |
| 员工 | 姓名+用户名+角色 | 改手机号→核对 | N/A | N/A | N/A | 空姓名/重复用户名 |
| 产品 | 名称+大类+单位 | 改规格→核对 | 删除→确认消失 | N/A | N/A | 空名称/空大类 |
| 研发样品 | 客户+名称+级别+储存 | N/A | N/A | 草稿→提交→通过→报价按钮 | N/A | 空名称 |
| 原材料入库 | 批次+类型+供应商+数量 | 改数量→核对 | N/A | N/A | 总重量自动 | 空批次号 |
| 生产计划 | 产品+数量+日期 | N/A | 取消 | 计划→开始→完成 | N/A | 空产品/空数量 |
| 质检 | 批次+抽样+结果 | N/A | N/A | N/A | 合格率=合格/抽样 | 空批次 |

### 业务流程链（按真实操作顺序）

**链A: 采购员一天**
```
1. 创建PO: 选供应商+选原料+填数量20+单价15+规格500g→提交
2. Error: 不选供应商→提交→"供应商不能为空"→选上→提交成功
3. 详情核对: 供应商名=选的(非UUID), 原料名=选的, 数量=20, 单价=15
4. 小计验证: 20×15=300
5. 提交审批→状态标签"待审批"→"提交"按钮消失
6. (管理员)审批→状态"已审批"
7. 入库: 数量=20→确认→PO收货数=20(精确值)
8. 库存验证: 原材料库存页有对应批次
```

**链B: 销售员一天**
```
1. 创建SO: 选客户+选产品+数量50+单价100+规格200g→提交
2. 箱数验证: 如产品箱系数=10→箱数应=5
3. Error: 加重复产品→"不能添加重复产品"
4. 详情核对: 客户=选的名称, 产品名/数量/单价/规格/箱数逐项
5. 编辑: 改数量50→80→保存→刷新→数量确实=80
6. 确认→状态"已确认"→"编辑"按钮消失+"出库"按钮出现
7. 取消→状态"已取消"→所有操作按钮消失
```

**链C: 研发员一天**
```
1. 创建样品: 客户名+样品名+级别A(下拉)+储存冷冻(下拉)→提交
2. Error: 空名称→"请填写样品名称"→填入→成功
3. 搜索: 按名称搜→只显示匹配行→重置→恢复全部
4. 追踪: 日期disabled=today→记录员disabled=当前用户→填内容→添加
5. 提交审核→状态"待审核"→"提交审核"消失
6. 审核通过→状态"样品通过"→"提交报价申请"出现
```

**链D: 基础数据CRUD闭环**
```
客户: 创建→详情核对→编辑联系人→刷新核对变了→删除→确认消失
供应商: 同上
员工: 创建→详情核对→编辑手机号→刷新核对
产品: 创建→搜索找到→编辑规格→刷新核对→删除→确认消失
```

## 验证标准

每个测试必须输出证据:
```
evidence:
  filled: 每个填写的字段=具体值
  toast: 确切toast文本
  detail_check: 详情页每个字段=提交的值(精确匹配)
  error_check: 错误提示文本(error path)
  state_change: 状态标签变化+按钮显隐变化
  calculation: 计算公式=实际值
  downstream: 下游模块数据变化
  screenshot: 截图路径
```
