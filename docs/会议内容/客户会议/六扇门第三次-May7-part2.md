### 1. 收货数量分次显示 (字段需求 — 真实 gap)

- 客户原话: "收货数量加一个呗这样的话又比较直观一点吧, 比如说**第一次收了多少 第二次收了多少**那种"
- 现状: 收货单可以一直创建 (~8 次), 系统根据下单量 × 超收阈值判断是否还能再收, 但**列表上没显示分次收货数量**
- **现 PR 关联**: PR #173 P1 (超收 30% 阈值已落地), 但**分次显示列**尚未实装 → 真实 gap

### 2. PDF 打印 + 扫码入库 (流程闭环 — 真实 gap)

完整流程客户描述如下:
1. 采购员创建采购订单 → 系统出 **PDF 模板** (含二维码)
2. PDF 发给供应商 → 供应商打印 → 送货员**带着 PDF 过来**
3. 仓管员**扫描 PDF 上的条码** → 系统跳转到对应入库单界面
4. 仓管员**只录两个字段**: 收货数量 + 商品日期
5. 双方签字 → **拍照留附件** → 提交 → 系统库存自动入库

- "拍照也可以留个单谱吧, 就是你留个附件类似一个拍照然后一个附件吗也可以的呀"
- 设计原则: "其他的话就尽量少让那个仓管员去参与什么什么价格类的"
  - 原因: "做仓管的他年纪都比较大文化素质很低的, 你不能太伪赖他们"
- **现 PR 关联**: 待 grep — 采购订单 PDF 打印功能 + 扫码入库流程 (两端都需要建)
- **真实 gap**: 完整闭环未实装

### 3. RBAC 角色分离 (审计 — 真实 gap)

- 客户明确划分:
  - **采购员**: 只管下单 (创建采购订单 + 发 PDF 给供应商)
  - **仓管员**: 只管入库 (扫码 + 数量/日期核对 + 拍照签字)
  - "其他的话就尽量少让仓管员去参与, 什么价格类的不要让他们去参与"
- 客户原话: "采购跟入库是两个人吗? 两个人两个角色"
- **现状**: 系统目前似乎是同一个用户可同时操作两边
- **现 PR 关联**: RBAC 审计待开 ticket — 验证采购/入库权限隔离

### 4. 销售单价处理 (设计决策 — 已落地)

- 客户场景: 价格根据市场波动 (美国巴士牛肉涨疯了 / 包袱铁价涨 4%)
- 决策: **默认带 BOM 核算价 (出厂价), 但销售订单这个字段允许人工修改**
- 客户原话: "BOM 合算价格能带出来, 但是这个字段是可以修改的, 11 或者 12 我可以可以修改"
- **现 PR 关联**: PR #297 (D2 BOM algo UI) — BOM 计价已落地, 单价可改逻辑可能已存

### 5. 预估成本暂时隐藏 (UX 决策)

- 现状: 财务审批界面有"预估成本"图章
- 客户决策: "这个建议**暂时先去掉**, 容易产生冲突. 财务那边肯定会比较跳的"
- 原因: 财务会争论"我一定要算出来什么东西什么东西"
- 后期再启用: "后期可能这个我们这边跑起来的可能会用到"
- **行动项**: 隐藏预估成本字段 (前端 feature flag 或角色权限隐藏)

### 6. 原料字段需要"供应商" (字段补全)

- 客户原话: "原料的话那个加一个对应的供应商, 加个字段, 对应是哪家供应商供的吗"
- 设计: 一个供应商可供多种原料, 一种原料可来自多个供应商 (多对多)
- 客户认可现状: "供应商管理是分开的, 关联嘛, 跟关键客户一样"
- 客户结论: "这个不成就吧到时候实际用的时候再看吧, 可能并没我们想这个问题那么大"
- **现 PR 关联**: 供应商-原料关联表已建 (待 grep entity), 实际使用时再 refine

### 7. UI 列宽 / 详情盖住 (历史问题 — 反复出现)

- 客户原话: "成品详情盖住了是规格那边, 品名那个就特别大, 然后规格那个因为格子比较小嘛"
- "屏幕太小导致的" — 后续: "也不是, 这个是我在详细里面看到的"
- "我写个图给你吧"
- **现 PR 关联**: 历史列宽问题 PR #126 / `feedback_ui_smoke_scope_creep_default_ticket.md` 已 graduate
- **行动项**: 销售订单详情页规格列列宽 audit

### 8. 三价对比数据源 (Self-confirm + 数据 bug)

- 客户问: "三价对比的数据是从哪里转的? 是入库的呃价格还是说以那个我新建了采购订单的价格?"
- 系统答: "应该是入库的, 就是实际上已经在用了的"
- 客户测试发现: 新建一个采购单后, "三家对比没有" — "**可能是一些数据的 bug**"
- **行动项**: file P2 ticket — 三价对比在新采购单创建后未刷新

### 9. 一二级单位转换 (已落地确认)

- 客户原话: "箱数嘛就是刚刚我们那个逻辑, 根据那个转换系数自动转好来"
- 客户认可: "一二级单位转换, 这个没问题的, 这个你做的挺好的"
